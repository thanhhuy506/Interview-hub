Replace Digits with 5

Make exactly K replacements and produce the greatest possible number.

Problem statement

There is a string S representing a positive number consisting of N digits.

In one move, you can choose some digit of S that is not equal to 5 and replace it with the digit 5.

What is the maximum number that can be obtained after making exactly K moves?

Write a function that, given a string S and an integer K, returns a string representing the maximum value that can be obtained after making exactly K moves.

If making exactly K moves is impossible, return "IMPOSSIBLE".

class Solution {
    public String solution(String S, int K);
}

Example

Example 1

Input
S = "165232"
K = 3
Output"565552"

This is the largest number obtainable by replacing exactly three non-5 digits with 5.

!
The remaining examples and constraints were not visible in the supplied screenshot, so they are not invented here.

Core idea · Ý tưởng chính

English explanation

Key observation

Replacing a digit smaller than 5 increases the number. Replacing a digit greater than 5 decreases it. Because the number is represented as a string, an earlier position has a greater place value than every later position.

Greedy strategy

  1. Count digits different from 5. If fewer than K exist, exactly K moves are impossible.
  2. Scan left to right and replace digits smaller than 5. These are beneficial changes; doing the earliest positions first gives the largest increase.
  3. If moves remain, replace digits greater than 5 from right to left. These changes are unavoidable losses, so applying them at the smallest place values minimizes the damage.

Why it is correct

For two differing numbers of equal length, the first differing digit determines which number is larger. Therefore beneficial changes belong as far left as possible, while harmful mandatory changes belong as far right as possible.

Giải thích tiếng Việt

Nhận xét quan trọng

Đổi chữ số nhỏ hơn 5 thành 5 sẽ làm số lớn hơn. Đổi chữ số lớn hơn 5 thành 5 sẽ làm số nhỏ đi. Vì số được biểu diễn bằng chuỗi, vị trí càng bên trái có hàng giá trị càng lớn.

Chiến lược tham lam

  1. Đếm số chữ số khác 5. Nếu ít hơn K thì không thể thực hiện đúng K lần đổi, trả về IMPOSSIBLE.
  2. Duyệt từ trái sang phải, đổi các chữ số nhỏ hơn 5 trước. Đây là những lần đổi có lợi; ưu tiên vị trí bên trái để tăng giá trị nhiều nhất.
  3. Nếu vẫn còn lượt đổi, duyệt từ phải sang trái và đổi các chữ số lớn hơn 5. Đây là phần giảm giá trị bắt buộc, nên đặt ở hàng thấp nhất để thiệt hại nhỏ nhất.

Vì sao đúng?

Với hai số có cùng độ dài, chữ số khác nhau đầu tiên từ bên trái quyết định số nào lớn hơn. Vì vậy thay đổi có lợi phải nằm bên trái, còn thay đổi bất lợi bắt buộc nên bị đẩy sang phải.

Step-by-step · Từng bước

English

1

S = "165232", K = 3. There are six non-5 digits, so the operation is possible.

2

Scan left to right. Digit 1 is below 5, so replace it: 565232. K becomes 2.

3

Digit 6 is above 5, so keep it for now. The next digit 2 is below 5: 565532. K becomes 1.

4

The next non-5 digit 3 is below 5: 565552. K becomes 0, so this is the answer.

Tiếng Việt

1

S = "165232", K = 3. Có sáu chữ số khác 5 nên có thể thực hiện đủ K lần.

2

Duyệt từ trái sang phải. Chữ số 1 nhỏ hơn 5 nên đổi thành 5: 565232. K còn 2.

3

Chữ số 6 lớn hơn 5 nên tạm giữ. Chữ số 2 tiếp theo nhỏ hơn 5: 565532. K còn 1.

4

Chữ số 3 tiếp theo nhỏ hơn 5 nên đổi: 565552. K bằng 0, đây là đáp án.

Java solution

Solution.java
class Solution {
    public String solution(String S, int K) {
        char[] digits = S.toCharArray();

        int changeable = 0;
        for (char digit : digits) {
            if (digit != '5') {
                changeable++;
            }
        }

        if (changeable < K) {
            return "IMPOSSIBLE";
        }

        // Beneficial changes: use the highest place values first.
        for (int i = 0; i < digits.length && K > 0; i++) {
            if (digits[i] < '5') {
                digits[i] = '5';
                K--;
            }
        }

        // Mandatory harmful changes: use the lowest place values first.
        for (int i = digits.length - 1; i >= 0 && K > 0; i--) {
            if (digits[i] > '5') {
                digits[i] = '5';
                K--;
            }
        }

        return new String(digits);
    }
}

Complexity · Độ phức tạp

TimeO(N)

At most three linear scans. / Tối đa ba lần duyệt tuyến tính.

Extra spaceO(N)

The mutable character array. / Mảng ký tự dùng để chỉnh sửa chuỗi.

Common mistakes · Lỗi thường gặp

  • Replacing every digit below 5 without stopping after exactly K moves. / Đổi tất cả chữ số nhỏ hơn 5 mà không dừng đúng K lần.
  • When harmful replacements are required, scanning left to right instead of right to left. / Khi bắt buộc đổi chữ số lớn hơn 5, lại duyệt từ trái sang phải.
  • Forgetting that a digit already equal to 5 cannot be selected as a move. / Quên rằng chữ số đã bằng 5 không được tính là một lượt đổi.

Array · Simulation

Packages on the Shelf

Simulate package arrivals and find the maximum number waiting on the shelf.

Problem statement

N clients are waiting in line to collect their packages at the post office. Packages arrive one by one and are numbered from 1 to N in arrival order.

The K-th client in line (K from 0 to N−1) wants package number client[K].

After a package arrives:

  • If the first client wants that package, they collect it and leave.
  • Otherwise, the package is put on the shelf.
  • If the first client wants a package already on the shelf, they collect it and leave. Only the first client can collect a package.

Return the maximum number of packages stored on the shelf at the same time.

class Solution {
    public int solution(int[] client);
}

Examples

Example 1

Input
client = [3, 2, 4, 5, 1]
Output2

Example 2

Input
client = [1, 2, 3, 4, 5]
Output0

Example 3

Input
client = [3, 2, 7, 4, 5, 6, 1]
Output4
✓
Known constraint: 1 ≤ N ≤ 100,000.

Core idea · Ý tưởng chính

English explanation

What must be simulated?

Packages arrive in the fixed order 1, 2, ..., N. Clients leave only from the front of the queue. A package that arrives too early waits on the shelf.

State to maintain

  • first: index of the first client still waiting.
  • onShelf[p]: whether package p is waiting on the shelf.
  • shelf: current shelf size.
  • answer: maximum shelf size seen.

Important cascade

After the front client leaves, the next client may already have a package on the shelf. That client leaves immediately, possibly enabling another client to leave. Therefore we need a while loop, not a single if.

Giải thích tiếng Việt

Cần mô phỏng điều gì?

Các gói hàng đến theo thứ tự cố định 1, 2, ..., N. Khách hàng chỉ được rời hàng từ vị trí đầu tiên. Gói đến quá sớm phải nằm chờ trên kệ.

Trạng thái cần lưu

  • first: chỉ số của khách đầu tiên còn đang chờ.
  • onShelf[p]: gói p hiện có trên kệ hay không.
  • shelf: số gói hiện tại trên kệ.
  • answer: số gói lớn nhất từng xuất hiện trên kệ.

Hiệu ứng dây chuyền

Sau khi khách đầu hàng rời đi, khách kế tiếp có thể đã có gói trên kệ và cũng rời đi ngay. Quá trình này có thể lặp nhiều lần, nên phải dùng vòng while, không chỉ một câu if.

Algorithm · Thuật toán

English

1

Iterate packageNumber from 1 to N.

2

If the front client wants the arriving package, increment first. Otherwise mark the package on the shelf and update the maximum.

3

While the new front client wants a package already on the shelf, remove it, decrease the shelf count, and advance first.

Tiếng Việt

1

Duyệt packageNumber từ 1 đến N theo thứ tự gói đến.

2

Nếu khách đầu hàng cần đúng gói vừa đến thì tăng first. Nếu không, đặt gói lên kệ và cập nhật giá trị lớn nhất.

3

Trong khi khách đầu hàng mới có gói đang nằm trên kệ, lấy gói khỏi kệ, giảm số lượng và tiếp tục tăng first.

Java solution

Solution.java
class Solution {
    public int solution(int[] client) {
        int n = client.length;
        boolean[] onShelf = new boolean[n + 1];

        int first = 0;
        int shelf = 0;
        int answer = 0;

        for (int packageNumber = 1; packageNumber <= n; packageNumber++) {
            if (first < n && client[first] == packageNumber) {
                first++;
            } else {
                onShelf[packageNumber] = true;
                shelf++;
                answer = Math.max(answer, shelf);
            }

            // Several clients may leave immediately in a chain.
            while (first < n && onShelf[client[first]]) {
                onShelf[client[first]] = false;
                shelf--;
                first++;
            }
        }

        return answer;
    }
}

Correctness · Tính đúng đắn

English

Before each arrival, first identifies exactly the first waiting client, and onShelf contains exactly the arrived but uncollected packages. The arrival step follows the problem rules. The while loop then removes every client who can immediately collect from the shelf, stopping precisely when the queue is empty or its first client must wait. Thus the simulation state is correct after every arrival, and the recorded maximum is the required answer.

Tiếng Việt

Trước mỗi lần gói đến, first luôn chỉ đúng khách đầu tiên còn chờ, còn onShelf chứa đúng các gói đã đến nhưng chưa được nhận. Bước xử lý gói mới tuân theo đề bài. Vòng while loại bỏ toàn bộ khách có thể lấy gói ngay trên kệ và chỉ dừng khi hàng rỗng hoặc khách đầu hàng phải chờ. Vì vậy trạng thái mô phỏng luôn đúng sau mỗi lần gói đến, và giá trị lớn nhất ghi nhận chính là đáp án.

Complexity · Độ phức tạp

TimeO(N)

Each package is added/removed at most once. / Mỗi gói được thêm và lấy khỏi kệ tối đa một lần.

Extra spaceO(N)

The shelf-presence array. / Mảng đánh dấu các gói đang trên kệ.

Common mistakes · Lỗi thường gặp

  • Using only one if after a client leaves and missing the chain of clients who can also leave. / Chỉ dùng một if và bỏ sót chuỗi khách có thể rời đi liên tiếp.
  • Confusing client indices 0..N−1 with package numbers 1..N. / Nhầm chỉ số khách 0..N−1 với số thứ tự gói 1..N.
  • Updating the maximum only after removing packages, which can miss the instant a newly arrived package reaches the peak shelf size. / Chỉ cập nhật cực đại sau khi lấy gói khỏi kệ.

Graph · Multi-source BFS

Ambulance and Hospitals

Find the worst waiting time when each district is served by its nearest hospital.

Problem statement

There are N districts, numbered 0 to N−1, connected by M streets. Arrays A and B, both of length M, describe undirected streets: (A[K], B[K]).

There are L hospitals. The J-th hospital is located in district H[J].

An ambulance is sent from the hospital that can reach the requested district in the shortest time. Every street takes exactly 1 minute to pass.

A patient may need help in any district. Return the longest time required for an ambulance to reach any possible patient.

class Solution {
    public int solution(int N, int[] A, int[] B, int[] H);
}

Examples

Example 1

Input
N = 6
A = [0, 1, 1, 3, 0]
B = [1, 2, 3, 4, 5]
H = [2, 4]
Output3

District 5 waits longest. Route from hospital 2: 2 → 1 → 0 → 5.

Example 2

Input
N = 6
A = [0, 1, 1, 3, 0, 4]
B = [1, 2, 3, 4, 5, 5]
H = [2, 4]
Output2

District 0 has the longest arrival time. Every other district is reached in at most 1 minute.

!
The constraints were not visible in the supplied screenshots. The explanation assumes the problem guarantee that every district can be reached from at least one hospital.

Core idea · Ý tưởng chính

English explanation

Reverse the viewpoint

For every district, we need the distance to its nearest hospital. Running a separate BFS from every district would repeat work. Instead, start one BFS from all hospitals simultaneously.

Multi-source BFS

Put every hospital in the queue with distance 0. BFS expands the graph in layers. The first time a district is visited, it is reached through the smallest possible number of streets from any hospital.

Final answer

After BFS, dist[d] is the nearest-hospital distance for district d. The answer is the maximum value in dist.

Giải thích tiếng Việt

Đổi góc nhìn

Với mỗi quận, ta cần khoảng cách tới bệnh viện gần nhất. Nếu chạy BFS riêng từ từng quận thì sẽ lặp lại rất nhiều công việc. Thay vào đó, chạy một BFS bắt đầu đồng thời từ tất cả bệnh viện.

BFS đa nguồn

Đưa toàn bộ bệnh viện vào hàng đợi với khoảng cách 0. BFS mở rộng đồ thị theo từng lớp. Lần đầu một quận được thăm chính là khi nó được tiếp cận qua số con đường ít nhất từ một trong các bệnh viện.

Đáp án cuối

Sau BFS, dist[d] là khoảng cách từ quận d tới bệnh viện gần nhất. Lấy giá trị lớn nhất trong mảng dist.

Algorithm · Thuật toán

English

1

Build an undirected adjacency list from A and B.

2

Fill dist with −1, meaning unvisited.

3

For each hospital h, set dist[h] = 0 and enqueue the district ID h.

4

Run BFS. For each unvisited neighbor, set its distance to the current distance plus 1 and enqueue the neighbor.

5

Track the maximum assigned distance and return it.

Tiếng Việt

1

Tạo danh sách kề vô hướng từ hai mảng A và B.

2

Gán toàn bộ dist bằng −1, nghĩa là chưa được thăm.

3

Với mỗi bệnh viện h, gán dist[h] = 0 và đưa mã quận h vào hàng đợi.

4

Chạy BFS. Với mỗi quận kề chưa thăm, gán khoảng cách bằng khoảng cách hiện tại cộng 1 rồi đưa quận kề vào hàng đợi.

5

Theo dõi khoảng cách lớn nhất đã gán và trả về giá trị đó.

The largest BFS layer is 3, so the longest ambulance waiting time is 3 minutes.

Java solution

Solution.java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Queue;

class Solution {
    public int solution(int N, int[] A, int[] B, int[] H) {
        List<Integer>[] graph = new ArrayList[N];

        for (int district = 0; district < N; district++) {
            graph[district] = new ArrayList<>();
        }

        for (int street = 0; street < A.length; street++) {
            graph[A[street]].add(B[street]);
            graph[B[street]].add(A[street]);
        }

        int[] dist = new int[N];
        Arrays.fill(dist, -1);

        Queue<Integer> queue = new ArrayDeque<>();
        for (int hospital : H) {
            if (dist[hospital] == -1) {
                dist[hospital] = 0;
                queue.offer(hospital);
            }
        }

        int answer = 0;

        while (!queue.isEmpty()) {
            int current = queue.poll();

            for (int next : graph[current]) {
                if (dist[next] == -1) {
                    dist[next] = dist[current] + 1;
                    answer = Math.max(answer, dist[next]);
                    queue.offer(next);
                }
            }
        }

        return answer;
    }
}

Correctness · Tính đúng đắn

English

All hospitals enter the queue at distance 0. BFS processes vertices in nondecreasing distance order. When a district is first visited from a district at distance d, it receives distance d + 1. No shorter route from another hospital can appear later because all smaller layers were already processed. Therefore every stored distance is the shortest distance to any hospital, and their maximum is exactly the worst ambulance arrival time.

Tiếng Việt

Tất cả bệnh viện được đưa vào hàng đợi với khoảng cách 0. BFS xử lý các đỉnh theo thứ tự khoảng cách không giảm. Khi một quận lần đầu được thăm từ quận có khoảng cách d, nó nhận khoảng cách d + 1. Không thể có đường ngắn hơn từ bệnh viện khác xuất hiện về sau vì mọi lớp nhỏ hơn đã được xử lý. Do đó mỗi khoảng cách lưu được đều là khoảng cách ngắn nhất tới một bệnh viện, và giá trị lớn nhất chính là thời gian xe cứu thương lâu nhất.

Complexity · Độ phức tạp

TimeO(N + M)

Every district and street is processed a constant number of times. / Mỗi quận và con đường được xử lý số lần hằng số.

Extra spaceO(N + M)

Adjacency list, distance array, and queue. / Danh sách kề, mảng khoảng cách và hàng đợi.

Common mistakes · Lỗi thường gặp

  • Running one BFS per hospital or per district, causing unnecessary repeated work. / Chạy BFS riêng cho từng bệnh viện hoặc từng quận.
  • Adding only A[i] → B[i] and forgetting that streets are bidirectional. / Chỉ thêm cạnh một chiều và quên đường phố là hai chiều.
  • Putting dist[hospital] or dist[next] into the queue instead of the district ID. / Đưa giá trị khoảng cách vào queue thay vì mã quận.
  • Marking a district visited only when it is removed from the queue, allowing duplicates. / Chỉ đánh dấu đã thăm khi lấy khỏi queue, làm một quận bị thêm nhiều lần.
