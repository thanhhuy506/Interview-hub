1. AI Fundamentals

AI, Generative AI, and LLM

🌐

AI

Broad technology that lets machines perform tasks that usually need human intelligence: classify, predict, recommend, understand, or decide.

✨

Generative AI

A type of AI that creates new content: text, image, code, document, test case, summary, or design idea.

📚

LLM

Large Language Model. It reads text context and predicts the next useful tokens to produce a helpful answer.

Simple view: AI is the big field → GenAI creates content → LLM is the text/code engine.

04
Core Terms

Token, context window, hallucination

Input memory for one answer

  • Token: a small piece of text. It can be a word, part of a word, number, or symbol.
  • Context window: the maximum amount of text the model can consider at one time.
  • Prompt: instruction + context + constraints that guide the answer.

Main risk: hallucination

  • The model can sound confident even when the answer is wrong or incomplete.
  • It happens more when context is missing, unclear, outdated, or too broad.
  • Mitigation: give source context, ask for assumptions, verify with tests and human review.

06
Agent Sequence Flow

What really happens when you use a coding agent?

Developer prompt

You describe the task, constraints, and approval level.

Agent runtime

The orchestration layer decides what context and tools are needed.

Repository access

The agent searches and reads relevant files, tests, docs, or logs.

Model request

Prompt + selected code/context are sent for model inference.

Model reasoning

The model proposes the next action: read, edit, test, or ask.

Sandbox execution

The runtime executes approved tool calls or terminal commands.

Observation

Results, errors, test output, and diffs return to the agent loop.

Repeat loop

Plan → Act → Observe → Verify continues until the task is complete.

Human review

Developer reviews the answer, test result, and git diff before merge.

Key distinction: the agent is not the model. The agent runtime manages tools, files, sandbox, permissions, and feedback loops around the model.

Sources: OpenAI Codex cloud environment documentation describes container checkout, setup, agent command loop, validation, and diff review behavior.
07
Local vs Cloud Agent

Does the agent upload the whole project?

Local / IDE agent

  • The repository usually stays on the developer machine.
  • The agent can search, read, edit, and run tests locally, depending on the tool.
  • Code that the model must reason about can still be sent to the model provider.
  • It does not have to upload the whole repository, but broad tasks can send many files over many requests.
  • Risk is controlled by file permissions, ignored paths, approval mode, and local sandbox rules.

Cloud coding agent

  • The provider may create a cloud container and check out the selected repository branch or commit.
  • Setup scripts can install dependencies; the agent then runs commands in a controlled environment.
  • The repository can exist inside the cloud sandbox, but only selected context fits into the model context window.
  • Container/cache lifetime is product-specific; Codex cloud environment cache is documented as up to 12 hours.
  • Network access and secrets handling must be configured carefully before connecting private repositories.
Cloud sandbox access ≠ full repository inside the model context ≠ public Internet exposure.
Sources: OpenAI Codex cloud environment documentation: repo checkout in container, internet access settings, setup scripts, agent loop, container caching, and secrets behavior.
08
Data Handling

Sent, stored, trained, and published are different questions

1. Sent to provider

Anything pasted, attached, selected by an IDE agent, read from a repository, or returned by a tool may be included in model requests if needed for reasoning.

2. Stored or retained

Retention depends on product, plan, workspace policy, and contract. API inputs/outputs may be retained up to 30 days unless eligible zero-data-retention applies.

3. Used for training

Business, Enterprise, Edu, Healthcare, Teachers, and API data are not used for model training by default. Individual services may use content unless training is disabled.

4. Published publicly

Sending code to provider infrastructure does not mean it is posted online. Public exposure usually comes from sharing, connectors, network tools, logs, or permission mistakes.

Do not use one number for everything. Chat history, file uploads, cloud container cache, API logs, training settings, and audit logs can all have different retention rules.

Sources: OpenAI Enterprise Privacy, Chat/File Retention, Data Usage, and Codex cloud environment documentation.

Security Reality Check

Where AI-agent security risk actually appears

Prompt injection

Instructions hidden in docs, tickets, websites, comments, or generated files can try to override the task.

Secrets in context

Logs, .env files, private keys, tokens, customer data, or internal URLs may be read if access is too broad.

Over-broad tools

Write tools, shell access, MCP connectors, and admin APIs can cause damage if permission is not limited.

Network exfiltration

If internet access is enabled, malicious context may try to send data outside the controlled environment.

Unreviewed changes

The agent can generate plausible but unsafe code. Tests, diff review, and human approval are mandatory.

Safe default: company account, read-only first, least privilege, no secrets in prompts, restricted network, audit logs, approval for write actions, and human-owned merge/release.

Sources: OpenAI Codex environment/security guidance and OpenAI Enterprise Privacy data handling commitments. Exact behavior varies by vendor and workspace settings.

Token Efficiency

How to reduce token usage without reducing quality

🎯

Send only relevant context

Do not attach the whole repository or long chat history. Select the files, functions, tickets, and logs that directly affect the task.

🔍

Retrieve before you reason

Search first, then send only the top relevant results. Retrieval is usually cheaper than pushing every possible document into the prompt.

✂

Summarize large context

Compress long requirements, previous decisions, logs, and discussions into a short reusable project summary.

📝

Request concise output

Specify the exact format: bullets, JSON, diff, table, or maximum length. Avoid asking for explanations you do not need.

🔧

Limit tool output

Use grep, filters, SQL columns, pagination, log tailing, and targeted test output instead of returning thousands of irrelevant lines.

♻

Reuse stable context

Keep coding rules, architecture summaries, glossary, and project decisions in reusable instructions or memory instead of repeating them manually.

11
Token-Saving Workflow

Design the agent workflow to spend tokens only where they create value

Efficient coding-agent pattern

  • 1. Search: find related files, symbols, tickets, and tests.
  • 2. Narrow: read only the relevant ranges, not every file.
  • 3. Plan: create a short implementation plan before editing.
  • 4. Execute: change only the approved scope.
  • 5. Verify: run targeted tests first, then broader checks if needed.

Additional optimization techniques

  • Use a smaller or cheaper model for classification, formatting, simple summaries, and repetitive tasks.
  • Use a stronger reasoning model only for architecture, difficult debugging, or high-risk decisions.
  • Start a fresh task context when the conversation becomes noisy or unrelated.
  • Avoid resending unchanged generated code; reference files and diffs instead.
  • Prompt caching: when supported, repeated prefixes can reduce latency or cost, although cached tokens may still occupy context-window space.
Less efficient: "Read the entire repository and explain everything before fixing this bug." Better: "Search for the payment timeout handler. Read only related files and tests. Propose a 5-bullet plan. After approval, edit only impacted files and show the git diff."

2. Assistant vs Agent

From answering questions to taking controlled actions

AI Assistant

  • Mostly responds to direct questions.
  • Good for explanation, summary, brainstorming, translation, and small code snippets.
  • User manually copies context and applies the answer.
  • Lower automation risk, but easy to miss project context.

AI Agent

  • Can plan, use tools, read files, edit code, run commands, and observe results.
  • Works through a loop: Plan → Act → Observe → Verify.
  • Needs permissions, guardrails, logs, and human approval.
  • Higher productivity potential and higher governance need.
13
Coding AI

Chat assistant → coding assistant → coding agent

💬

Chat assistant

Explains concepts, reviews snippets, writes examples, answers “how to” questions.

⌨️

Coding assistant

Lives in IDE, suggests code, completes functions, explains local file, generates tests.

🧑‍💻

Coding agent

Understands repository, creates a plan, edits multiple files, runs tests, reviews git diff.

Example prompt for coding agent: "Analyze this requirement. Find related code. Propose an implementation plan first. Do not edit files until I approve the plan. After approval, implement, run tests, and show me the git diff."

7. Security and limitations

AI risks we must design around

🌫️

Hallucination

Wrong but confident output. Use source context, tests, and review.

💧

Data leakage

Sensitive code, customer data, keys, logs, or internal docs can leak.

🧨

Prompt injection

Untrusted content can instruct the model to ignore rules or exfiltrate data.

🔑

Least privilege

Agent should only access what it needs for the current task.

✅

Human approval

Human gates for write actions, production operations, and risky changes.

22
Safe AI operating model

Controls before scaling agents

🧱

Sandbox first

Agents run in isolated environment. No production secrets. No direct production write access.

🪪

Permission model

Read-only by default. Explicit approval for write, external calls, deployment, or data export.

🧾

Audit trail

Log prompts, tool calls, changed files, test results, and approval decisions.

🧪

Verification gates

Unit test, lint, type-check, secret scan, SAST, dependency scan, and PR review.

🛡️

Data policy

Define what can be sent to AI, what must be masked, and what is forbidden.

👥

Human ownership

Engineer owns final code quality, security, business correctness, and release decision.

8. Plan to apply AI-SDLC

Adoption roadmap

AI Assistant

Start with safe daily usage: explain code, summarize requirement, write draft docs, generate simple tests.

Coding Agent

Use in a pilot repo. Require plan-first workflow, engineer approval, and local test verification.

MCP read-only

Connect approved data sources with read-only access: Git, Jira, docs, CI logs, design files.

Controlled automation

Allow selected write actions behind approval: create branch, update tests, draft PR, generate release note.

AI across SDLC

Standardize AI support from requirement analysis to implementation, test, review, release, and support.

Use AI to accelerate thinking, coding, testing, and documentation — but keep source context, security controls, CI verification, and human approval in the loop.
