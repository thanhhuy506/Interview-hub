11. Khi nào mới dùng Custom JWT Filter?

Dùng custom filter khi authentication mechanism của bạn không phù hợp với Resource Server chuẩn, hoặc bạn cần logic đặc biệt.

@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter
        extends OncePerRequestFilter {

    private final JwtService jwtService;

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain)
            throws ServletException, IOException {

        String header = request.getHeader("Authorization");

        if (header == null || !header.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        String token = header.substring(7);

        JwtUser user = jwtService.validateAndParse(token);

        var auth =
            new UsernamePasswordAuthenticationToken(
                user.username(),
                null,
                user.authorities()
            );

        SecurityContextHolder.getContext()
            .setAuthentication(auth);

        filterChain.doFilter(request, response);
    }
}

Đăng ký filter:

http.addFilterBefore(
    jwtAuthenticationFilter,
    UsernamePasswordAuthenticationFilter.class
);
Nếu tự viết filter, bạn phải chịu trách nhiệm chính xác cho signature verification, expiration, issuer, audience, error handling, key rotation, authority mapping và các security edge cases. Vì vậy, nếu chuẩn OAuth2/OIDC đáp ứng được, ưu tiên Resource Server.

13. Cách trả lời trong phỏng vấn

Short answer:
When a request comes to a Spring Boot application, it first reaches the web server such as Tomcat. If Spring Security is enabled, the request goes through the Security Filter Chain before reaching the DispatcherServlet. For JWT authentication, the BearerTokenAuthenticationFilter extracts the token, then Spring uses the AuthenticationManager, JwtAuthenticationProvider and JwtDecoder to verify the signature and validate claims such as expiration and issuer. If authentication succeeds, an Authentication object is stored in the SecurityContextHolder. Authorization is then checked based on roles or scopes. Only after security succeeds does the request reach DispatcherServlet, Interceptor, Controller, Service, Repository and finally the database.

Câu hỏi follow-up thường gặp

Filter khác Interceptor ở đâu?

Filter chạy ở Servlet/security layer, trước DispatcherServlet. Interceptor thuộc Spring MVC và chạy sau DispatcherServlet đã bắt đầu xử lý request. Authentication nên nằm ở Filter; logging/business context có thể dùng Interceptor.

JWT decode ở Filter hay Interceptor?

Ở security filter layer. Nếu dùng Spring Security Resource Server thì để framework xử lý bằng BearerTokenAuthenticationFilter + JwtDecoder.

JWT có cần gọi DB mỗi request không?

Không bắt buộc. JWT thường self-contained và có thể verify bằng public key. Nhưng hệ thống vẫn có thể gọi DB/cache nếu cần user status, token revocation, permission động hoặc business authorization.

Authentication được giữ ở đâu?

Trong SecurityContext, được truy cập qua SecurityContextHolder. Ở servlet application truyền thống, context gắn với request execution thread.

401 và 403?

401 khi authentication thất bại hoặc không có credential hợp lệ. 403 khi đã authenticate nhưng không đủ permission.

Cognito JWT thì backend verify thế nào?

Backend đọc issuer/JWKS public keys của Cognito, verify JWT signature, sau đó validate claims như issuer, expiry và audience/client-specific claim tùy loại token/config. Spring Security Resource Server có thể làm phần này tự động.

15.3 BearerTokenAuthenticationFilter — filter framework chạy mỗi request

// Spring Security framework class - simplified mental model
public class BearerTokenAuthenticationFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain) {

        String token = bearerTokenResolver.resolve(request);

        if (token == null) {
            filterChain.doFilter(request, response);
            return;
        }

        Authentication requestAuth =
            new BearerTokenAuthenticationToken(token);

        Authentication result =
            authenticationManager.authenticate(requestAuth);

        SecurityContext context =
            SecurityContextHolder.createEmptyContext();
        context.setAuthentication(result);
        SecurityContextHolder.setContext(context);

        filterChain.doFilter(request, response);
    }
}

Method cần nhớ: doFilterInternal(). Đây là method chạy cho mỗi HTTP request đi qua filter.

Dòng logicÝ nghĩa
bearerTokenResolver.resolve()Tìm Bearer token trong request.
authenticationManager.authenticate()Chuyển việc verify/authenticate cho authentication subsystem.
SecurityContextHolder.setContext()Lưu user đã authenticate để các layer sau sử dụng.
filterChain.doFilter()Cho request đi tiếp sang filter kế tiếp.

15.9 CustomJwtAuthenticationConverter — map claim thành role/scope

public class CustomJwtAuthenticationConverter
        implements Converter {

    @Override
    public AbstractAuthenticationToken convert(Jwt jwt) {

        List authorities = new ArrayList<>();

        String scope = jwt.getClaimAsString("scope");
        if (scope != null) {
            Arrays.stream(scope.split(" \"))
                .map(s -> new SimpleGrantedAuthority("SCOPE_" + s))
                .forEach(authorities::add);
        }

        List groups = jwt.getClaimAsStringList("cognito:groups");
        if (groups != null) {
            groups.stream()
                .map(g -> new SimpleGrantedAuthority("ROLE_" + g))
                .forEach(authorities::add);
        }

        return new JwtAuthenticationToken(
            jwt,
            authorities,
            jwt.getSubject()
        );
    }
}

Method cần nhớ: convert(Jwt jwt). Đây là chỗ rất hay dùng khi claim của Cognito/Keycloak không map đúng với authority format app cần.

15.16 OrderService — business layer

@Service

    public OrderResponse getOrder(Long id, String currentUserId) {

What does @SpringBootApplication mean?

It is a composed annotation. Conceptually, it combines:

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan

During startup Spring creates the ApplicationContext, scans components, creates beans, applies BeanPostProcessors, auto-configures MVC/Security/JPA/DataSource, and starts the embedded web server.

Do not memorize Spring Boot startup as “main calls Controller”. Controllers do not execute during startup. They are instantiated as beans and wait for HTTP requests.

14. Custom JWT filter: when you write the filter yourself

public class CustomJwtFilter
        extends OncePerRequestFilter {

    private final JwtService jwtService;

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain)
            throws ServletException, IOException {

        String authorization = request.getHeader("Authorization");

        if (authorization == null ||
            !authorization.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        String token = authorization.substring(7);

        JwtUser user = jwtService.validateAndParse(token);

        Authentication authentication =
            new UsernamePasswordAuthenticationToken(
                user.username(),
                null,
                user.authorities()
            );

        SecurityContextHolder.getContext()
            .setAuthentication(authentication);

        filterChain.doFilter(request, response);
    }
}

18. Interview-ready explanation

When a request reaches a Spring Boot MVC application, the Servlet container first runs the Servlet filter chain. With Spring Security enabled, DelegatingFilterProxy delegates into Spring Security's FilterChainProxy. For a JWT resource server, BearerTokenAuthenticationFilter, which extends OncePerRequestFilter, extracts the Bearer token and delegates authentication to AuthenticationManager. The common AuthenticationManager implementation is ProviderManager, which delegates to an AuthenticationProvider such as JwtAuthenticationProvider. That provider uses a JwtDecoder, commonly NimbusJwtDecoder, to verify the JWT signature and validate its claims. After successful authentication, Spring stores an Authentication object such as JwtAuthenticationToken in the SecurityContext. Authorization is checked before the request reaches Spring MVC. Then DispatcherServlet finds the controller through HandlerMapping and invokes it through HandlerAdapter. The controller calls the service. If the service method is transactional, a Spring AOP proxy invokes TransactionInterceptor before the real service method. The service calls a Spring Data repository proxy, which commonly delegates standard JPA operations to SimpleJpaRepository and EntityManager. Hibernate generates SQL, obtains a JDBC connection through a DataSource such as HikariDataSource, and talks to the database. The result travels back to the controller, and Spring uses an HttpMessageConverter such as MappingJackson2HttpMessageConverter to serialize the response to JSON.
Why does OrderController not extend a Spring Controller class?

Because annotation-based Spring MVC discovers it through @RestController. Inheritance is not required.

Why does OrderRepository extend JpaRepository?

Because the repository is a contract. Extending JpaRepository gives Spring Data enough type information and API contracts to create a runtime proxy and provide standard CRUD operations.

Why does a custom JWT filter extend OncePerRequestFilter?

It gives you a Spring-friendly Servlet filter base class and a clear doFilterInternal() hook while handling once-per-request filter semantics.

Does BearerTokenAuthenticationFilter extend AuthenticationManager?

No. This is exactly the difference between inheritance and collaboration. The filter has/uses an AuthenticationManager and calls authenticate(); it does not inherit from it.

Does @Transactional mean OrderService extends TransactionInterceptor?

No. Spring usually wraps the service with an AOP proxy. The proxy/interceptor surrounds the real method call. Your service class still does not extend TransactionInterceptor.
