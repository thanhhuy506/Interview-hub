Q2

Given a sentence, fetch the longest word using Java Stream API.

Formatted script

Input example: "this is a stream problem". The longest word is "problem".

Senior answer script
I would solve this by splitting the sentence into words, converting the array into a stream, removing empty values, and using `max()` with a comparator based on word length. In production code, I would also handle null or blank input safely instead of assuming the sentence is always valid.
import java.util.Arrays;
import java.util.Comparator;
import java.util.Optional;

public class LongestWordExample {

    public static Optional<String> findLongestWord(String sentence) {
        if (sentence == null || sentence.isBlank()) {
            return Optional.empty();
        }

        return Arrays.stream(sentence.trim().split("\\s+"))
                .filter(word -> !word.isBlank())
                .max(Comparator.comparingInt(String::length));
    }

    public static void main(String[] args) {
        String sentence = "this is a stream problem";

        String longestWord = findLongestWord(sentence)
                .orElse("No word found");

        System.out.println(longestWord); // problem
    }
}
Q3

Given an Employee class with name, age, salary, and department, fetch all employees whose salary is greater than 50,000 using Stream API.

Formatted script

Use Java Streams to filter employees with salary greater than 50,000.

Senior answer script
I would keep the solution simple and readable. The stream should filter by salary and collect the matching employees into a list. In a real project, if this data comes from a database, I would prefer filtering at the query level instead of fetching all rows into memory and filtering in Java.
import java.math.BigDecimal;
import java.util.List;

public class EmployeeFilterExample {

    record Employee(String name, int age, BigDecimal salary, String department) {}

    public static List<Employee> findHighSalaryEmployees(List<Employee> employees) {
        return employees.stream()
                .filter(employee -> employee.salary().compareTo(BigDecimal.valueOf(50_000)) > 0)
                .toList();
    }

    public static void main(String[] args) {
        List<Employee> employees = List.of(
                new Employee("An", 28, BigDecimal.valueOf(45_000), "IT"),
                new Employee("Binh", 31, BigDecimal.valueOf(75_000), "Finance"),
                new Employee("Chi", 26, BigDecimal.valueOf(60_000), "IT")
        );

        findHighSalaryEmployees(employees)
                .forEach(System.out::println);
    }
}
Q4

Write a JUnit test case for calculating prime numbers using JUnit 5 and Mockito.

Formatted script

The interviewer asked for unit tests using JUnit 5 and Mockito around a prime-number calculation.

Senior answer script
For a pure prime-checking method, Mockito is not always necessary because the logic is self-contained. I would use JUnit 5 parameterized tests for multiple inputs. If the prime calculation depends on another component, for example a repository or validator, then Mockito becomes useful to isolate the class under test.
// Production code
public class PrimeService {

    private final NumberValidator validator;

    public PrimeService(NumberValidator validator) {
        this.validator = validator;
    }

    public boolean isPrime(int number) {
        validator.validate(number);

        if (number <= 1) {
            return false;
        }

        if (number == 2) {
            return true;
        }

        if (number % 2 == 0) {
            return false;
        }

        for (int i = 3; i <= Math.sqrt(number); i += 2) {
            if (number % i == 0) {
                return false;
            }
        }

        return true;
    }
}

interface NumberValidator {
    void validate(int number);
}

// JUnit 5 + Mockito test
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.ValueSource;
import org.mockito.Mock;
import org.mockito.MockitoAnnotations;

import static org.junit.jupiter.api.Assertions.*;
import static org.mockito.Mockito.*;

class PrimeServiceTest {

    @Mock
    private NumberValidator validator;

    private PrimeService primeService;

    @BeforeEach
    void setUp() {
        MockitoAnnotations.openMocks(this);
        primeService = new PrimeService(validator);
    }

    @ParameterizedTest
    @ValueSource(ints = {2, 3, 5, 7, 11, 13, 17})
    void shouldReturnTrueForPrimeNumbers(int number) {
        assertTrue(primeService.isPrime(number));
        verify(validator).validate(number);
    }

    @ParameterizedTest
    @ValueSource(ints = {-1, 0, 1, 4, 6, 8, 9, 10})
    void shouldReturnFalseForNonPrimeNumbers(int number) {
        assertFalse(primeService.isPrime(number));
        verify(validator).validate(number);
    }

    @Test
    void shouldThrowExceptionWhenValidatorRejectsInput() {
        doThrow(new IllegalArgumentException("Invalid number"))
                .when(validator).validate(-10);

        assertThrows(
                IllegalArgumentException.class,
                () -> primeService.isPrime(-10)
        );
    }
}
Q5

Write a basic CRUD REST API.

Formatted script

The interviewer asked for a basic CRUD REST API implementation.

Senior answer script
For a CRUD API, I would separate controller, service, repository, DTO, and entity layers. The controller should only handle HTTP concerns; business logic should stay in the service. I would return proper HTTP status codes: `201 Created` for create, `200 OK` for read/update, and `204 No Content` for delete.
// Entity
import jakarta.persistence.*;

@Entity
@Table(name = "employees")
public class EmployeeEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String department;
    private Double salary;

    // getters and setters
}

// DTO
public record EmployeeRequest(String name, String department, Double salary) {}

public record EmployeeResponse(Long id, String name, String department, Double salary) {}

// Repository
import org.springframework.data.jpa.repository.JpaRepository;

public interface EmployeeRepository extends JpaRepository<EmployeeEntity, Long> {
}

// Service
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Service
public class EmployeeService {

    private final EmployeeRepository repository;

    public EmployeeService(EmployeeRepository repository) {
        this.repository = repository;
    }

    public List<EmployeeResponse> findAll() {
        return repository.findAll().stream()
                .map(this::toResponse)
                .toList();
    }

    public EmployeeResponse findById(Long id) {
        EmployeeEntity employee = repository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("Employee not found: " + id));
        return toResponse(employee);
    }

    @Transactional
    public EmployeeResponse create(EmployeeRequest request) {
        EmployeeEntity entity = new EmployeeEntity();
        entity.setName(request.name());
        entity.setDepartment(request.department());
        entity.setSalary(request.salary());

        return toResponse(repository.save(entity));
    }

    @Transactional
    public EmployeeResponse update(Long id, EmployeeRequest request) {
        EmployeeEntity entity = repository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("Employee not found: " + id));

        entity.setName(request.name());
        entity.setDepartment(request.department());
        entity.setSalary(request.salary());

        return toResponse(entity);
    }

    @Transactional
    public void delete(Long id) {
        if (!repository.existsById(id)) {
            throw new ResourceNotFoundException("Employee not found: " + id);
        }
        repository.deleteById(id);
    }

    private EmployeeResponse toResponse(EmployeeEntity entity) {
        return new EmployeeResponse(
                entity.getId(),
                entity.getName(),
                entity.getDepartment(),
                entity.getSalary()
        );
    }
}

// Controller
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/employees")
public class EmployeeController {

    private final EmployeeService service;

    public EmployeeController(EmployeeService service) {
        this.service = service;
    }

    @GetMapping
    public List<EmployeeResponse> findAll() {
        return service.findAll();
    }

    @GetMapping("/{id}")
    public EmployeeResponse findById(@PathVariable Long id) {
        return service.findById(id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public EmployeeResponse create(@RequestBody EmployeeRequest request) {
        return service.create(request);
    }

    @PutMapping("/{id}")
    public EmployeeResponse update(@PathVariable Long id,
                                   @RequestBody EmployeeRequest request) {
        return service.update(id, request);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable Long id) {
        service.delete(id);
    }
}

    }

Q6

What is garbage collection and what are its types?

Formatted script

Garbage collection is JVM memory management that removes unreachable objects from heap memory.

Senior answer script
Garbage collection is the JVM mechanism for automatically reclaiming memory from objects that are no longer reachable from application roots such as thread stacks, static references, or JNI references. In Java, developers do not explicitly free memory, but we still need to understand object lifecycle because poor reference management can still cause memory leaks.

In a generational heap, most objects are created in the young generation. A Minor GC cleans young-generation objects. Objects that survive several collections may be promoted to the old generation. A Major GC focuses on the old generation, and a Full GC can involve the whole heap and metadata areas, depending on the collector and JVM version.

In production, I monitor GC pause time, allocation rate, heap usage, and promotion rate using tools like GC logs, JFR, VisualVM, Prometheus, or Grafana. If I see frequent Full GC, I check memory leaks, oversized caches, inefficient object creation, and heap sizing.
Q7

Difference between ArrayList and LinkedList with real-time use cases.

Formatted script

ArrayList is backed by a dynamic array. LinkedList is backed by nodes linked together.

Senior answer script
`ArrayList` is usually the default choice in Java because it has fast indexed access and good CPU cache locality. Reading by index is O(1), appending is usually O(1) amortized, but insertion or deletion in the middle can be O(n) because elements need to shift.

`LinkedList` is a doubly linked list. It is efficient for adding or removing elements if we already have the node position, but random access is O(n). It also uses more memory because each node stores previous and next references.

In real projects, I use `ArrayList` for lists returned by APIs, UI data, reports, and most read-heavy operations. I rarely use `LinkedList` unless I specifically need queue/deque behavior, and even then I usually prefer `ArrayDeque` for better performance.
Q8

What is polymorphism?

Formatted script

Polymorphism means one interface or method can behave differently based on the object or input.

Senior answer script
Polymorphism allows code to work with abstractions while the actual behavior is decided by the concrete implementation. In Java, compile-time polymorphism is method overloading, where methods share the same name but have different parameters. Runtime polymorphism is method overriding, where a subclass provides its own implementation and the JVM dispatches the method call dynamically.

A practical example is payment processing. The service can depend on a `PaymentProvider` interface, while implementations like `CreditCardPaymentProvider`, `PaypalPaymentProvider`, and `BankTransferPaymentProvider` handle different behavior. This makes the code extensible and supports the Open/Closed Principle.
Q9

What are bean scopes in Spring Boot?

Formatted script

Bean scope defines how Spring creates and manages bean instances.

Senior answer script
Bean scope controls the lifecycle and visibility of a Spring bean. The default scope is `singleton`, meaning Spring creates one instance per application context. `prototype` creates a new instance every time the bean is requested.

In web applications, we also have request, session, application, and websocket scopes. `request` creates one bean per HTTP request. `session` creates one bean per HTTP session. `application` creates one bean per servlet context.

In production, most service and repository beans are singleton because they are stateless. If a bean holds request-specific or user-specific state, I avoid singleton state and prefer request scope, method parameters, or a context holder such as Spring Security context.
Q10

How would you implement global exception handling in Spring Boot?

Formatted script

Use `@RestControllerAdvice` and `@ExceptionHandler` to handle exceptions in one place.

Senior answer script
I would implement global exception handling using `@RestControllerAdvice`. This keeps controllers clean and makes error responses consistent across the application. I usually define a standard error response containing timestamp, status, error code, message, and path.

For business exceptions, I return 400 or domain-specific error codes. For not-found cases, I return 404. For validation errors, I return a list of field errors. For unexpected exceptions, I log the root cause and return a generic 500 response without leaking internal details.
import jakarta.servlet.http.HttpServletRequest;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;

import java.time.Instant;
import java.util.List;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ApiError handleNotFound(ResourceNotFoundException ex,
                                   HttpServletRequest request) {
        return ApiError.of(404, "RESOURCE_NOT_FOUND", ex.getMessage(), request.getRequestURI());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiError handleValidation(MethodArgumentNotValidException ex,
                                     HttpServletRequest request) {
        List<String> details = ex.getBindingResult()
                .getFieldErrors()
                .stream()
                .map(error -> error.getField() + ": " + error.getDefaultMessage())
                .toList();

        return ApiError.of(400, "VALIDATION_ERROR", String.join(", ", details), request.getRequestURI());
    }

    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ApiError handleUnexpected(Exception ex,
                                     HttpServletRequest request) {
        // log.error("Unexpected error", ex);
        return ApiError.of(500, "INTERNAL_SERVER_ERROR", "Unexpected server error", request.getRequestURI());
    }
}

record ApiError(
        Instant timestamp,
        int status,
        String code,
        String message,
        String path
) {
    static ApiError of(int status, String code, String message, String path) {
        return new ApiError(Instant.now(), status, code, message, path);
    }
}

Explain HashMap internal working.

Formatted script

HashMap stores key-value pairs in buckets. It uses hashCode and equals to put and get entries.

Senior answer script
`HashMap` stores entries in an internal array called a table. When we put a key-value pair, Java calculates the key's `hashCode()`, applies a hash spreading function, and maps it to a bucket index. If the bucket is empty, the entry is inserted directly. If another entry already exists in the same bucket, Java handles it as a collision.

For lookup, HashMap calculates the hash again, finds the bucket, and then compares keys using `equals()` to identify the exact entry. That is why if we override `equals()`, we must also override `hashCode()`.

Default initial capacity is 16 and default load factor is 0.75. When the number of entries exceeds capacity multiplied by load factor, HashMap resizes and redistributes entries. Average put/get complexity is O(1), but bad collisions can degrade performance.
Q12

Why did Java 8 switch from linked list to red-black tree in case of hash collision?

Formatted script

Java 8 improves collision handling by treeifying long collision chains.

Senior answer script
Before Java 8, entries in the same bucket were stored as a linked list. If many keys landed in the same bucket, lookup time became O(n). Java 8 introduced treeification: when a bucket has many entries and the table is large enough, the bucket can be converted from a linked list to a red-black tree.

This improves worst-case lookup from O(n) to O(log n). It also protects HashMap from poor hash distribution and certain collision-heavy scenarios. In Java 8, treeification happens when the bucket size exceeds a threshold, commonly 8, and the table capacity is at least 64. If the table is still small, HashMap prefers resizing first instead of treeifying.
Q13

What is circular dependency and how would you fix it?

Formatted script

Circular dependency occurs when bean A depends on bean B and bean B depends on bean A.

Senior answer script
A circular dependency happens when two or more beans depend on each other, directly or indirectly. For example, `OrderService` depends on `PaymentService`, and `PaymentService` depends back on `OrderService`. With constructor injection, Spring cannot create either bean first, so the application may fail to start.

The best fix is redesigning the responsibilities because circular dependency often indicates poor separation of concerns. If redesign is not immediately possible, we can use setter injection, `@Lazy`, events, or extract the shared logic into a third service.

For senior-level design, I prefer breaking the cycle by introducing a domain service, event-driven communication, or an interface that reverses the dependency correctly.
Q14

What is `@Transactional`?

Formatted script

`@Transactional` manages database transaction boundaries in Spring.

Senior answer script
`@Transactional` tells Spring to execute a method within a database transaction. If the method completes successfully, the transaction commits. If an unchecked exception occurs by default, the transaction rolls back.

It helps maintain data consistency when multiple database operations must succeed or fail together. In real projects, I pay attention to propagation, isolation, rollback rules, read-only transactions, and proxy limitations. For example, a method calling another transactional method in the same class may bypass the Spring proxy, so the transaction behavior may not apply as expected.

Q17

What does `@EmbeddedId` do?

Formatted script

`@EmbeddedId` is used in JPA for composite primary keys.

Senior answer script
`@EmbeddedId` allows an entity to use a composite primary key represented by a separate embeddable class. This is useful when a table is uniquely identified by multiple columns, such as `order_id` and `product_id`.

The key class should be annotated with `@Embeddable`, implement `Serializable`, and correctly implement `equals()` and `hashCode()` because JPA uses identity comparison internally.
import jakarta.persistence.*;
import java.io.Serializable;
import java.util.Objects;

@Embeddable
public class OrderItemId implements Serializable {
    private Long orderId;
    private Long productId;

    // constructors, getters

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof OrderItemId that)) return false;
        return Objects.equals(orderId, that.orderId)
                && Objects.equals(productId, that.productId);
    }

    @Override
    public int hashCode() {
        return Objects.hash(orderId, productId);
    }
}

@Entity
@Table(name = "order_items")
public class OrderItem {

    @EmbeddedId
    private OrderItemId id;

    private Integer quantity;
}

Q19

What is circuit breaker pattern?

Formatted script

Circuit breaker prevents repeated calls to a failing downstream service.

Senior answer script
The circuit breaker pattern improves resilience in microservices. When a downstream service is slow or failing, the circuit breaker stops sending more requests for a period of time. This prevents thread exhaustion, reduces cascading failures, and allows the failing service time to recover.

It has three common states: closed, open, and half-open. In closed state, calls are allowed. In open state, calls fail fast or return fallback. In half-open state, a limited number of test calls are allowed to check recovery. In Java, Resilience4j is commonly used with Spring Boot.

Senior answer script
In microservices, centralized logging is critical because a single request may pass through many services. I would structure logs as JSON and include correlation ID, trace ID, span ID, user ID where allowed, service name, environment, and request path.

Q21

How do you handle distributed transactions in microservices?

Formatted script

Use Saga, compensation, event-driven consistency, or rarely two-phase commit.

Senior answer script
In microservices, I avoid distributed ACID transactions when possible because they reduce scalability and availability. The preferred approach is eventual consistency using the Saga pattern. Each service owns its local transaction and publishes an event. If a later step fails, previous services execute compensating actions.

Two-phase commit can provide stronger consistency, but it is blocking and tightly couples services, so it is less suitable for highly scalable microservices. For most business workflows like order-payment-inventory, Saga with idempotent operations, retry, outbox pattern, and dead-letter queues is more practical.
Q22

What is Saga pattern?

Formatted script

Saga splits a distributed transaction into smaller local transactions with compensating actions.

Senior answer script
Saga manages long-running business transactions across services without a global lock. Each step commits locally. If a step fails, the system runs compensating transactions to undo previous steps.

There are two styles. In choreography, services communicate through events and there is no central coordinator. In orchestration, a central orchestrator controls the workflow. Choreography is loosely coupled but harder to trace. Orchestration is easier to monitor but introduces a central workflow component.

For example, order creation can reserve inventory, create payment, and confirm shipment. If payment fails, the system releases the reserved inventory.
Q23

Difference between Kafka and queue.

Formatted script

Kafka is an event streaming platform. Traditional queues are usually point-to-point messaging systems.

Senior answer script
Kafka is designed as a distributed commit log. Messages are stored in topics and partitions for a configured retention period, so multiple consumer groups can read the same data independently and replay events. It is excellent for event streaming, audit trails, analytics, and high-throughput asynchronous communication.

Traditional queues like RabbitMQ are often used for task distribution. A message is usually consumed by one consumer and then acknowledged/removed. Queues are great for work dispatching, background jobs, and request decoupling.

I choose Kafka when event history, replay, high throughput, and multiple independent consumers are important. I choose a queue when I need reliable task processing with simpler routing semantics.
Q24

What is query planning?

Formatted script

Query planning is how the database chooses an execution strategy.

Senior answer script
Query planning is the database optimizer's process of deciding how to execute a SQL query. It evaluates possible strategies such as full table scan, index scan, join order, join algorithm, sorting, grouping, and filtering.

As a backend developer, I use execution plans to identify bottlenecks. For example, if a query scans millions of rows instead of using an index, I check whether the query condition matches the index, whether statistics are updated, and whether a composite index would help. Query planning is important for production performance tuning.
Q25

Explain SOLID principles.

Formatted script

SOLID is a set of five object-oriented design principles.

Senior answer script
SOLID helps us design code that is maintainable, testable, and extensible.

Single Responsibility means one class should have one reason to change. Open/Closed means we should add new behavior through extension instead of modifying stable code. Liskov Substitution means child classes must be safely replaceable for parent types. Interface Segregation means clients should not depend on methods they do not use. Dependency Inversion means high-level modules should depend on abstractions, not concrete classes.

In Spring Boot, we apply SOLID by using layered architecture, interfaces for replaceable strategies, dependency injection, small focused services, and clear domain boundaries.
Q26

Explain ACID properties.

Formatted script

ACID defines reliable database transaction behavior.

Senior answer script
ACID stands for Atomicity, Consistency, Isolation, and Durability. Atomicity means a transaction is all-or-nothing. Consistency means the database moves from one valid state to another. Isolation means concurrent transactions should not corrupt each other. Durability means committed data must survive failures.

For example, in a money transfer, deducting from one account and crediting another must happen together. If crediting fails, deduction must roll back. Isolation prevents another transaction from reading inconsistent intermediate data.
Q27

Implement lazy initialization for Singleton.

Formatted script

Lazy initialization creates the singleton object only when it is first needed.

Senior answer script
For singleton lazy initialization, the simplest thread-safe approach in modern Java is the static holder pattern. The instance is created only when the holder class is accessed, and class loading guarantees thread safety without explicit synchronization.
public final class AppConfig {

    private AppConfig() {
        // prevent external instantiation
    }

    private static class Holder {
        private static final AppConfig INSTANCE = new AppConfig();
    }

    public static AppConfig getInstance() {
        return Holder.INSTANCE;
    }
}

// Alternative: double-checked locking
public final class LazySingleton {

    private static volatile LazySingleton instance;

    private LazySingleton() {
    }

    public static LazySingleton getInstance() {
        if (instance == null) {
            synchronized (LazySingleton.class) {
                if (instance == null) {
                    instance = new LazySingleton();
                }
            }
        }
        return instance;
    }
}
Q28

Fail-fast vs fail-safe iterators.

Formatted script

Fail-fast iterators throw ConcurrentModificationException. Fail-safe iterators work on a copy or weakly consistent view.

Senior answer script
Fail-fast iterators detect structural modification of a collection during iteration and throw `ConcurrentModificationException`. Examples include iterators from `ArrayList` and `HashMap`. They are not guaranteed for concurrency control; they are mainly a bug-detection mechanism.

Fail-safe or weakly consistent iterators do not throw that exception during concurrent modification. Examples include `ConcurrentHashMap` iterators and `CopyOnWriteArrayList`. `CopyOnWriteArrayList` iterates over a snapshot, while `ConcurrentHashMap` provides a weakly consistent view.

In concurrent systems, I use concurrent collections instead of manually synchronizing normal collections unless I have a specific reason.
