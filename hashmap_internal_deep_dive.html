How HashMap Works Internally

A detailed visual guide to understand Java HashMap from basic to advanced: buckets, nodes, hash spreading, collision handling, treeification, resizing, time complexity, and common interview traps.

1. Overview

HashMap is one of the most important Java Collection classes for backend interviews and production coding.

HashMap stores data as key-value pairs. It gives very fast access because it does not search all elements one by one. Instead, it calculates where a key should be stored by using the key's hash.

Purpose

Store and retrieve values using unique keys.

Map<String, Integer> scores = new HashMap<>();
scores.put("Java", 100);
scores.get("Java"); // 100

Core Idea

Convert key into bucket index.

key
  -> hashCode()
  -> hash spreading
  -> bucket index

Expected Performance

Most operations are expected O(1).

put()    ~ O(1)
get()    ~ O(1)
remove() ~ O(1)

HashMap lưu dữ liệu theo dạng key-value. Nó truy xuất rất nhanh vì không cần duyệt toàn bộ phần tử. Thay vào đó, nó tính toán vị trí lưu key dựa trên hash của key.

Mục đích

Lưu và lấy dữ liệu thông qua key duy nhất.

Map<String, Integer> scores = new HashMap<>();
scores.put("Java", 100);
scores.get("Java"); // 100

Ý tưởng chính

Biến key thành vị trí bucket.

key
  -> hashCode()
  -> xử lý hash
  -> bucket index

Hiệu năng mong đợi

Hầu hết operation là O(1).

put()    ~ O(1)
get()    ~ O(1)
remove() ~ O(1)

2. Internal Structure

Internally, HashMap uses an array. Each array position is called a bucket. Each bucket can hold one or more nodes. 

transient Node<K,V>[] table;

static class Node<K,V> implements Map.Entry<K,V> {
    final int hash;
    final K key;
    V value;
    Node<K,V> next;
}
Bucket 0
null key = ABC
Bucket 1
empty
Bucket 2
Java = 100 → Spring = 200
Bucket 3
Hibernate = 300
Important: A bucket is not the value itself. A bucket is a position in the internal array. The actual data is stored inside Node objects.

What each Node stores

Field Meaning Why it is needed
hash The processed hash value of the key. Used to quickly compare candidate nodes before calling equals().
key The key object. Used to identify the mapping.
value The value object. The actual data returned by get(key).
next Reference to the next node in the same bucket. Used when collision happens and nodes form a linked list.

3. How put(key, value) Works

When you call map.put(key, value), HashMap does not randomly store the pair. It follows a clear algorithm.

Step 1 Calculate key's hashCode().
Step 2 Apply hash spreading: h ^ (h >>> 16).
Step 3 Calculate bucket index: (n - 1) & hash.
Step 4 Insert node if bucket is empty.
Step 5 If bucket is not empty, compare key and handle collision/update.

Example

Map<String, Integer> map = new HashMap<>();

map.put("Java", 100);

Simplified Internal Algorithm

put(key, value) {
    hash = hash(key);
    index = (table.length - 1) & hash;

    if (table[index] == null) {
        table[index] = new Node(hash, key, value, null);
    } else {
        // Collision or same key
        search bucket:
            if existing key is same:
                replace old value
            else:
                append new node or insert into tree
    }

    if (size > threshold) {
        resize();
    }
}
Senior note: put() may either insert a new mapping or update an existing mapping. If the key already exists, HashMap replaces the old value and returns the old value.

4. How get(key) Works

get(key) uses the same hash calculation process to locate the bucket. Then it checks the nodes inside that bucket. 

Integer score = map.get("Java");

Simplified Internal Algorithm

get(key) {
    hash = hash(key);
    index = (table.length - 1) & hash;

    first = table[index];

    while (first != null) {
        if (first.hash == hash &&
           (first.key == key || key.equals(first.key))) {
            return first.value;
        }
        first = first.next;
    }

    return null;
}

Why check hash first?

Comparing integers is very cheap. So HashMap first checks node.hash == hash. If the hash is different, the keys cannot be equal.

Why check equals()?

Two different keys may have the same hash or same bucket index. equals() confirms the exact key.

Key rule: hashCode() helps HashMap find the bucket. equals() helps HashMap find the exact key inside that bucket.

5. Collision Handling

A collision happens when two or more keys are placed into the same bucket. This does not always mean their hashCode() is exactly the same. It can also happen because different hash values produce the same bucket index.

Collision Example

Bucket 5
Java = 100 → Spring = 200 → Kafka = 300

Before Java 8

Collision nodes were stored as a linked list. If many keys were placed in the same bucket, searching became slow.

Java 8 and Later

HashMap can convert a long linked list inside a bucket into a Red-Black Tree. This is called treeification.

Condition Value Meaning
TREEIFY_THRESHOLD 8 If a bucket has 8 or more nodes, it may be converted to a tree.
MIN_TREEIFY_CAPACITY 64 The table capacity must be at least 64 before treeification happens.
UNTREEIFY_THRESHOLD 6 If tree nodes reduce below this level during resize/removal, it may become a linked list again.
Important: If bucket size reaches 8 but table capacity is still below 64, HashMap prefers resizing instead of treeifying. Why? Because better distribution may solve the collision.

Complexity

Normal case

O(1)

Good hash distribution, few collisions.

Linked-list collision

O(n)

Many nodes in one bucket.

Tree bin

O(log n)

Java 8+ Red-Black Tree optimization.

6. Resize Mechanism

HashMap does not keep the same array size forever. When the number of mappings becomes too large, it resizes the internal table.

Default capacity

16

The first table size when data is inserted.

Default load factor

0.75

Controls when resizing happens.

Threshold

capacity * loadFactor

For capacity 16, threshold is 12.

Example

capacity = 16
loadFactor = 0.75
threshold = 16 * 0.75 = 12

When size becomes 13:
HashMap resizes from 16 to 32.

What happens during resize?

The capacity doubles. After that, nodes may stay in the same bucket or move to another bucket. Since the bucket index depends on capacity, changing capacity changes the possible index.

Before resize

capacity = 16
index = (16 - 1) & hash

After resize

capacity = 32
index = (32 - 1) & hash
Performance warning: Resize is expensive because HashMap must redistribute nodes. If you know the expected number of elements, initialize HashMap with a proper capacity.

Better Initialization

// If you expect around 1000 elements:
Map<String, Object> map = new HashMap<>(1340);

// Why around 1340?
// Because threshold = capacity * 0.75
// We want threshold >= 1000

7. equals() and hashCode() Contract

This is one of the most important HashMap interview topics. HashMap depends on both hashCode() and equals().

Contract: If two objects are equal by equals(), they must return the same hashCode().

Correct Example

class Employee {
    private final Long id;
    private final String name;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee other)) return false;
        return Objects.equals(id, other.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}

What happens if equals() is overridden but hashCode() is not?

Employee e1 = new Employee(1L, "John");
Employee e2 = new Employee(1L, "John");

map.put(e1, "Developer");

map.get(e2); // may return null if hashCode is different

Even though e1.equals(e2) may be true, HashMap may look in a different bucket if their hash codes are different.

Mutable Key Problem

Employee e = new Employee(1L, "John");

map.put(e, "Developer");

// Dangerous: changing field used in hashCode/equals
e.setId(2L);

map.get(e); // may return null
Production rule: Avoid using mutable objects as HashMap keys. If a key changes after insertion, HashMap may not be able to find it again.

8. How remove(key) Works

remove(key) is similar to get(key), but after finding the node, HashMap unlinks it from the bucket. 

map.remove("Java");

Simplified Algorithm

remove(key) {
    hash = hash(key);
    index = (table.length - 1) & hash;

    search bucket:
        if node key matches:
            unlink node from linked list or tree
            size--
            return old value

    return null;
}

Removing first node

Bucket:
A -> B -> C

remove(A)

Bucket:
B -> C

Removing middle node

Bucket:
A -> B -> C

remove(B)

Bucket:
A -> C

9. Thread Safety

HashMap is not thread-safe. It is designed for single-threaded access or externally synchronized access.

If multiple threads modify a HashMap at the same time without synchronization, the data can become inconsistent.
Map Type Thread-safe? Use Case
HashMap No Normal single-thread usage.
Collections.synchronizedMap() Yes, with global lock Simple synchronized wrapper, but lower concurrency.
ConcurrentHashMap Yes Preferred for high-concurrency applications.

Recommended in concurrent code

Map<String, Integer> map = new ConcurrentHashMap<>();

11. Common Interview Questions & Answers

1. Why does HashMap use both hashCode() and equals()?

hashCode() is used to find the bucket quickly. equals() is used to find the exact key inside that bucket. Hash collisions are possible, so hash alone is not enough.

2. What happens if two keys have the same hashCode?

They go to the same bucket. HashMap then compares keys using equals(). If keys are equal, the value is replaced. If not equal, a new node is stored in the same bucket.

3. Is collision always caused by same hashCode?

No. Collision can happen when different hash values produce the same bucket index. The index is calculated using (capacity - 1) & hash, so many hash values can map to the same bucket.

4. Why is HashMap capacity always power of two?

Power-of-two capacity allows HashMap to calculate bucket index using fast bit operation: (capacity - 1) & hash. It also helps distribution when combined with hash spreading.

5. Why does HashMap resize?

As the number of entries increases, collisions become more likely. Resizing increases bucket count, improves distribution, and keeps average operation time near O(1).

6. Why should we avoid mutable keys?

If a field used in hashCode() or equals() changes after insertion, the key may belong to a different bucket logically. Then get() may not find it anymore.

7. What is the difference between HashMap and ConcurrentHashMap?

HashMap is not thread-safe. ConcurrentHashMap is designed for concurrent access and provides better scalability than synchronizing the whole map.

8. Can HashMap store null?

Yes. HashMap allows one null key and multiple null values. The null key is handled specially and usually goes to bucket index 0.

HashMap là gì?

HashMap là cấu trúc dữ liệu lưu dữ liệu theo dạng key-value. Nó truy xuất nhanh vì dùng hashCode() của key để tính vị trí bucket.

Node gồm:
- hash
- key
- value
- next

Các bước:

2. Xử lý hash để phân phối đều hơn
3. Tính bucket index
4. Nếu bucket rỗng thì tạo Node mới
5. Nếu bucket đã có dữ liệu thì xử lý collision
6. Nếu size vượt threshold thì resize

Khi get dữ liệu

map.get("Java");

Các bước:
1. Tính hash
2. Tính bucket index
3. Đi vào bucket
4. So sánh hash trước
5. So sánh equals để tìm đúng key
6. Trả về value nếu tìm thấy

Collision là gì?

Collision xảy ra khi nhiều key rơi vào cùng một bucket. HashMap xử lý bằng linked list. Từ Java 8, nếu bucket quá dài, linked list có thể chuyển sang Red-Black Tree.

Điều kiện treeify thường gặp: bucket có từ 8 node trở lên và capacity tối thiểu là 64.

Resize là gì?

Khi số lượng phần tử vượt ngưỡng capacity * loadFactor, HashMap tăng capacity gấp đôi để giảm collision. 

Default capacity = 16
Default load factor = 0.75
Threshold = 16 * 0.75 = 12

Khi size > 12:
capacity tăng từ 16 lên 32
