Interviewer: Which Java version do you use in your current project?

Candidate: Currently we use **Java 17** in my project. I am also comfortable with Java 8 because many core features that are still used today were introduced there, such as Stream API, Lambda expressions, Optional, functional interfaces, and the new Date/Time API.

In production, Java 17 gives us better performance, long-term support, better GC options, records, sealed classes, pattern matching improvements, and a stronger runtime compared with older versions. But from an interview and coding perspective, Java 8 concepts are still very important because Stream API, functional programming style, and CompletableFuture are widely used in enterprise applications.

Interviewer: Could you describe the SOLID principles?

Candidate: SOLID is a set of object-oriented design principles that help us write code that is easier to maintain, test, extend, and refactor.

- **S — Single Responsibility Principle:** a class should have one main reason to change. For example, a `PaymentService` should handle payment business logic, while `PaymentRepository` should handle database access.
- **O — Open/Closed Principle:** code should be open for extension but closed for modification. For example, instead of modifying an existing payment method every time we add a new provider, we create a `PaymentProcessor` interface and add new implementations such as `CreditCardProcessor`, `PaypalProcessor`, or `BankTransferProcessor`.
- **L — Liskov Substitution Principle:** a child class should be safely replaceable wherever the parent type is expected. If a subclass breaks expected behavior, the abstraction is wrong.
- **I — Interface Segregation Principle:** avoid large interfaces. A class should not be forced to implement methods it does not need.
- **D — Dependency Inversion Principle:** high-level modules should depend on abstractions, not concrete classes. In Spring Boot, we usually achieve this through dependency injection.

A senior point is that SOLID is not about creating too many interfaces blindly. It is about controlling coupling and making future changes safer.

Interviewer: How would you use Stream API to print employee names whose salary is greater than 5,000?

Candidate: I would use `filter()` to keep employees whose salary is greater than the threshold, then use `map()` to transform each `Employee` into its name, and finally use `forEach()` or `collect()` depending on whether I want to print directly or return a list.

For interview coding, I prefer returning a list first because it is easier to test. Printing is a side effect, so I usually keep it at the outer layer.

Interviewer: How would you create a new list of employees with a 10% salary increase?

Candidate: A senior answer should mention immutability. Instead of mutating the original employee object inside `map()`, I prefer creating a new `Employee` object with the updated salary. This avoids side effects and makes the stream pipeline safer.

If `Employee` is mutable and we call `setSalary()` inside `map()`, it works technically, but it modifies the original list. That can cause bugs if other parts of the system still use the original salary.

Interviewer: How do you find the employee with the highest salary using Stream API?

Candidate: I would use `max()` with a comparator. Since the result may not exist if the list is empty, the return type is `Optional<Employee>`. In production code, I should handle the empty case instead of directly calling `get()`.

Interviewer: Why do we need Optional in Java?

Candidate: `Optional` is a container object used to represent a value that may or may not be present. It helps us express absence explicitly and reduce accidental `NullPointerException`.

However, `Optional` does not magically remove null problems. It should be used properly. A senior practice is:

- use `Optional` mainly as a return type when a result may not exist;
- avoid using `Optional` as entity fields or method parameters in most cases;
- avoid calling `get()` without checking;
- prefer `orElse`, `orElseGet`, `orElseThrow`, `ifPresent`, or `map`.

Interviewer: What is the difference between intermediate and terminal operations in Stream API?

Candidate: Intermediate operations return another stream and are lazy. They build the pipeline but do not execute it immediately. Examples are `filter`, `map`, `flatMap`, `sorted`, and `distinct`.

Terminal operations trigger the execution of the pipeline and produce a result or side effect. Examples are `collect`, `toList`, `forEach`, `count`, `reduce`, `findFirst`, and `anyMatch`.

The important point is that Stream API uses lazy evaluation. If there is no terminal operation, intermediate operations will not run.

Interviewer: How would you solve smallest positive missing number in an integer array?

Candidate: A clean solution is to put all positive numbers into a `HashSet`, then start checking from `1` upward. The first number not found in the set is the answer.

This is easy to explain and has **O(n)** time complexity. Space complexity is **O(n)** due to the set.

For a more advanced version, we can solve it in-place with O(1) extra space by rearranging numbers, but in an interview I would first provide the simple correct solution, then mention the optimization.

Interviewer: How does HashMap work internally?

Candidate: `HashMap` stores key-value pairs in an internal array of buckets. When we put a key-value pair, Java calculates the key's hash code, applies a hash spreading function, and uses the result to find the bucket index.

If the bucket is empty, the entry is stored there. If another key already exists in the same bucket, a collision happens. Java then compares keys using `equals()` to know whether it should replace an existing value or add a new entry.

Since Java 8, if too many entries are stored in the same bucket, the linked list can be converted into a balanced tree to improve lookup performance from O(n) to O(log n) in worst-case collision scenarios.

Important senior points:

- default initial capacity is 16;
- default load factor is 0.75;
- resize happens when size exceeds threshold;
- `hashCode()` finds the bucket, `equals()` finds the exact key;
- one null key is allowed;
- `HashMap` is not thread-safe;
- mutable keys are dangerous because changing fields used in `hashCode()` can make the key unreachable.

Interviewer: What is the difference between ArrayList and LinkedList?

Candidate: `ArrayList` is backed by a dynamic array. It is very good for random access because `get(index)` is O(1). It is usually the default choice for lists in Java applications.

`LinkedList` is backed by a doubly linked list. It is not good for random access because it must traverse nodes, so `get(index)` is O(n). It can be efficient for insert/delete when we already have the node position, but in normal Java usage we usually do not have direct node references.

A senior point is that many people say LinkedList is better for insert/delete, but in real-world Java applications `ArrayList` often performs better because of CPU cache locality and lower memory overhead.

public static int firstMissingPositive(int[] nums) {
    Set<Integer> positives = Arrays.stream(nums)
        .filter(n -> n > 0)
        .boxed()
        .collect(Collectors.toSet());

    int candidate = 1;
    while (positives.contains(candidate)) {

How does HashMap work internally?
Candidate — senior version

HashMap stores key-value pairs in an internal array of buckets. When we put a key-value pair, Java calculates the key's hash code, applies a hash spreading function, and uses the result to find the bucket index.

If the bucket is empty, the entry is stored there. If another key already exists in the same bucket, a collision happens. Java then compares keys using equals() to know whether it should replace an existing value or add a new entry.

Since Java 8, if too many entries are stored in the same bucket, the linked list can be converted into a balanced tree to improve lookup performance from O(n) to O(log n) in worst-case collision scenarios.

Important senior points:

  • default initial capacity is 16;
  • default load factor is 0.75;
  • resize happens when size exceeds threshold;
  • hashCode() finds the bucket, equals() finds the exact key;
  • one null key is allowed;
  • HashMap is not thread-safe;
  • mutable keys are dangerous because changing fields used in hashCode() can make the key unreachable.

What is the difference between ArrayList and LinkedList?
Candidate — senior version

ArrayList is backed by a dynamic array. It is very good for random access because get(index) is O(1). It is usually the default choice for lists in Java applications.

LinkedList is backed by a doubly linked list. It is not good for random access because it must traverse nodes, so get(index) is O(n). It can be efficient for insert/delete when we already have the node position, but in normal Java usage we usually do not have direct node references.

Interviewer: How does garbage collection work in heap memory?

Candidate: Java heap is managed by the garbage collector. Most JVMs use the generational hypothesis: most objects die young, while some survive longer.

Interviewer: Explain Saga pattern.

Candidate: Saga splits a large distributed transaction into a sequence of local transactions. Each service updates its own database and publishes an event or returns a result. If one step fails, compensating actions are executed to undo previous steps logically.

Example order flow:

1. Order service creates order as `PENDING`.
2. Payment service reserves payment.
3. Inventory service reserves stock.
4. Shipping service creates shipment.
5. Order service marks order as `CONFIRMED`.

If inventory reservation fails, payment reservation is cancelled and the order is marked as failed.

This avoids holding locks across services and is more scalable than 2PC.

Interviewer
Explain Saga pattern.
Candidate — senior version

Saga splits a large distributed transaction into a sequence of local transactions. Each service updates its own database and publishes an event or returns a result. If one step fails, compensating actions are executed to undo previous steps logically.

Example order flow:

1. Order service creates order as PENDING. 2. Payment service reserves payment. 3. Inventory service reserves stock. 4. Shipping service creates shipment. 5. Order service marks order as CONFIRMED.

If inventory reservation fails, payment reservation is cancelled and the order is marked as failed.

This avoids holding locks across services and is more scalable than 2PC.

import java.util.*;
import java.util.stream.*;

public class EmployeeStreamInterview {
    static class Employee {
        private final int id;
        private final String name;
        private final double salary;

        public Employee(int id, String name, double salary) {
            this.id = id;
            this.name = name;
            this.salary = salary;
        }

        public int getId() { return id; }
        public String getName() { return name; }
        public double getSalary() { return salary; }

        @Override
        public String toString() {
            return "Employee{id=" + id + ", name='" + name + "', salary=" + salary + "}";
        }
    }

    public static void main(String[] args) {
        List<Employee> employees = List.of(
            new Employee(1, "Alice", 4500),
            new Employee(2, "Bob", 7000),
            new Employee(3, "Charlie", 9000)
        );

        double threshold = 5000;

        List<String> highSalaryNames = employees.stream()
            .filter(e -> e.getSalary() > threshold)
            .map(Employee::getName)
            .toList();

        List<Employee> increasedSalaryEmployees = employees.stream()
            .map(e -> new Employee(e.getId(), e.getName(), e.getSalary() * 1.10))
            .toList();

        Employee highestPaid = employees.stream()
            .max(Comparator.comparingDouble(Employee::getSalary))
            .orElseThrow(() -> new IllegalArgumentException("Employee list is empty"));

        System.out.println("Employees salary > " + threshold + ": " + highSalaryNames);
        System.out.println("After 10% increase: " + increasedSalaryEmployees);
        System.out.println("Highest paid: " + highestPaid);
    }
}

import java.util.*;
import java.util.stream.*;

public class SmallestMissingPositive {
    public static int firstMissingPositive(int[] nums) {
        Set<Integer> positives = Arrays.stream(nums)
            .filter(n -> n > 0)
            .boxed()
            .collect(Collectors.toSet());

        int candidate = 1;
        while (positives.contains(candidate)) {
            candidate++;
        }
        return candidate;
    }

    public static void main(String[] args) {
        System.out.println(firstMissingPositive(new int[]{1, 2, 3, 4, 6, 7, 8, 9})); // 5
        System.out.println(firstMissingPositive(new int[]{-3, -1, 2}));              // 1
        System.out.println(firstMissingPositive(new int[]{1, 2, 3}));                // 4
    }
}

import java.util.*;
import java.util.function.Function;
import java.util.stream.Collectors;

public class PatternCounter {
    public static Map<String, Long> countPatternsSeparatedBySpace(String input) {
        return Arrays.stream(input.trim().split("\s+"))
            .collect(Collectors.groupingBy(
                Function.identity(),
                LinkedHashMap::new,
                Collectors.counting()
            ));
    }

    public static Map<String, Long> countFixedLengthPatterns(String input, int tokenLength) {
        String normalized = input.replaceAll("\s+", "");
        Map<String, Long> result = new LinkedHashMap<>();

        for (int i = 0; i + tokenLength <= normalized.length(); i += tokenLength) {
            String token = normalized.substring(i, i + tokenLength);
            result.merge(token, 1L, Long::sum);
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println(countPatternsSeparatedBySpace("xx vc ff yy tt vc xx"));
        System.out.println(countFixedLengthPatterns("xxvcffyyttvcxx", 2));
    }
}
