Java Backend Engineer Interview Introduction

A polished interview script combining your self-introduction and the most challenging part of your recent project. Use this page to practice speaking naturally and confidently.

Self Introduction

I have around nine years of experience as a Java backend engineer. My main technical stack includes Java, Spring Boot, REST APIs, JPA/Hibernate, SQL databases, unit testing, and architecture design.

Currently, I am working as a Java team leader, leading a team of seven members.

In my recent project, I worked on a commercial SIM card management system for ANA airline. The project was built from scratch. The backend was developed using Java and Spring Boot, the frontend used Next.js, and the database was PostgreSQL. We also used several AWS cloud services such as SQS, Lambda, Cognito, and other related services.

I was responsible for analyzing requirements, designing the backend architecture, preparing the codebase, implementing core features, reviewing code, supporting the production release, tracing logs, and fixing critical issues in production.

From a technical perspective, I focused on clean architecture, transaction management, API design, data consistency, exception handling, logging, and maintainability. I also supported team members through code reviews, technical discussions, and guidance during implementation.

  • Team leader, 7 members
  • Built from scratch
  • ANA commercial SIM system
  • Java / Spring Boot / Next.js
  • PostgreSQL / AWS services
  • Architecture and codebase
  • Production release support
2

Biggest Challenge

The biggest challenge in my project was related to security.

In this project, I worked on several important features such as building the codebase from scratch, implementing security, and integrating payment. However, I think the most challenging part was the security design and implementation, because it was the first time I applied AWS Cognito and AVP for authentication and authorization across the whole project, including the application, my page, and admin modules.

For the application and my page, we used the same authentication mechanism with AWS Cognito custom authentication, including login and two-factor authentication using OTP sent via email.

For the admin module, we also used AWS Cognito, but with a different two-factor authentication mechanism using a TOTP authenticator application.

In addition, we used AWS Verified Permissions to control whether a user is allowed to access specific APIs or screens. We also applied Spring AOP to ensure that users with the USER role can only access their own resources and cannot access resources belonging to other users.

As a result, the security implementation passed multiple security scanning tools from the client side and has been working well in production until now.

Keywords to remember

  • Security was the biggest challenge
  • AWS Cognito custom auth
  • OTP via email
  • Admin TOTP authenticator
  • AWS Verified Permissions
  • API and screen authorization
  • Spring AOP resource ownership
  • Passed client security scans
