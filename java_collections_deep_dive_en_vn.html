Java Collections Deep Dive: Hashing, equals/hashCode, HashMap Internals & Interview Q&A

From basic to advanced Java Collections knowledge for Senior Backend interviews. Focus on practical usage, internal mechanisms, performance, pitfalls, concurrent collections, and common interview answers in English and Vietnamese.

1. Big Picture

Java Collections Framework is a unified architecture for storing, accessing, searching, sorting, and manipulating groups of objects.

Iterable ↓ Collection ├── List ├── Set └── Queue / Deque Map is part of Java Collections Framework, but it does NOT extend Collection. Map stores key-value pairs.

List

Ordered collection, allows duplicates. Example: ArrayList, LinkedList.

Set

No duplicate elements. Example: HashSet, LinkedHashSet, TreeSet.

Queue / Deque

Designed for processing elements. Example: ArrayDeque, PriorityQueue, BlockingQueue.

Map

Key-value structure. Keys are unique. Example: HashMap, LinkedHashMap, TreeMap, ConcurrentHashMap.

Senior mindset: In interviews, do not only say “ArrayList is array, LinkedList is node”. Explain complexity, memory, cache locality, resizing, hashing, equality contract, iteration behavior, and thread-safety.

3. List Deep Dive

ArrayList

ArrayList is backed by a dynamic array. It is usually the default choice for List because random access and iteration are fast.

OperationComplexityNotes
get(index)O(1)Direct array access.
add(element)Amortized O(1)May trigger resize.
add(index, element)O(n)Need shift elements.
remove(index)O(n)Need shift elements.
contains(element)O(n)Linear scan using equals.

ArrayList resizing

When internal array is full, ArrayList creates a larger array and copies existing elements. This is why append is amortized O(1), not always O(1).

List<Integer> numbers = new ArrayList<>();
for (int i = 0; i < 1_000_000; i++) {
    numbers.add(i);
}

// If size is known, pre-size to reduce resizing:
List<Integer> optimized = new ArrayList<>(1_000_000);

LinkedList

LinkedList is a doubly linked list. Each node stores item, previous pointer, and next pointer.

OperationComplexityNotes

addFirst/addLastO(1)Good for deque operations.
removeFirst/removeLastO(1)Good for queue/deque.
iterationO(n)Usually slower than ArrayList due to pointer chasing/cache locality.
Interview trap: Many candidates say “LinkedList is better for insert/delete”. This is only true when you already have the node position. If you insert/delete by index, finding the position is O(n).

6. HashMap Internals — Most Important Interview Topic

What is HashMap?

HashMap is a hash table based implementation of Map. It stores entries in an internal array of buckets. Each bucket may contain zero, one, or multiple entries.

HashMap internal idea: table = array of buckets index 0 → null index 1 → Node(key1, value1) index 2 → Node(key2, value2) → Node(key3, value3) index 3 → TreeNode(...) ...

HashMap put flow

put(key, value) ↓ 1. Calculate hash from key.hashCode() ↓ 2. Spread hash bits to reduce poor hash distribution ↓ 3. Calculate bucket index: (table.length - 1) & hash ↓ 4. If bucket empty → insert new node ↓ 5. If same key found by hash + equals → replace value ↓ 6. If collision with different key → append node or insert into tree ↓ 7. If size exceeds threshold → resize table
Map<String, Integer> map = new HashMap<>();
map.put("Java", 17);
map.put("Spring", 6);
map.put("Java", 21); // same key, value replaced

System.out.println(map.get("Java")); // 21

How HashMap finds bucket index

HashMap does not usually use modulo directly. It uses bit operation when table length is power of two.

index = (table.length - 1) & hash

This is fast and works well when table length is power of two.

Load factor and threshold

TermMeaning
CapacityNumber of buckets in internal table.
Load factorHow full the table can be before resizing. Default is 0.75.
Thresholdcapacity * loadFactor. When size exceeds threshold, HashMap resizes.
 
Map<String, Integer> map = new HashMap<>(16, 0.75f);
// threshold = 16 * 0.75 = 12
// when size exceeds 12, resize happens

Resize / Rehash

When HashMap grows beyond threshold, it creates a bigger table, usually double capacity, and redistributes entries. This operation is expensive.

Production tip: If you know expected size, create HashMap with proper initial capacity to reduce resizing.
int expectedSize = 1_000_000;
Map<Long, User> users = new HashMap<>((int) (expectedSize / 0.75f) + 1);

Collision

A collision happens when different keys map to the same bucket index.

key A → hash → index 5 key B → hash → index 5 Bucket 5: Node(A) → Node(B)

Collision handling before and after Java 8

VersionCollision Handling
Before Java 8Bucket uses linked list.
Java 8+Bucket starts as linked list, but can become red-black tree when collision chain is large.

Treeification

In Java 8+, when many entries collide in the same bucket, HashMap may convert the linked list into a red-black tree to improve lookup performance.

ConditionMeaning
TREEIFY_THRESHOLD = 8If bucket has too many nodes, it may treeify.
MIN_TREEIFY_CAPACITY = 64HashMap prefers resizing instead of treeifying if table is still small.
UNTREEIFY_THRESHOLD = 6Tree can become list again when entries are reduced.
Interview answer: Average HashMap get/put is O(1). In heavy collision, linked list would be O(n), but Java 8+ can treeify bucket to O(log n), assuming keys are comparable or tie-break can be handled.

Why HashMap is not thread-safe

HashMap is not safe for concurrent modification. Multiple threads writing at the same time can cause lost updates, inconsistent state, or unexpected behavior.

Map<String, Integer> map = new HashMap<>();

// Not safe if many threads call put at the same time
map.put("A", 1);
Use instead: ConcurrentHashMap, external synchronization, or immutable map depending on use case.

7. equals() and hashCode() — Critical for Hashing

Why equals and hashCode matter

Hash-based collections such as HashMap, HashSet, and ConcurrentHashMap depend on hashCode() and equals().

HashMap lookup: 1. Use hashCode() to find bucket 2. Use equals() to find exact key inside bucket

Contract

RuleMeaning
If a.equals(b) is truea.hashCode() must equal b.hashCode().
If hashCode is sameObjects may or may not be equal. Collision is allowed.
equals must be reflexivea.equals(a) is true.
equals must be symmetricIf a.equals(b), then b.equals(a).
equals must be transitiveIf a equals b and b equals c, then a equals c.
equals must be consistentResult should not change unless fields used in equality change.

Correct implementation example

public class Employee {
    private final Long id;
    private final String email;

    public Employee(Long id, String email) {
        this.id = id;
        this.email = email;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee employee)) return false;
        return Objects.equals(id, employee.id)
            && Objects.equals(email, employee.email);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, email);
    }
}

What happens if equals is overridden but hashCode is not?

Set<Employee> set = new HashSet<>();

Employee e1 = new Employee(1L, "a@example.com");
Employee e2 = new Employee(1L, "a@example.com");

set.add(e1);
set.add(e2);

System.out.println(set.size()); // may be 2 if hashCode is not consistent

If two objects are logically equal but have different hash codes, HashSet/HashMap may place them into different buckets and fail to detect duplicates.

Mutable key problem

Never mutate fields used in equals() or hashCode() after inserting object as key into HashMap or element into HashSet.

class User {
    String email;

    public boolean equals(Object o) {
        return o instanceof User u && Objects.equals(email, u.email);
    }

    public int hashCode() {
        return Objects.hash(email);
    }
}

User user = new User("old@example.com");
Set<User> users = new HashSet<>();
users.add(user);

user.email = "new@example.com";

System.out.println(users.contains(user)); // may be false
Senior warning: Mutable keys break hash-based collections because the object is stored in bucket based on old hash, but lookup uses new hash.

Business key vs database ID

For JPA entities, equals/hashCode is tricky. If you use generated ID, it may be null before persistence. If you use mutable business fields, hash can change.

ApproachProsRisk
Use generated IDStable after persistenceID is null before persist; equality changes after save.
Use immutable business keyWorks before persistenceOnly safe if truly unique and immutable.
Use default object identitySimpleLogical duplicates may not be detected.

Comparable vs Comparator

    try {
        queue.put("message"); // waits if full
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
});

Thread consumer = new Thread(() -> {
    try {
        String message = queue.take(); // waits if empty
    } catch (InterruptedException e) {

});

9. Concurrent Collections

Normal collections such as ArrayList and HashMap are not thread-safe for concurrent modification. Java provides concurrent collections for multi-threaded environments.

CollectionPurposeNotes
ConcurrentHashMapThread-safe map with high concurrency.No null key/value. Prefer over Hashtable.
CopyOnWriteArrayListThread-safe list optimized for many reads, few writes.Writes copy entire array, expensive for frequent writes.
BlockingQueueThread-safe producer-consumer queue.Supports blocking put/take.
ConcurrentLinkedQueueNon-blocking thread-safe queue.High-throughput queue.
ConcurrentSkipListMapSorted concurrent map.Concurrent alternative to TreeMap.

ConcurrentHashMap atomic operations

ConcurrentHashMap<String, Integer> counts = new ConcurrentHashMap<>();

counts.merge("ERROR", 1, Integer::sum);

counts.computeIfAbsent("user:1", key -> loadUserScore(key));

Why ConcurrentHashMap does not allow null

In concurrent maps, null would create ambiguity. If get(key) returns null, it is unclear whether the key is absent or the value is actually null, especially with concurrent updates.

Fail-fast vs fail-safe / weakly consistent

Iterator TypeBehaviorExample
Fail-fastThrows ConcurrentModificationException when collection is structurally modified during iteration outside iterator.ArrayList, HashMap iterators.
SnapshotIterates over a copied snapshot.CopyOnWriteArrayList.
Weakly consistentMay reflect some concurrent changes, does not throw fail-fast exception.ConcurrentHashMap iterator.

ConcurrentModificationException example

List<String> names = new ArrayList<>(List.of("A", "B", "C"));

for (String name : names) {
    if (name.equals("B")) {
        names.remove(name); // may throw ConcurrentModificationException
    }
}

Correct removal

Iterator<String> iterator = names.iterator();
while (iterator.hasNext()) {
    if (iterator.next().equals("B")) {
        iterator.remove();
    }
}

// or
names.removeIf(name -> name.equals("B"));

Choosing the right collection

  • Need indexed access and fast iteration: ArrayList.
  • Need uniqueness and fast lookup: HashSet.
  • Need uniqueness and insertion order: LinkedHashSet.
  • Need sorted unique values: TreeSet.
  • Need key-value lookup: HashMap.
  • Need key-value lookup with insertion/access order: LinkedHashMap.
  • Need sorted keys/range query: TreeMap.
  • Need concurrent key-value access: ConcurrentHashMap.
  • Need stack/queue/deque: ArrayDeque.
  • Need producer-consumer: BlockingQueue.

11. Common Interview Questions & Answers — English

Q1. What is Java Collections Framework?

A: It is a unified architecture for storing and manipulating groups of objects. It provides interfaces such as List, Set, Queue, Deque, Map and implementations such as ArrayList, HashSet, HashMap, TreeMap, ConcurrentHashMap. It also provides algorithms through the Collections utility class.

Q2. ArrayList vs LinkedList?

A: ArrayList is backed by a dynamic array. It has O(1) random access, fast iteration, and lower memory overhead. LinkedList is a doubly linked list. It has O(n) random access and higher memory overhead. LinkedList is only better for adding/removing at ends or when you already have node position. For most cases, ArrayList is preferred.

Q3. How does HashMap work internally?

A: HashMap stores entries in an array of buckets. For put/get, it computes hash from key.hashCode(), calculates bucket index using bit operation, then checks entries in the bucket using hash and equals. If bucket is empty, it inserts. If same key exists, it replaces value. If collision happens, entries are stored in a linked list or, in Java 8+, converted to a red-black tree when collision chain becomes large.

Q4. What is a hash collision?

A: Collision happens when different keys map to the same bucket index. HashMap handles collision by storing multiple entries in the bucket. Before Java 8 it used linked list. Java 8+ can treeify heavily-collided buckets into red-black trees to improve worst-case lookup.

Q5. Why must equals and hashCode be overridden together?

A: Hash-based collections first use hashCode to find a bucket, then use equals to find the exact object inside that bucket. If two objects are equal by equals but return different hash codes, they may be placed in different buckets, causing HashMap/HashSet to fail lookup or allow duplicates.

Q6. If two objects have same hashCode, are they equal?

A: Not necessarily. Same hashCode only means they may be in the same bucket. Hash collision is allowed. equals is still required to determine logical equality.

Q7. What happens if a key is mutated after insertion into HashMap?

A: If fields used in hashCode/equals are changed, the key may no longer be found because it is stored in bucket calculated from old hash, but lookup uses new hash. This is why map keys should be immutable or at least fields used for equality must not change.

Q8. HashMap vs Hashtable vs ConcurrentHashMap?

A: HashMap is not thread-safe and allows one null key. Hashtable is legacy, synchronized, and does not allow null key/value. ConcurrentHashMap is thread-safe with better concurrency and does not allow null key/value. For concurrent use, prefer ConcurrentHashMap.

Q9. HashSet vs TreeSet?

A: HashSet uses hashing, has no guaranteed order, and average O(1) add/remove/contains. TreeSet uses red-black tree, keeps sorted order, and operations are O(log n). Use HashSet for fast uniqueness and TreeSet for sorted unique elements.

Q10. What is fail-fast iterator?

A: A fail-fast iterator detects structural modification outside the iterator during iteration and throws ConcurrentModificationException. ArrayList and HashMap iterators are fail-fast. It is a bug-detection mechanism, not a thread-safety guarantee.

Q11. Comparable vs Comparator?

A: Comparable defines natural ordering inside the class using compareTo. Comparator defines external ordering using compare and allows multiple sorting strategies. Use Comparator when sorting by different fields or when you cannot modify the class.

Q12. Why ConcurrentHashMap does not allow null?

A: In concurrent context, null causes ambiguity. If get(key) returns null, it is unclear whether key is absent or value is null, especially when another thread may update the map. So ConcurrentHashMap disallows null key/value.

Q13. What is load factor in HashMap?

A: Load factor controls how full the table can be before resizing. Default is 0.75. Threshold equals capacity multiplied by load factor. Higher load factor saves memory but increases collision risk. Lower load factor reduces collisions but uses more memory.

Q14. Why is ArrayDeque preferred over Stack?

A: Stack is legacy and synchronized because it extends Vector. ArrayDeque is faster for stack/deque operations in single-threaded use and is the recommended general-purpose stack replacement.

Q15. How do you choose a collection in production?

A: I choose based on access pattern, ordering, uniqueness, sorting, concurrency, memory, and expected size. For most lists, ArrayList. For uniqueness, HashSet. For key-value lookup, HashMap. For sorted keys, TreeMap. For concurrent maps, ConcurrentHashMap. For queue/deque, ArrayDeque or BlockingQueue depending on thread-safety needs.

17. HashMap Internals — Chủ đề phỏng vấn cực quan trọng

HashMap là gì?

HashMap là implementation của Map dựa trên hash table. Nó lưu entries trong internal array các bucket.

HashMap internal idea: table = array of buckets index 0 → null index 1 → Node(key1, value1) index 2 → Node(key2, value2) → Node(key3, value3) index 3 → TreeNode(...) ...

Flow put(key, value)

put(key, value) ↓ 1. Tính hash từ key.hashCode() ↓ 2. Spread hash bits để giảm phân bố xấu ↓ 3. Tính bucket index: (table.length - 1) & hash ↓ 4. Bucket empty → insert node mới ↓ 5. Nếu same key bằng hash + equals → replace value ↓ 6. Nếu collision với key khác → append node hoặc insert vào tree ↓ 7. Nếu size vượt threshold → resize table

Bucket index

index = (table.length - 1) & hash

HashMap dùng bit operation nhanh hơn modulo, vì capacity là power of two.

Load factor và threshold

TermÝ nghĩa
CapacitySố bucket trong internal table.
Load factorMức độ đầy trước khi resize. Default 0.75.
Thresholdcapacity * loadFactor. Size vượt threshold thì resize.

Collision

Collision xảy ra khi nhiều key khác nhau map vào cùng bucket index.

key A → hash → index 5 key B → hash → index 5 Bucket 5: Node(A) → Node(B)

Collision handling

VersionCách xử lý
Trước Java 8Bucket dùng linked list.

Câu trả lời phỏng vấn: Average get/put của HashMap là O(1). Nếu collision nặng, linked list là O(n), nhưng Java 8+ có thể treeify bucket thành red-black tree để cải thiện thành O(log n).

HashMap không thread-safe

HashMap không an toàn khi nhiều thread cùng modify. Có thể gây lost update, inconsistent state hoặc behavior không mong muốn.

Nên dùng: ConcurrentHashMap, external synchronization, hoặc immutable map tùy use case.

18. equals() và hashCode() — Quan trọng nhất cho hashing

Vì sao quan trọng?

Hash-based collections như HashMap, HashSet, ConcurrentHashMap phụ thuộc vào hashCode() và equals().

HashMap lookup: 1. Dùng hashCode() để tìm bucket 2. Dùng equals() để tìm đúng key trong bucket

Contract

RuleÝ nghĩa
Nếu a.equals(b) truea.hashCode() phải bằng b.hashCode().
Nếu hashCode giống nhauObject có thể bằng hoặc không bằng nhau. Collision được phép.
equals reflexivea.equals(a) true.
equals symmetricNếu a.equals(b), thì b.equals(a).
equals transitiveNếu a equals b và b equals c, thì a equals c.
equals consistentKết quả không đổi nếu field dùng để compare không đổi.

Ví dụ đúng

public class Employee {
    private final Long id;
    private final String email;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee employee)) return false;
        return Objects.equals(id, employee.id)
            && Objects.equals(email, employee.email);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, email);
    }
}

Override equals nhưng không override hashCode

Nếu hai object logically equal nhưng hashCode khác nhau, HashSet/HashMap có thể đưa chúng vào bucket khác nhau và không detect duplicate.

Mutable key problem

Không nên thay đổi field dùng trong equals() hoặc hashCode() sau khi object đã được dùng làm key trong HashMap hoặc element trong HashSet.

User user = new User("old@example.com");
Set<User> users = new HashSet<>();
users.add(user);

user.email = "new@example.com";

System.out.println(users.contains(user)); // may be false
Cảnh báo Senior: Mutable key phá hash-based collections vì object đang nằm ở bucket theo old hash, nhưng lookup dùng new hash.

22. Tổng hợp câu hỏi phỏng vấn và trả lời — Vietnamese

Q1. Java Collections Framework là gì?

A: Là kiến trúc thống nhất để lưu trữ và xử lý nhóm object. Nó cung cấp interfaces như List, Set, Queue, Deque, Map và implementations như ArrayList, HashSet, HashMap, TreeMap, ConcurrentHashMap. Ngoài ra có utility class Collections cung cấp sort, search, unmodifiable, synchronized wrapper.

Q2. ArrayList khác LinkedList thế nào?

A: ArrayList dùng dynamic array, random access O(1), iteration nhanh và ít memory overhead. LinkedList dùng doubly linked nodes, random access O(n), memory overhead cao hơn. LinkedList chỉ lợi khi thao tác đầu/cuối hoặc đã có node position. Hầu hết case nên dùng ArrayList.

Q3. HashMap hoạt động thế nào bên trong?

A: HashMap lưu entries trong array of buckets. Khi put/get, nó tính hash từ key.hashCode(), tính bucket index bằng bit operation, sau đó dùng hash và equals để tìm key trong bucket. Nếu bucket empty thì insert. Nếu key đã tồn tại thì replace value. Nếu collision thì lưu dạng linked list hoặc Java 8+ có thể chuyển sang red-black tree khi collision chain lớn.

Q4. Hash collision là gì?

A: Collision xảy ra khi nhiều key khác nhau map vào cùng bucket index. HashMap xử lý bằng cách lưu nhiều entry trong bucket. Trước Java 8 dùng linked list; Java 8+ có thể treeify bucket thành red-black tree để cải thiện lookup khi collision nặng.

Q5. Vì sao override equals phải override hashCode?

A: Hash-based collections dùng hashCode để tìm bucket trước, rồi dùng equals để tìm object chính xác trong bucket. Nếu hai object equals true nhưng hashCode khác nhau, chúng có thể nằm ở bucket khác nhau, làm HashMap/HashSet lookup sai hoặc cho duplicate.

Q6. Hai object có cùng hashCode thì có equals không?

A: Không chắc. Cùng hashCode chỉ có nghĩa là có thể cùng bucket. Collision được phép. equals mới quyết định object có logically equal hay không.

Q7. Điều gì xảy ra nếu key bị mutate sau khi đưa vào HashMap?

A: Nếu field dùng trong hashCode/equals bị thay đổi, key có thể không tìm lại được. Object đang nằm ở bucket tính theo old hash, nhưng lookup dùng new hash. Vì vậy key nên immutable hoặc field dùng cho equality không được thay đổi.

Q8. HashMap vs Hashtable vs ConcurrentHashMap?

A: HashMap không thread-safe và cho phép một null key. Hashtable là legacy, synchronized toàn bộ method, không cho null key/value. ConcurrentHashMap thread-safe với concurrency tốt hơn, không cho null key/value. Trong concurrent use case nên dùng ConcurrentHashMap.

Q9. HashSet khác TreeSet thế nào?

A: HashSet dùng hashing, không đảm bảo order, average add/remove/contains O(1). TreeSet dùng red-black tree, giữ sorted order, operation O(log n). Dùng HashSet khi cần unique nhanh; dùng TreeSet khi cần sorted unique elements.

Q10. Fail-fast iterator là gì?

A: Fail-fast iterator detect structural modification trong lúc iterate nếu modification không qua chính iterator, rồi throw ConcurrentModificationException. ArrayList và HashMap iterator là fail-fast. Đây là cơ chế detect bug, không phải đảm bảo thread-safety.

Q11. Comparable khác Comparator thế nào?

A: Comparable định nghĩa natural ordering trong chính class qua compareTo. Comparator là external ordering strategy qua compare, cho phép nhiều cách sort khác nhau và dùng được khi không sửa được class.

Q12. Vì sao ConcurrentHashMap không cho null?

A: Trong concurrent context, null gây ambiguity. Nếu get(key) trả null, không biết key absent hay value là null, nhất là khi thread khác có thể update đồng thời. Vì vậy ConcurrentHashMap cấm null key/value.

Q13. Load factor trong HashMap là gì?

A: Load factor quyết định table được phép đầy tới mức nào trước khi resize. Default là 0.75. Threshold = capacity * loadFactor. Load factor cao tiết kiệm memory nhưng tăng collision risk; thấp giảm collision nhưng tốn memory hơn.

Q14. Vì sao ArrayDeque được khuyến nghị hơn Stack?

A: Stack là legacy class vì extends Vector và synchronized. ArrayDeque nhanh hơn cho stack/deque operations trong single-thread use case và thường được khuyến nghị thay Stack.

Q15. Chọn collection trong production như thế nào?

A: Chọn dựa trên access pattern, ordering, uniqueness, sorting, concurrency, memory và expected size. List thường dùng ArrayList. Unique nhanh dùng HashSet. Key-value lookup dùng HashMap. Sorted keys dùng TreeMap. Concurrent map dùng ConcurrentHashMap. Queue/deque dùng ArrayDeque hoặc BlockingQueue nếu cần thread-safe producer-consumer.
