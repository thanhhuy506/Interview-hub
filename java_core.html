JVM vs JDK vs JRE

Understanding the nested relationship and distinct boundaries of JDK, JRE, and JVM is a fundamental Java interview standard. They represent the compilation, runtime, and execution lifecycle phases.

Structural Nested Boundaries

JDK (Java Development Kit) = JRE + Development Tools (javac, jdb, jshell)
JRE (Java Runtime Environment) = JVM + Core Class Libraries
JVM (Java Virtual Machine) Executes bytecode line-by-line via JIT & Interpreter
Feature / Layer JVM JRE JDK
Purpose Executes Java bytecode. Provides runtime environment to execute applications. Provides tools needed to write, build, and run Java programs.
Inclusion Interpreter, JIT, Garbage Collector. JVM + Core class files (java.lang, util). JRE + Compiler (javac), Archiver (jar).
Target User Hardware / OS execution interface. End users executing prebuilt programs. Java software developers.
💡 Pro-Tip Interview Question

"Is JVM platform independent?"

Answer: No! The JVM is platform-dependent. There is a specific JVM build for Windows, macOS, Linux, etc. It is the JVM that interprets/translates platform-independent bytecode into platform-specific machine code.

Java Compilation Process

Java employs a unique two-stage approach: compilation to intermediate bytecode followed by real-time hardware execution via the JVM.

Source File MyClass.java
➔
Compiler javac MyClass.java
➔
Bytecode MyClass.class
➔
JVM (Execution) Interpreter & JIT Compiler

The Two Key Compilation / Execution Actors:

  • Compiler (javac): Evaluates the source code syntax, checks types, and writes compile-time assertions to output structural `.class` binary instruction structures containing platform-agnostic bytecode instructions.
  • JIT (Just-In-Time) Compiler: Resides inside the JVM. While executing, it monitors performance hotspots. High-execution blocks are compiled straight into native CPU instructions for maximum operational speed, rather than interpreted instruction-by-instruction.
3

Bytecode

Bytecode is the intermediate, machine-readable instruction set generated by compiling high-level Java code. Designed to target the virtual machine stack directly, bytecode acts as the universal language across all JVM implementations.

// Source Java Code
public int add(int a, int b) {
    return a + b;
}
// Resulting Bytecode (Compiled Representation)
iload_1       ; Load local int parameter 1 on stack
iload_2       ; Load local int parameter 2 on stack
iadd          ; Pop top two integers, add them
ireturn       ; Return resulting integer
🔍 Tool Tip

You can view compilation bytecode directly by typing javap -c MyClass.class into your system console on any compiled file.

ClassLoader

The Java ClassLoader is a subsystem of the JVM responsible for loading class files dynamically into system memory at runtime.

The Delegation Principle:

ClassLoaders follow the delegation-hierarchy model. When asked to find a class, a ClassLoader first delegates the request upwards to its parent ClassLoader before attempting to find it locally.

1. Bootstrap ClassLoader Loads core JVM classes (lib/rt.jar). Written in C/C++. Parent of Platform.
2. Platform / Extension Loads platform extensions / standard library APIs.
3. Application / System Loads your classes inside the custom classpath directories.
🔑 Three Steps of Loading:
  1. Loading: Acquires the raw binary bytes representing a class or interface file name.
  2. Linking: Includes bytecode verification, static field allocation (preparation), and symbolic reference compilation.
  3. Initialization: Executes static blocks and assigns actual program variables inside the loaded files.
5

Platform Independent

Java achieves its legendary WORA (Write Once, Run Anywhere) status by isolating compilation structures from CPU execution architectures.

How it works under the hood:

Languages like C/C++ compile directly into machine language for a target architecture (e.g. x86 assembly). Java compiles into bytecode. Any computer with the appropriate OS-specific JVM can execute the exact same `.class` bytecode file.

Platform Dependent Languages (e.g., C++) Source code compiles straight into operating system specific machine-binary structures. Binary cannot travel between OS platforms.
Platform Independent (Java) Code compiles to universal platform bytecode. Platform dependent JVMs read that exact same bytecode and resolve it to target systems on the fly.

Primitive vs Object

Java has a dual nature: highly-efficient low-level Primitive types and full Object structures that represent pointers in memory.

Feature Primitive Types (e.g. int, char) Object Types (e.g. Integer, String)
Memory Allocation Usually Stack memory (fast access). Heap memory (reference resides on Stack, object on Heap).
Performance Highly performant, minimal memory layout. Slower due to reference dereferencing and overhead.
Default Values Always default values (e.g., 0, false). Defaults to null if uninitialized.
Can use with Generics? No (e.g. List<int> is invalid). Yes (e.g. List<Integer>).

Wrapper Class

Wrapper classes provide a mechanism to wrap primitive values inside a standard Object container.

Primary Uses

  • Generics: Type parameters only support Object classes.
  • Utility Methods: Parsing integers from strings (e.g. Integer.parseInt("123")).
  • Collections: Storing primitive sequences in standard JVM collections (e.g., ArrayList, HashMap).
⚠️ Integer Cache Pitfall

To optimize performance, Java caches instances of wrapper classes representing values between -128 to 127. 

Integer a = 100;
Integer b = 100;
System.out.println(a == b); // Prints TRUE (points to cached instance)

Integer x = 200;
Integer y = 200;
System.out.println(x == y); // Prints FALSE (different objects on heap! Use .equals()!)
8

Auto boxing / Unboxing

Introduced in Java 5, these features allow Java to automatically convert between primitives and their respective wrapper objects without manual casting.

Autoboxing (Primitive ➔ Wrapper) 
// What you write:
Integer count = 10;

// What compiler does under the hood:
Integer count = Integer.valueOf(10);
Unboxing (Wrapper ➔ Primitive) 
// What you write:
int price = count;

// What compiler does under the hood:
int price = count.intValue();
⚠️ Major Interview Trap: NullPointerException during Unboxing

If a wrapper class instance is null, and you attempt to unbox it into a primitive, Java will throw a NullPointerException at runtime! 

Integer numObj = null;
int numPrim = numObj; // Throws NullPointerException!

String

Strings in Java are objects of the final class String. They are immutable—once created, their value cannot be changed.

The String Pool concept

When a String is initialized using literals, the JVM stores it in a special cache memory called the String Constant Pool inside the Heap. Reusing the literal resolves to the exact same pointer reference. 

String s1 = "Java"; // Created in pool
String s2 = "Java"; // Reuses literal from pool
System.out.println(s1 == s2); // TRUE

String s3 = new String("Java"); // Created directly on standard Heap
System.out.println(s1 == s3); // FALSE (different heap pointers)
🔑 Why are Strings Immutable?
  1. Security: Parameters like network connection URLs, file paths, and database credentials can't be altered mid-execution.
  2. Thread Safety: Multiple execution pipelines can read strings without synchronization.
  3. String Cache Hash: High performance inside collection structures because hashcodes are precomputed and cached.

StringBuilder & StringBuffer

When modifying strings frequently (e.g., inside loops), standard String concatenation is highly inefficient because it produces multiple short-lived garbage collector target references. Mutable companions StringBuilder and StringBuffer solve this issue.

Feature StringBuilder StringBuffer
Mutability Mutable Mutable
Thread Safety Not Thread-safe (unsynchronized methods) Thread-safe (synchronized methods)
Speed / Efficiency Extremely Fast (default choice for local modifications) Slower due to lock overhead

final / finally / finalize

Despite similar names, these are three distinct constructs in Java:

Modifier Keyword

final

  • Variable: Cannot be reassigned.
  • Method: Cannot be overridden in subclasses.
  • Class: Cannot be extended (e.g. String).
Block Structure

finally

A block used in try-catch structures for cleanup (e.g., closing connections). It **always** executes, even if an exception occurs.

Method

finalize()

A deprecated method in the Object class, formerly called by the garbage collector before deleting an object. **Never use this.**

static

The static keyword defines members belonging directly to the **class** itself rather than to individual object instances.

Common Static Varieties

  • Variables: Only one shared copy exists across all instances in heap memory.
  • Methods: Can be called without instantiating the class. Cannot access non-static variables directly (no reference to this).
  • Blocks: Run once when the class is first loaded by the ClassLoader.
  • Nested Classes: A static class defined inside another class; doesn't need a reference to the outer class instance.
// Static usage example
public class Counter {
    public static int count = 0; // Shared
    public static void increment() {
        count++; // OK
    }
}

enum

An enum represents a fixed set of type-safe, named constants. Under the hood, Enums are specialized classes extending java.lang.Enum.

✨ Cool Java Enum Features:

Unlike other languages, Java enums are full classes. They can declare **fields, constructors (always private), and methods**, and can even implement **interfaces**. 

public enum Severity {
    LOW(1), MEDIUM(2), HIGH(3); // Constants invoke constructor

    private final int level;

    Severity(int level) { // Constructor (always private)
        this.level = level;
    }

    public int getLevel() { return this.level; }
}

record (Java 16+)

Introduced in Java 16, a record is a special type of class designed exclusively to carry immutable data. It eliminates boilerplates for simple Data Transfer Objects (DTOs).

Modern Record (Java 16) 
public record User(String name, int age) {}
Just 1 line! Auto-generates: constructor, getters (no "get" prefix: e.g., user.name()), equals(), hashCode(), and toString().

Critical Rules

  • Immutable: Fields are implicitly private final.
  • No Inheritance: Records cannot extend other classes (they implicitly extend java.lang.Record) and are implicitly final.
  • Interfaces: Can implement interfaces.

var (Local Variable Type Inference)

Introduced in Java 10, the var keyword enables local variable type inference. The compiler determines the target type statically based on the initialization value.

✅ Where you CAN use var 
var text = "Hello"; // Local variable initialized
var list = new ArrayList<String>();
for (var item : list) {} // In loops
❌ Where you CANNOT use var 
// Not as fields:
public class User { var name = "John"; }
// Not as method arguments/returns:
public var doSomething(var a) {}
// Not without initialization:
var count;

Switch Expression & Optional

A. Switch Expressions (Java 12+)

Unlike traditional switch statements, switch expressions return a direct result value, omit break fall-through behaviors, and enforce path exhaustiveness. 

int days = switch (month) {
    case JANUARY, MARCH, MAY -> 31;
    case APRIL, JUNE, SEPTEMBER -> 30;
    case FEBRUARY -> {
        System.out.println("Leap check needed");
        yield 28; // Returns value for multi-line blocks
    }
    default -> throw new IllegalArgumentException();
};

B. Optional (Java 8+)

Optional<T> is a monadic container object designed specifically to represent optional/nullable properties explicitly, reducing runtime NullPointerExceptions.

Common Optional Patterns: 
Optional<String> opt = Optional.ofNullable(getUserName());

// Fallback default value if null
String name = opt.orElse("Guest");

// Trigger behavior if present
opt.ifPresent(n -> System.out.println("Hello " + n));
