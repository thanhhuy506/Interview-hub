Understand runtime metadata, dynamic method invocation, annotations, proxies, aspects, advice, pointcuts, join points, and how Spring uses AOP for transactions, security, caching and logging.

1. Big Picture

Reflection is a Java runtime capability to inspect and manipulate classes, methods, fields, constructors and annotations. Spring AOP is a programming model that applies cross-cutting behavior around Spring beans using proxies.

Java Reflection: Runtime metadata access → inspect class/method/field/annotation → create object dynamically → invoke method dynamically → used by frameworks internally Spring AOP: Proxy-based interception → wrap Spring bean with proxy → intercept method call → run advice before/after/around method → used for transaction, security, caching, logging

Reflection

Low-level Java feature. It works on class metadata and can access members dynamically.

Spring AOP

Higher-level Spring feature. It intercepts method calls on Spring beans through proxies.

Relationship

Spring may use reflection internally, but AOP itself is not just reflection. AOP is based on proxy interception.

Interview Focus

Explain when to use each, performance, proxy limitations, self-invocation, private/final methods, and real Spring examples.

Senior mindset: Reflection is about runtime inspection and dynamic access. AOP is about separating cross-cutting concerns from business logic by intercepting method calls.

2. Java Reflection Basics

What is Reflection?

Reflection allows Java code to inspect classes, methods, fields, constructors, annotations and invoke members at runtime, even if the class is only known dynamically.

Core Reflection Classes

ClassPurposeExample
Class<?>Runtime representation of a Java class.User.class, Class.forName()
FieldRepresents a field.Read/write field value dynamically.
MethodRepresents a method.Invoke method dynamically.
ConstructorRepresents a constructor.Create object dynamically.
AnnotationRepresents annotation metadata.Read custom annotation.

Getting Class Object

Class<User> clazz1 = User.class;

User user = new User();
Class<? extends User> clazz2 = user.getClass();

Class<?> clazz3 = Class.forName("com.example.User");

Inspect Fields and Methods

Class<User> clazz = User.class;

for (Field field : clazz.getDeclaredFields()) {
    System.out.println(field.getName() + " : " + field.getType());
}

for (Method method : clazz.getDeclaredMethods()) {
    System.out.println(method.getName());
}

Invoke Method Dynamically

public class UserService {
    public String hello(String name) {
        return "Hello " + name;
    }
}

UserService service = new UserService();

Method method = UserService.class.getDeclaredMethod("hello", String.class);
Object result = method.invoke(service, "Huy");

System.out.println(result); // Hello Huy

Access Private Field

public class User {
    private String email = "old@example.com";
}

User user = new User();

Field emailField = User.class.getDeclaredField("email");
emailField.setAccessible(true);

String oldEmail = (String) emailField.get(user);
emailField.set(user, "new@example.com");
Important: Accessing private members breaks encapsulation. Frameworks may do it, but business code should avoid abusing it.

3. Reflection Advanced

Reflection and Annotations

Many frameworks use reflection to read annotations and build runtime behavior.

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface AuditLog {
    String action();
}

public class PaymentService {
    @AuditLog(action = "PAYMENT_CREATED")
    public void createPayment() {
        // business logic
    }
}

Method method = PaymentService.class.getDeclaredMethod("createPayment");

if (method.isAnnotationPresent(AuditLog.class)) {
    AuditLog auditLog = method.getAnnotation(AuditLog.class);
    System.out.println(auditLog.action());
}

Dynamic Object Creation

Class<?> clazz = Class.forName("com.example.User");

Constructor<?> constructor = clazz.getDeclaredConstructor(String.class);
Object user = constructor.newInstance("huy@example.com");

Generic Type Inspection

public class UserRepository {
    private List<User> users;
}

Field field = UserRepository.class.getDeclaredField("users");
Type genericType = field.getGenericType();

if (genericType instanceof ParameterizedType parameterizedType) {
    Type actualType = parameterizedType.getActualTypeArguments()[0];
    System.out.println(actualType); // class User
}

Reflection in Real Frameworks

FrameworkReflection Usage
SpringScan classes, read annotations, create beans, inject dependencies, call lifecycle methods.
Hibernate/JPARead entity annotations, access fields, instantiate entities, map database columns.
JacksonInspect fields/getters/setters, serialize/deserialize JSON.
JUnitFind and invoke test methods annotated with @Test.
MockitoCreate mocks/proxies and inject fields.

Reflection Performance

Reflection is slower than direct method calls because it involves dynamic lookup, access checks, boxing/unboxing and less compiler optimization. Modern JVMs optimize some cases, but reflection still has overhead and should not be used in hot paths without caching.

Reflection Risks

  • Breaks encapsulation by accessing private fields/methods.
  • Runtime errors instead of compile-time errors.
  • Harder refactoring because method/field names may be strings.
  • Performance overhead if used heavily.
  • Security/module access restrictions can block reflective access.
  • Harder to understand and debug.

4. Spring AOP Basics

What is AOP?

AOP — Aspect-Oriented Programming — separates cross-cutting concerns from business logic. Cross-cutting concerns are logic repeated across many places, such as transaction, logging, security, caching, audit and metrics.

Without AOP: OrderService.createOrder() → log start → begin transaction → check security → business logic → commit transaction → log end With AOP: Proxy wraps OrderService → logging advice → transaction advice → security advice → actual business method

AOP Concepts

ConceptMeaningExample
AspectModule containing cross-cutting logic.LoggingAspect, AuditAspect.
AdviceCode executed at a join point.@Before, @After, @Around.
Join PointA point in program execution. In Spring AOP, usually method execution.Calling OrderService.createOrder().
PointcutExpression selecting join points.execution(* com.example..service..*(..)).
Target ObjectOriginal object being proxied.Real OrderService bean.
ProxyObject wrapping target to apply advice.JDK dynamic proxy or CGLIB proxy.
WeavingApplying aspect to target.In Spring AOP, done at runtime through proxy.

Advice Types

AdviceWhen it runsUse Case
@BeforeBefore method execution.Validation, logging before call.
@AfterAfter method execution, success or failure.Cleanup, generic logging.
@AfterReturningOnly after successful method return.Log response, audit success.
@AfterThrowingOnly when method throws exception.Error logging, failure audit.
@AroundWraps method execution.Performance timing, transaction-like behavior, retry.

5. Spring AOP Internals

Proxy-Based Mechanism

Spring AOP works by creating a proxy object around the target Spring bean. Client code calls the proxy. The proxy runs advice and then delegates to the target method.

Client ↓ Proxy bean ↓ run advice before Target method ↓ run advice after Return to client

JDK Dynamic Proxy vs CGLIB Proxy

Proxy TypeHow it worksWhen usedLimitation
JDK Dynamic ProxyCreates proxy implementing interfaces.When bean has interface.Only interface methods are proxied.
CGLIB ProxyCreates subclass of target class.When no interface or class-based proxy is configured.Cannot proxy final class/method; private methods cannot be advised.

@Transactional is AOP

@Transactional is one of the most common Spring AOP examples. Spring creates a proxy that opens transaction before method execution and commits/rolls back after execution.

@Service
public class OrderService {

    @Transactional
    public void createOrder(CreateOrderRequest request) {
        // 1. proxy opens transaction
        // 2. business logic executes
        // 3. proxy commits if success
        // 4. proxy rolls back if RuntimeException/Error
    }
}

Self-Invocation Problem

@Service
public class OrderService {

    public void outer() {
        this.inner(); // bypasses proxy
    }

    @Transactional
    public void inner() {
        // transaction may NOT be applied when called by this.inner()
    }
}
Very common interview point: Spring AOP works only when the call goes through the proxy. Self-invocation bypasses proxy.

Spring AOP Limitations

  • Only Spring beans are proxied.
  • Only method execution join points are supported in Spring AOP.
  • Private methods are not advised.
  • Final methods/classes cannot be proxied by CGLIB.
  • Self-invocation bypasses proxy.
  • Constructor execution is not advised by Spring AOP.
  • For full AspectJ features, use AspectJ weaving, not Spring proxy AOP.

6. Practical Spring AOP Examples

Example 1: Logging Execution Time

@Aspect
@Component
public class PerformanceLoggingAspect {

    @Around("execution(* com.example..service..*(..))")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();

        try {
            return joinPoint.proceed();
        } finally {
            long duration = System.currentTimeMillis() - start;
            System.out.println(joinPoint.getSignature() + " took " + duration + "ms");
        }
    }
}

Example 2: Audit by Custom Annotation

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Auditable {
    String action();
}

@Aspect
@Component
public class AuditAspect {

    @AfterReturning("@annotation(auditable)")
    public void auditSuccess(JoinPoint joinPoint, Auditable auditable) {
        System.out.println("Audit action = " + auditable.action());
        System.out.println("Method = " + joinPoint.getSignature().getName());
    }
}

@Service
public class PaymentService {

    @Auditable(action = "CREATE_PAYMENT")
    public void createPayment() {
        // business logic
    }
}

Example 3: Exception Logging

@Aspect
@Component
public class ExceptionLoggingAspect {

    @AfterThrowing(
        pointcut = "execution(* com.example..service..*(..))",
        throwing = "ex"
    )
    public void logException(JoinPoint joinPoint, Exception ex) {
        System.out.println("Exception in " + joinPoint.getSignature());
        System.out.println("Error: " + ex.getMessage());
    }
}

Example 4: Simple Retry with @Around

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface RetryableOperation {
    int maxAttempts() default 3;
}

@Aspect
@Component
public class RetryAspect {

    @Around("@annotation(retryable)")
    public Object retry(ProceedingJoinPoint joinPoint, RetryableOperation retryable) throws Throwable {
        int attempts = 0;
        Throwable lastError = null;

        while (attempts < retryable.maxAttempts()) {
            try {
                attempts++;
                return joinPoint.proceed();
            } catch (RuntimeException ex) {
                lastError = ex;
            }
        }

        throw lastError;
    }
}
Production note: For real retry, prefer battle-tested libraries like Spring Retry or Resilience4j because they handle backoff, retryable exceptions, metrics and circuit breakers better.

Relationship Between Them

Spring AOP may use reflection internally to inspect annotations, methods and metadata. However, Spring AOP is not the same as reflection. AOP is about method interception through proxy. Reflection is about dynamic metadata access and invocation.

Reflection: "Let me inspect this class/method/field and maybe invoke it dynamically." AOP: "Let me intercept calls to this Spring bean method and run extra behavior before/after/around it."

8. Common Pitfalls

Reflection Pitfalls

  • Overusing reflection in business code.
  • Accessing private fields and breaking encapsulation.
  • Using string method/field names that break during refactoring.
  • Ignoring performance overhead in loops or hot paths.
  • Not handling checked exceptions from reflection APIs.
  • Assuming reflective access always works with Java module restrictions.

AOP Pitfalls

  • Self-invocation bypasses proxy.
  • Private methods are not advised.
  • Final methods/classes may not be proxied.
  • Advice only applies to Spring beans.
  • Pointcut too broad can accidentally affect many methods.
  • Putting business logic inside aspects makes code hard to understand.
  • Wrong advice order can cause unexpected behavior.
  • Assuming @Transactional works on every method call without understanding proxy.

Best Practices

  • Use reflection mostly in framework-like code, not normal business services.
  • Cache reflective metadata if used repeatedly.
  • Prefer annotations and clear contracts over magic strings.
  • Use AOP for cross-cutting concerns only.
  • Keep aspects small, focused and observable.
  • Use explicit pointcuts and package conventions.
  • Understand proxy limitations before using @Transactional, @Async, @Cacheable.

9. Common Interview Questions & Answers — English

Q1. What is Java Reflection?

A: Reflection is a Java runtime feature that allows code to inspect and manipulate classes, fields, methods, constructors and annotations dynamically. It is commonly used by frameworks like Spring, Hibernate, Jackson and JUnit for annotation scanning, dependency injection, object creation and method invocation.

Q2. What are the disadvantages of reflection?

A: Reflection has runtime overhead, weaker compile-time safety, can break encapsulation, may fail at runtime because of wrong names or access restrictions, and can make code harder to understand and refactor. It should be used carefully, especially outside framework code.

Q3. What is Spring AOP?

A: Spring AOP is a proxy-based mechanism for applying cross-cutting concerns to Spring beans. It intercepts method calls and runs advice before, after, or around the target method. It is commonly used for transactions, security, caching, logging, audit and metrics.

Q4. How does Spring AOP work internally?

A: Spring creates a proxy for the target bean. Client code calls the proxy instead of the real object. The proxy checks pointcuts, runs applicable advice, and then delegates to the target method. Depending on the bean, Spring can use JDK dynamic proxy or CGLIB class-based proxy.

Q5. JDK Dynamic Proxy vs CGLIB?

A: JDK dynamic proxy creates a proxy implementing interfaces, so it works when the bean exposes an interface. CGLIB creates a subclass of the target class, so it can proxy classes without interfaces. However, CGLIB cannot proxy final classes or final methods, and private methods are not advised.

Q6. Is Spring AOP the same as reflection?

A: No. Reflection is a low-level Java feature for runtime metadata inspection and dynamic invocation. Spring AOP is a higher-level proxy-based method interception mechanism. Spring may use reflection internally, but AOP is mainly about proxies, pointcuts and advice.

Q7. Why does self-invocation break @Transactional?

A: Spring AOP works only when method calls go through the proxy. If a method inside the same class calls another method using this.inner(), the call bypasses the proxy, so transactional advice is not applied.

Q8. Can Spring AOP advise private methods?

A: No. Spring AOP is proxy-based and intercepts method calls through the proxy. Private methods are not visible to proxy-based method interception. Also, private method calls are usually internal calls within the class.

Q9. What is the difference between @Before, @After and @Around?

A: @Before runs before target method. @After runs after target method whether it succeeds or fails. @AfterReturning runs only on success. @AfterThrowing runs only on exception. @Around wraps the method and can control whether, when and how the target method executes.

Q10. When should you use AOP?

A: Use AOP for cross-cutting concerns repeated across many places: transaction, logging, metrics, audit, security, caching and tracing. Avoid putting core business logic into aspects because it makes behavior hidden and harder to understand.

10. Tổng quan

Reflection là khả năng runtime của Java để inspect và manipulate class, method, field, constructor, annotation. Spring AOP là cơ chế của Spring để apply cross-cutting behavior quanh Spring beans bằng proxy.

Java Reflection: Runtime metadata access → inspect class/method/field/annotation → create object dynamically → invoke method dynamically → framework hay dùng bên trong Spring AOP: Proxy-based interception → wrap Spring bean bằng proxy → intercept method call → chạy advice before/after/around method → dùng cho transaction, security, caching, logging

17. Pitfalls

Reflection Pitfalls

  • Lạm dụng reflection trong business code.
  • Access private fields làm phá encapsulation.
  • Dùng string method/field names khiến refactor dễ lỗi.
  • Bỏ qua performance overhead trong loops/hot paths.
  • Không xử lý checked exceptions từ reflection APIs.

AOP Pitfalls

  • Self-invocation bypass proxy.
  • Private methods không được advise.
  • Final methods/classes có thể không proxy được.
  • Advice chỉ apply cho Spring beans.
  • Pointcut quá rộng ảnh hưởng ngoài ý muốn.
  • Đưa business logic vào aspect làm code khó hiểu.
  • Advice order sai gây behavior khó đoán.
  • Tưởng @Transactional luôn chạy mà không hiểu proxy.

Best Practices

  • Dùng reflection chủ yếu cho framework-like code.
  • Cache reflective metadata nếu dùng lặp lại.
  • Dùng AOP cho cross-cutting concerns, không dùng để giấu business logic.
  • Pointcut nên rõ ràng, theo package convention.
  • Hiểu proxy limitation trước khi dùng @Transactional, @Async, @Cacheable.

18. Câu hỏi phỏng vấn và trả lời — Vietnamese

Q1. Java Reflection là gì?

A: Reflection là tính năng runtime của Java cho phép inspect và manipulate class, fields, methods, constructors và annotations một cách dynamic. Framework như Spring, Hibernate, Jackson, JUnit dùng reflection để scan annotation, inject dependency, create object và invoke method.

Q2. Nhược điểm của reflection?

A: Reflection có runtime overhead, compile-time safety thấp hơn, có thể phá encapsulation, dễ lỗi runtime do sai tên method/field hoặc access restriction, và làm code khó hiểu/khó refactor. Business code nên hạn chế dùng reflection trực tiếp.

Q3. Spring AOP là gì?

A: Spring AOP là cơ chế proxy-based để apply cross-cutting concerns vào Spring beans. Nó intercept method call và chạy advice trước, sau hoặc xung quanh target method. Use case phổ biến là transaction, security, caching, logging, audit và metrics.

Q4. Spring AOP hoạt động bên trong thế nào?

A: Spring tạo proxy cho target bean. Client gọi proxy thay vì object thật. Proxy kiểm tra pointcut, chạy advice phù hợp, rồi delegate tới target method. Spring có thể dùng JDK dynamic proxy hoặc CGLIB proxy.

Q5. JDK Dynamic Proxy khác CGLIB?

A: JDK dynamic proxy tạo proxy implement interface, phù hợp khi bean có interface. CGLIB tạo subclass của target class, dùng khi không có interface hoặc class-based proxy. CGLIB không proxy được final class/final method, private method cũng không được advise.

Q6. Spring AOP có phải Reflection không?

A: Không. Reflection là low-level Java feature để inspect metadata và invoke dynamic. Spring AOP là proxy-based method interception. Spring có thể dùng reflection bên trong, nhưng AOP chủ yếu là proxy, pointcut và advice.

Q7. Vì sao self-invocation làm @Transactional không chạy?

A: Spring AOP chỉ chạy khi method call đi qua proxy. Nếu method trong cùng class gọi this.inner(), call này bypass proxy nên transactional advice không được apply.

Q8. Spring AOP có advise private method không?

A: Không. Spring AOP là proxy-based, intercept method call qua proxy. Private method không visible cho proxy-based interception và thường là internal call trong cùng class.

Q9. @Before, @After, @Around khác nhau thế nào?

A: @Before chạy trước target method. @After chạy sau method dù success hay fail. @AfterReturning chỉ chạy khi success. @AfterThrowing chạy khi exception. @Around wrap method và có thể kiểm soát có gọi target method hay không, gọi khi nào, xử lý result/exception thế nào.

Q10. Khi nào dùng AOP?

A: Dùng AOP cho cross-cutting concerns lặp lại ở nhiều nơi như transaction, logging, metrics, audit, security, caching, tracing. Không nên đưa core business logic vào aspect vì behavior bị ẩn và khó maintain.

Quick Senior Checklist

  • Know Class, Field, Method, Constructor, annotations.
  • Know why frameworks use reflection.
  • Know Reflection drawbacks: performance, encapsulation, runtime errors.
  • Explain AOP as proxy-based method interception.
  • Know Aspect, Advice, Join Point, Pointcut, Proxy, Target.
  • Know JDK Dynamic Proxy vs CGLIB.
  • Know self-invocation problem.
  • Know why private/final methods are problematic for Spring AOP.
  • Compare Reflection vs AOP clearly.
