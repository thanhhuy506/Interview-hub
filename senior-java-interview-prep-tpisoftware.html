Core Java & Concurrency

1. What are the main differences between using synchronized blocks, ReentrantLock, and ConcurrentHashMap? In what specific scenario would you choose ReentrantLock over a standard synchronized block?

Ideal Answer:

Differences:

  • synchronized block: Implicit, built-in, block-structured mechanism. Automatically releases lock when exiting block. Lacks advanced features like fairness, timeouts, or non-blocking attempts.
  • ReentrantLock: Explicit lock implementation. Requires manual unlocking in a finally block. Supports advanced options like tryLock(), lock timeouts, and fairness policies.
  • ConcurrentHashMap: A thread-safe collection utilizing lock striping or CAS (Compare-And-Swap) operations rather than locking the entire resource, allowing high-throughput concurrent access.

Scenario for ReentrantLock:

Choose ReentrantLock when implementing non-blocking or timed lock attempts to prevent system degradation. For example, in a payment gateway, if a thread fails to lock a user wallet within 2 seconds, you can cleanly abort and return a "System Busy" error using lock.tryLock(2, TimeUnit.SECONDS).

Spring Boot & Microservices

2. Imagine Service A calls Service B via REST. Service B experiences high latency due to a DB bottleneck, causing Service A's thread pool to exhaust rapidly and crash the system. What pattern and configuration would you implement to prevent this cascading failure?

Ideal Answer:

1. Pattern:

Implement the Circuit Breaker Pattern. When Service B slows down, the circuit trips Open, rejecting subsequent requests immediately or routing them to a fallback method to preserve Service A's thread pool.

2. Configuration & Metrics (Resilience4j):

  • slidingWindowType: Set to COUNT_BASED or TIME_BASED to capture recent failures.
  • failureRateThreshold: Open the circuit if a percentage threshold (e.g., 50%) is reached.
  • slowCallRateThreshold & slowCallDurationThreshold: Mark calls taking longer than e.g., 2 seconds as slow, opening the circuit if too many slow calls occur.
  • waitDurationInOpenState: Duration the circuit stays Open before attempting recovery in Half-Open state.
  • Metrics to Monitor: resilience4j_circuitbreaker_state (State visualization) and resilience4j_circuitbreaker_buffered_calls (Throughput breakdown).
System Design & Database

3. A reporting query on a table with tens of millions of rows takes over 10 seconds. What systematic steps do you take to optimize it, and what advanced strategies do you use if standard B-Tree indexes fail?

Ideal Answer:

1. Diagnosis & Basic Optimization:

  • Run EXPLAIN ANALYZE to check for Sequential Scans or heavy sorting costs.
  • Verify indexing on filter predicates (WHERE) and join columns. Utilize Composite Indexes if needed.
  • Refactor the query to eliminate unnecessary subqueries or leading wildcards (e.g., LIKE '%abc').

2. Advanced Strategies for Large Data:

  • Database Partitioning: Logical breakdown by specific ranges (e.g., CREATED_DATE) to allow partition pruning.
  • Materialized Views: Cache heavy reporting metrics and refresh them asynchronously.
  • CQRS Pattern: Isolate the write operations from reads, synchronizing changes via a message broker (Kafka) to a dedicated query store like Elasticsearch.
Cloud, Security & DevOps

4. How do you safely handle secrets in a Kubernetes-deployed Spring Boot app, and what practices do you follow to minimize and secure production container images?

Ideal Answer:

1. Managing Sensitive Configurations:

  • Externalize secrets using HashiCorp Vault or Cloud Secret Managers (AWS/GCP).
  • Inject credentials dynamically at runtime using Kubernetes Secret objects managed by an External Secrets Operator.
  • Use library encryption like Jasypt if configurations must reside encrypted in the repository.

2. Optimizing Docker Containers:

  • Multi-stage Builds: Compile using a full JDK image, then copy only the artifact into a runtime-only base.
  • Distroless / Alpine Images: Minimize the attack surface by avoiding unnecessary shells and tools.
  • Run as Non-Root: Declare a dedicated user (USER appuser) to restrict host container permissions.
AI Integration & Leadership

5. How do you integrate AI coding assistants into your workflow safely, and how would you coach a Junior Developer who over-relies on AI and lacks debugging fundamentals?

Ideal Answer:

1. Safe AI Integration:

Leverage AI for boilerplate code, unit test generation, and regex matching. Ensure your enterprise license prohibits code reuse for model training. Never paste proprietary intellectual property, credentials, or actual DB structures into public prompts.

2. Coaching Junior Engineers:

  • Enforce structured code reviews requiring the Junior to explain the logic of the code line-by-line.
  • Run pair programming sessions with AI turned off, guiding them through breakpoint evaluation and log reading.
  • Establish strict boundaries ensuring comprehension always precedes deployment.
Behavioral & Crisis Management

6. A critical production memory leak occurs. The PO pressures for an immediate fix, and a Junior Developer panics thinking they caused it. As a Senior, how do you handle this crisis?

Ideal Answer:

  1. Triage & De-escalation: Defuse junior panic by emphasizing collective responsibility. Inform the Product Owner with an empirical timeline expectation rather than overpromising.
  2. Mitigation & Isolation: Trigger a prompt code rollback to the previous stable build, or provision temporary vertical scaling (JVM Memory allocation) to buy debugging time. Analyze heap dumps and APM logs afterwards.
  3. Prevention (Post-Mortem): Host a blameless post-mortem meeting to assess pipeline gaps and integrate preventative automated regression or load tests into the CI/CD pipeline.
