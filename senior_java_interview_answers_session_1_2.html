Real Senior Interview Style

Java Interview Answers That Sound Like a Senior Engineer

These answers are written as natural spoken answers in an interview. They focus on practical experience, internal working, production risk, trade-offs, and clear examples instead of dry definitions.

Answering style: Start with the main idea, explain how it works, connect it to a real project, then mention one important trade-off or production risk.
Round 1 — Coding

1. Given a sentence, fetch the longest word using Java Stream API.

“I would first split the sentence into words, convert the array into a stream, and then use max with a comparator based on word length. For a normal interview solution, I would write it like this.” 

String sentence = "Java Stream API is very powerful";

String longestWord = Arrays.stream(sentence.split("\s+"))
        .max(Comparator.comparingInt(String::length))
        .orElse("");

System.out.println(longestWord); // powerful

“The important point is that max returns an Optional, because the stream may be empty. In production code, I would also clarify how to handle punctuation, multiple words with the same length, and null input. For example, if the sentence contains commas or full stops, I may normalize the text first.”

Round 1 — Coding

2. Given an Employee class with name, age, salary, and department, fetch all employees whose salary is greater than 50,000 using Stream API.

“I would use filter because this is a simple condition-based selection. For salary, I prefer BigDecimal instead of double because money calculations need exact decimal values.” 

List<Employee> result = employees.stream()
        .filter(employee ->
                employee.getSalary().compareTo(BigDecimal.valueOf(50_000)) > 0)
        .toList();

“If the data already comes from a database, I would not load all employees into memory and then filter them with Stream API. I would push the condition to the database, for example with a repository query. Stream API is suitable when the data is already in memory and the collection size is reasonable.”

Round 1 — Coding

3. Write a JUnit test case for calculating prime numbers using JUnit 5 and Mockito.

“For a pure prime number calculator, Mockito is not necessary because there is no external dependency. I would test the logic directly with JUnit 5, and I would use a parameterized test because the same rule must be checked with many inputs.” 

class PrimeCalculator {

    boolean isPrime(int number) {
        if (number < 2) {
            return false;
        }

        for (int i = 2; i * i <= number; i++) {
            if (number % i == 0) {
                return false;
            }
        }

        return true;
    }
}

class PrimeCalculatorTest {

    private final PrimeCalculator calculator = new PrimeCalculator();

    @ParameterizedTest
    @ValueSource(ints = {2, 3, 5, 7, 11, 97})
    void shouldReturnTrueForPrimeNumbers(int number) {
        assertTrue(calculator.isPrime(number));
    }

    @ParameterizedTest
    @ValueSource(ints = {-1, 0, 1, 4, 9, 100})
    void shouldReturnFalseForNonPrimeNumbers(int number) {
        assertFalse(calculator.isPrime(number));
    }
}

“If the calculator service depended on a repository or another service, then I would use Mockito to isolate that dependency. I would not use Mockito just because the interviewer mentions it. I would explain that mocking is useful only when there is something meaningful to mock.”

Round 1 — Coding

4. Write a basic CRUD REST API.

“For a basic CRUD API in Spring Boot, I would separate the controller, service, repository, entity, and DTO responsibilities. The controller handles HTTP concerns, the service handles business logic, and the repository handles database access. In a real project, I would avoid exposing the JPA entity directly.” 

@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public ProductResponse create(@Valid @RequestBody CreateProductRequest request) {
        return productService.create(request);
    }

    @GetMapping("/{id}")
    public ProductResponse getById(@PathVariable Long id) {
        return productService.getById(id);
    }

    @PutMapping("/{id}")
    public ProductResponse update(
            @PathVariable Long id,
            @Valid @RequestBody UpdateProductRequest request) {
        return productService.update(id, request);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable Long id) {
        productService.delete(id);
    }
}
@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductRepository productRepository;

    @Transactional
    public ProductResponse create(CreateProductRequest request) {
        Product product = new Product();
        product.setName(request.name());
        product.setPrice(request.price());

        Product saved = productRepository.save(product);
        return ProductResponse.from(saved);
    }

    @Transactional(readOnly = true)
    public ProductResponse getById(Long id) {
        Product product = productRepository.findById(id)
                .orElseThrow(() ->
                        new ResourceNotFoundException("Product not found"));

        return ProductResponse.from(product);
    }

    @Transactional
    public ProductResponse update(Long id, UpdateProductRequest request) {
        Product product = productRepository.findById(id)
                .orElseThrow(() ->
                        new ResourceNotFoundException("Product not found"));

        product.setName(request.name());
        product.setPrice(request.price());

        return ProductResponse.from(product);
    }

    @Transactional
    public void delete(Long id) {
        if (!productRepository.existsById(id)) {
            throw new ResourceNotFoundException("Product not found");
        }

        productRepository.deleteById(id);
    }
}

“For production, I would also add validation, pagination, global exception handling, security, audit logging, API documentation, and integration tests. A basic CRUD API is simple, but the interview is usually checking whether I understand separation of concerns and production readiness.”

Round 1 — Technical

5. What is garbage collection and what are its types?

“Garbage Collection, or GC (thu gom rác), is the JVM mechanism that automatically reclaims heap memory from objects that are no longer reachable. The JVM starts from GC Roots such as active thread stacks, static references, and JNI references. If an object cannot be reached from any GC Root, it becomes eligible for collection.”

“In practice, I usually explain collectors by their goal. Serial GC is simple and suitable for small applications. Parallel GC focuses on throughput (thông lượng), so it is useful when total processing speed is more important than pause time. G1 GC is a balanced collector and is commonly used for server applications. ZGC and Shenandoah focus on very low pause time for large heaps.”

“I would not choose a collector only from a textbook. I would first look at the application requirement: acceptable pause time, heap size, allocation rate, CPU usage, and throughput target. In production, I monitor pause duration, old-generation usage, promotion rate, Full GC frequency, and allocation rate before deciding whether tuning is needed.”

Round 1 — Technical

6. Difference between ArrayList and LinkedList with real-time use cases.

“ArrayList uses a resizable array internally, while LinkedList uses a doubly linked list. ArrayList gives O(1) random access because it can directly calculate the index. LinkedList needs O(n) traversal to reach an element.”

“In real projects, I use ArrayList most of the time because it has better memory locality and lower object overhead. Even though LinkedList has O(1) insertion after reaching a node, finding that node is still O(n), so the practical benefit is often small. For queue behavior, I normally prefer ArrayDeque instead of LinkedList.”

“For example, API result lists, employee collections, and database query results are usually ArrayList use cases. LinkedList may be useful when I frequently add or remove elements at both ends and I already have the correct position, but this is less common in normal backend business code.”

Round 1 — Technical

7. What is polymorphism?

“Polymorphism (đa hình) means different implementations can be used through the same parent type or interface. The caller works with the abstraction and does not need to know the concrete implementation.” 

public interface PaymentProcessor {
    PaymentResult process(PaymentRequest request);
}

public class CardPaymentProcessor implements PaymentProcessor {
    public PaymentResult process(PaymentRequest request) {
        // Card payment logic
    }
}

public class WalletPaymentProcessor implements PaymentProcessor {
    public PaymentResult process(PaymentRequest request) {
        // Wallet payment logic
    }
}

“In a real payment system, this allows me to add a new provider without changing the main checkout flow. However, I do not create interfaces for every class. I use polymorphism when there is real behavior variation, not only to make the code look abstract.”

Round 1 — Technical

8. What are bean scopes in Spring Boot?

“The default Spring bean scope is singleton, which means one bean instance per ApplicationContext. Prototype creates a new instance each time the bean is requested. For web applications, request scope creates one bean per HTTP request, session scope creates one per HTTP session, and application scope creates one per ServletContext.”

“The most important production point is that singleton does not mean thread-safe. Most service beans are singleton, so I avoid mutable request-specific fields inside them. If a singleton service stores request data in an instance variable, concurrent requests can overwrite each other.”

“In normal Spring Boot backend services, I mainly use singleton. I use request or session scope only when there is a clear web-specific reason. Prototype is less common because lifecycle management becomes more complex.”

Round 1 — Technical

9. How would you implement global exception handling in Spring Boot?

“I would use @RestControllerAdvice with specific @ExceptionHandler methods. The goal is to keep controllers clean and return a consistent error response format.” 

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ApiError> handleNotFound(
            ResourceNotFoundException exception) {

        ApiError error = new ApiError(
                "RESOURCE_NOT_FOUND",
                exception.getMessage()
        );

        return ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(error);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiError> handleValidation(
            MethodArgumentNotValidException exception) {

        ApiError error = new ApiError(
                "VALIDATION_ERROR",
                "The request data is invalid"
        );

        return ResponseEntity
                .badRequest()
                .body(error);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiError> handleUnexpected(
            Exception exception) {

        // Log full internal error here

        ApiError error = new ApiError(
                "INTERNAL_ERROR",
                "An unexpected error occurred"
        );

        return ResponseEntity
                .status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(error);
    }
}

“I would log the internal exception with a trace ID, but I would not expose stack traces, SQL details, or sensitive data to the client. I also prefer stable business error codes because frontend and external clients should not depend only on text messages.”

Round 2 — Technical

10. Explain HashMap internal working.

“HashMap stores key-value pairs in an internal array of buckets. When I call put, HashMap first calculates the key hash, spreads the hash bits, and then calculates the bucket index. If the bucket is empty, it stores a new node. If the bucket already contains entries, HashMap compares the hash and then uses equals to find the same key.” 

int index = (table.length - 1) & hash;

“If the same key already exists, HashMap replaces the value. If different keys map to the same bucket, that is a hash collision (xung đột băm). Before Java 8, collisions were stored mainly as a linked list. From Java 8, a heavily collided bucket can become a red-black tree.”

“The default load factor is 0.75. When the number of entries passes the resize threshold, HashMap creates a larger table and redistributes entries. Average get and put complexity is close to O(1), but bad hash distribution can reduce performance. That is why a correct equals and hashCode contract is critical.”

Round 2 — Technical

11. Why did Java 8 switch from linked list to red-black tree in case of hash collision?

“Java 8 did not completely replace linked lists. It keeps linked lists for small collision groups because they use less memory and are simple. When a bucket becomes too large, HashMap can convert it into a red-black tree.”

“The reason is performance. Searching a linked list is O(n), while searching a balanced red-black tree is O(log n). This protects the map from very poor performance when many keys have the same hash value. It also helps reduce the impact of hash collision attacks.”

“Tree nodes use more memory, so Java does not treeify immediately. The bucket normally needs to reach the treeify threshold, and the table also needs enough capacity. This is a trade-off between memory cost and worst-case lookup performance.”

Round 2 — Technical

12. What is circular dependency and how would you fix it?

“A circular dependency happens when Bean A depends on Bean B and Bean B also depends on Bean A. For example, OrderService calls PaymentService, and PaymentService also directly calls OrderService.”

“I treat this mainly as a design problem, not only a Spring configuration problem. It usually means the responsibilities are not separated clearly.”

“My first solution is to redesign the dependency direction. I may extract shared logic into a third service, move orchestration into an application service or facade, or use domain events if the communication does not need to be synchronous. I can use @Lazy as a temporary workaround, but I would not consider it the final design because it hides the real coupling problem.”

Round 2 — Technical

13. What is @Transactional?

“@Transactional tells Spring to execute a method inside a database transaction. Spring usually applies it through a proxy. The proxy starts the transaction before the method, commits when the method completes successfully, and rolls back when a matching exception occurs.”

“By default, Spring rolls back for unchecked exceptions, but not automatically for every checked exception. Another important point is self-invocation. If one method inside the same class calls another @Transactional method, the call may bypass the proxy, so the transaction rule may not be applied.”

“In production, I keep transactions short and place them around one business unit of work. I avoid calling slow external APIs while a database transaction is open because that can hold locks and database connections for too long. I also use readOnly = true for read operations where appropriate, but I understand that it is mainly a hint and its effect depends on the database and JPA provider.”

Round 2 — Technical

14. How would you secure your REST API?

“I would secure a REST API in layers. First, all communication must use HTTPS. For authentication, I normally use OAuth 2.0 or OpenID Connect with JWT access tokens. After authentication, I apply authorization based on roles, scopes, and resource ownership.”

“For example, an ADMIN role may access management APIs, while a normal user can only access resources that belong to that user. I also validate all input, use short token lifetimes, rotate secrets, protect sensitive configuration, add rate limiting, and record security audit events.” 

@Bean
SecurityFilterChain security(HttpSecurity http) throws Exception {
    return http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                    .requestMatchers("/actuator/health").permitAll()
                    .requestMatchers("/api/admin/**").hasRole("ADMIN")
                    .anyRequest().authenticated())
            .oauth2ResourceServer(oauth -> oauth.jwt())
            .build();
}

“I also separate authentication from authorization. A valid token proves identity, but it does not automatically mean the user can access every resource.”

Round 2 — Technical

15. What is @Value annotation?

“@Value injects configuration values into a Spring bean. It is useful for a small number of simple properties.” 

@Value("${payment.timeout:3000}")
private int timeout;

“For a group of related properties, I prefer @ConfigurationProperties because it is type-safe, easier to validate, and easier to test. For example, payment base URL, timeout, retry count, and API key settings should normally belong to one configuration class instead of many scattered @Value fields.”

Round 2 — Technical

16. What does @EmbeddedId do?

“@EmbeddedId maps a composite primary key, meaning one primary key is made from multiple columns. The key is represented as one embeddable Java object.” 

@Embeddable
public class OrderItemId implements Serializable {

    private Long orderId;
    private Long productId;

    // equals and hashCode
}

@Entity
public class OrderItem {

    @EmbeddedId
    private OrderItemId id;
}

“The key class should implement Serializable and correctly implement equals and hashCode. In new systems, I often prefer a surrogate key when the natural composite key is large or may change, but composite keys are still useful when the business identity is naturally made from multiple fields.”

Round 2 — Technical

17. Explain Facade design pattern.

“Facade provides one simple interface over several complex subsystems. For example, a checkout process may need inventory, payment, order creation, and notification. Instead of letting the controller call all of them directly, I can expose one CheckoutFacade.” 

@Service
@RequiredArgsConstructor
public class CheckoutFacade {

    private final InventoryService inventoryService;
    private final PaymentService paymentService;
    private final OrderService orderService;
    private final NotificationService notificationService;

    public CheckoutResult checkout(CheckoutRequest request) {
        inventoryService.reserve(request);
        paymentService.charge(request);
        Order order = orderService.create(request);
        notificationService.sendConfirmation(order);

        return CheckoutResult.from(order);
    }
}

“The benefit is a simpler client and one clear orchestration point. The risk is that the facade can become a god class if it contains too much business logic. I keep orchestration in the facade, while detailed rules remain in domain services or specialized components.”

Round 2 — Technical

18. What is circuit breaker pattern?

“A circuit breaker protects the system from repeatedly calling a failing remote service. It usually has three states: closed, open, and half-open.”

“In the closed state, calls are allowed. When failures pass a configured threshold, the circuit opens and new calls fail fast. After a wait period, it moves to half-open and allows a small number of test requests. If they succeed, it closes again. If they fail, it opens again.”

“I normally combine circuit breaker with timeout, retry, and bulkhead, but I configure them carefully. For example, aggressive retry can make an outage worse by multiplying traffic. The fallback must also make business sense. Returning fake success for a failed payment call would be dangerous.”

Round 2 — Technical

19. How would you achieve centralized logging in microservices?

“In microservices, I would make every service write structured JSON logs and send them to a central logging platform. A common flow is service logs to Fluent Bit or Filebeat, then to Elasticsearch, OpenSearch, or Loki, and finally Kibana or Grafana for search and dashboards.”

“The most important part is correlation. Every request should include a trace ID, span ID, request ID, service name, environment, and sometimes a business correlation ID such as order ID or payment ID. This allows me to follow one request across many services.”

“I also define logging standards: common field names, error codes, log levels, retention rules, and masking rules. I never log passwords, tokens, card details, or sensitive personal data. For debugging distributed flows, logs should be connected with tracing and metrics, not used alone.”

Round 2 — Technical

20. How do you handle distributed transactions in microservices?

“In microservices, I avoid trying to use one database transaction across many services. Each service owns its own local transaction, and the overall business flow is coordinated with reliable events.”

“My common design is Saga plus Transactional Outbox. The service updates its database and writes an outbox event in the same local transaction. A separate publisher sends that event to Kafka or another broker. Consumers process the event idempotently, meaning repeated delivery does not create repeated business effects.”

“I also add retry with backoff, dead-letter handling, reconciliation jobs, and monitoring. I avoid two-phase commit in most microservice systems because it reduces availability and adds strong coordination. The correct solution depends on business consistency requirements. For payments, I may also need manual reconciliation because not every external action can be automatically rolled back.”

Round 2 — Technical

21. What is Saga pattern?

“A Saga is a sequence of local transactions across services. Each service completes its own transaction and publishes an event or returns a result. If a later step fails, compensating actions are executed for the earlier completed steps.”

“For example, an order flow may create the order, reserve inventory, charge payment, and then confirm the order. If payment fails, the system may release the inventory and cancel the order.”

“There are two common styles. In choreography, services react to events without one central controller. In orchestration, one coordinator tells each service what step to execute. Choreography is simple for small flows, but it can become hard to understand. Orchestration gives clearer control for complex workflows, but the orchestrator must not become too large.”

“A compensation is not a technical database rollback. It is a new business action. For example, refunding a payment is a separate operation and may itself fail.”

Round 2 — Technical

22. Difference between Kafka and queue.

“Kafka is mainly a distributed append-only log, while a traditional queue is mainly designed for work distribution. In a normal queue, a message is often removed after it is acknowledged. In Kafka, messages remain for a retention period, and consumers track their position using offsets.”

“This means Kafka supports replay very well. Different consumer groups can read the same event independently. Kafka is a strong choice for event streaming, audit events, data pipelines, and high-throughput integration.”

“A traditional queue is often simpler for command-style work, such as sending an email or processing one background job. I choose based on the communication model, ordering requirement, replay need, throughput, and operational complexity. Kafka can behave like a queue inside one consumer group, but its core model is still a log.”

Round 2 — Technical

23. What is query planning?

“Query planning is the process where the database decides how to execute SQL. The database parses the query, checks possible access paths, estimates the cost, and chooses a plan.”

“The planner decides whether to use an index scan or sequential scan, which table to join first, which join algorithm to use, and whether sorting or aggregation is needed.” 

EXPLAIN ANALYZE
SELECT *
FROM orders
WHERE customer_id = 100
ORDER BY created_at DESC;

“When I analyze a slow query, I compare estimated rows with actual rows. A large difference may mean stale statistics, data skew, or a poor predicate. I also check scanned rows, join type, sort operations, filter conditions, and execution time. I do not add an index before understanding the plan.”

Round 2 — Technical

24. Explain SOLID principles.

“SOLID is a group of object-oriented design principles that helps code become easier to change, test, and maintain. Single Responsibility means a class should have one main reason to change. Open/Closed means stable code should be extendable without repeated modification. Liskov Substitution means a subtype must safely replace its parent type. Interface Segregation means clients should not depend on methods they do not use. Dependency Inversion means high-level business logic should depend on abstractions, not concrete infrastructure.”

“In a payment system, I may use PaymentGateway as an abstraction. The business service depends on that interface, while StripeGateway and BankGateway are implementations. This supports OCP and DIP.”

“I do not apply SOLID mechanically. If I create an interface for every class and split every method into a separate service, the code becomes harder to understand. I use these principles around real change points and complex business rules.”

Round 2 — Technical

25. Explain ACID properties.

“ACID describes important transaction guarantees. Atomicity means all operations in the transaction succeed together or all are rolled back. Consistency means the transaction moves data from one valid state to another valid state. Isolation means concurrent transactions should not incorrectly interfere with each other. Durability means committed data survives a crash.”

“For example, in a bank transfer, subtracting money from one account and adding it to another should be atomic. If one step fails, both changes should roll back.”

“Isolation is the most complex part in practice. Different isolation levels balance consistency and concurrency. Databases implement isolation through locking, MVCC, or both. I choose the level based on business risk, not always the highest possible level.”

Round 2 — Technical

26. Implement lazy initialization for Singleton.

“For lazy and thread-safe Singleton initialization, I prefer the initialization-on-demand holder pattern. The JVM guarantees that the inner class is initialized safely when it is first used.” 

public final class AppConfig {

    private AppConfig() {
    }

    private static class Holder {
        private static final AppConfig INSTANCE = new AppConfig();
    }

    public static AppConfig getInstance() {
        return Holder.INSTANCE;
    }
}

“An enum singleton is also safe and simple. However, in Spring applications I normally let the container manage singleton beans instead of implementing the pattern manually. I also remember that singleton scope does not automatically make mutable state thread-safe.”

Round 2 — Technical

27. Fail-fast vs fail-safe iterators.

“A fail-fast iterator detects structural modification during iteration and usually throws ConcurrentModificationException. ArrayList and HashMap iterators are common examples.”

“The term fail-safe is commonly used in interviews, but Java documentation often uses terms such as weakly consistent or snapshot-based. For example, ConcurrentHashMap iterators are weakly consistent, while CopyOnWriteArrayList iterates over a snapshot.”

“The important point is that these iterators do not provide the same behavior. A snapshot iterator may not see new changes, while a weakly consistent iterator may see some changes. I choose the collection based on read/write frequency and consistency needs.”

34. How does HashMap work internally?

“HashMap uses an internal bucket array. For put, it calculates a hash, finds the bucket index, and then either adds a new node, replaces an existing value, or handles a collision. For get, it calculates the same bucket index and then compares the stored hash and key equality.”

35. Find the smallest positive missing integer.

“I would first clarify the expected complexity. The common optimal solution is O(n) time and O(1) extra space. The idea is to place each value x at index x - 1 when x is inside the range from 1 to n.” 

public int firstMissingPositive(int[] nums) {
    int n = nums.length;

    for (int i = 0; i < n; i++) {
        while (nums[i] > 0
                && nums[i] <= n
                && nums[nums[i] - 1] != nums[i]) {

            int correctIndex = nums[i] - 1;

            int temp = nums[i];
            nums[i] = nums[correctIndex];
            nums[correctIndex] = temp;
        }
    }

    for (int i = 0; i < n; i++) {
        if (nums[i] != i + 1) {
            return i + 1;
        }
    }

    return n + 1;
}

“After rearranging, the first index where the value is not index plus one gives the smallest missing positive number.”

38. How does garbage collection work in heap memory?

“Most JVM collectors use the generational idea because most objects die young. New objects are usually allocated in Eden. When Eden fills, a young-generation collection checks which objects are still alive. Surviving objects may move between survivor spaces and later be promoted to the old generation.”

“The collector finds live objects from GC Roots. Depending on the collector, it may use marking, copying, sweeping, and compaction. Compaction is useful because it reduces memory fragmentation.”

“In production, a GC issue is not only about total heap size. I also check allocation rate, object lifetime, promotion rate, pause time, and whether the old generation keeps growing. A memory leak in Java usually means objects are still reachable even though the application no longer needs them.”

80. Explain Kubernetes Deployment, Service, Ingress, and ConfigMap.

“Deployment manages application pods, replica count, rolling updates, and rollback. Service gives pods a stable network endpoint and load balances traffic to them. Ingress routes external HTTP or HTTPS traffic to services. ConfigMap stores non-sensitive configuration outside the container image.

For secrets such as passwords or API keys, I use Secret or an external secret manager instead of ConfigMap.

In production, I also define readiness and liveness probes, resource requests and limits, autoscaling, disruption budget, and rolling update settings.”

Session 2 — Round 2

81. Mockito @Mock vs @Spy.

“@Mock creates a fully mocked object. Its methods return default values unless they are stubbed. @Spy wraps a real object, so real methods run unless I stub them.

I use @Mock for external dependencies. I use @Spy carefully when I need partial behavior from a legacy or difficult object.

Too much use of @Spy can be a design smell because the test becomes coupled to implementation details.”

Session 2 — Round 2

82. Explain Kafka topic, partition, and delivery guarantee.

“A topic is a named stream of records. A partition is an ordered append-only log inside the topic. Partitions allow parallelism and scalability.

Ordering is guaranteed only inside one partition. Messages with the same key normally go to the same partition.

For delivery, I commonly design for at-least-once. Producers use acks=all, retries, and idempotence. Brokers use replication and min.insync.replicas. Consumers commit offsets only after successful processing, and the application must handle duplicates idempotently.”

83. How do you optimize SQL query performance?

“I start with EXPLAIN ANALYZE and real measurements. I check scanned rows, estimated versus actual rows, index usage, join order, sort operations, and filter conditions.

I also review N+1 queries, unnecessary columns, pagination, database statistics, locks, I/O, and connection pool usage.

I do not add indexes blindly. Indexes improve reads but increase storage and write cost. Composite index order must match the real query pattern.”

84. What is an execution plan?

“An execution plan shows how the database will execute a SQL query. It includes scan type, join type, join order, estimated cost, row count, sorting, and aggregation steps.

With EXPLAIN ANALYZE, I can compare estimates with actual execution. Large differences may show stale statistics, data skew, or a weak predicate.

I use the plan to understand the real bottleneck instead of guessing.”

92. What is CQRS?

“CQRS separates the write model from the read model. Commands change state, while queries read data.

This can be useful when read and write workloads have very different models or scaling needs.

The trade-off is more complexity, duplicated models, and eventual consistency. I do not use CQRS for simple CRUD systems. I use it only when the domain or performance requirements justify the cost.”

93. How do you achieve zero-downtime deployment?

“I use rolling deployment or blue-green deployment with multiple healthy instances behind a load balancer.

The new version must pass readiness checks before receiving traffic. The application should shut down gracefully and finish active requests.

Database changes must be backward-compatible. I normally use expand-and-contract migration: add new schema first, deploy compatible code, migrate data, and remove old schema later.”

95. How do you test a catch block?

“I trigger the dependency exception and verify the observable behavior of the catch path.

For example, I mock the provider to throw an exception, then verify that the service throws the correct business exception, records an audit event, or returns the expected fallback.

I do not test a catch block only for coverage. I test the behavior the user or caller can observe.”

96. What is idempotency in REST API?

“Idempotency means repeating the same request produces the same business effect.

For payments or order creation, I use an idempotency key. The server stores the key and result, and duplicate requests return the same result instead of processing again.

I also use a database unique constraint because duplicate requests may arrive at the same time. The check and save must be atomic.”

97. What is a composite primary key and how do you implement it in JPA?

“A composite primary key is made from multiple columns. In JPA, I can implement it with @EmbeddedId or @IdClass.

With @EmbeddedId, the key is one embeddable object. The key class must implement Serializable and correctly implement equals and hashCode.

For new systems, I often prefer a surrogate key when the natural key is large or unstable, but composite keys are still valid when they represent real business identity.”

98. How do you configure multiple database connections in Spring Boot?

“I define a separate DataSource, EntityManagerFactory, TransactionManager, and repository package for each database.

I also make the transaction manager explicit where needed.

The main risk is assuming one transaction covers both databases. Normally, each transaction manager controls only one database, so cross-database consistency needs a separate design.”

99. SQL task: find customers who placed orders for multiple different items.

“I would group by customer and count distinct item IDs. Then I use HAVING because the condition applies after grouping.”

SELECT customer_id
FROM orders
GROUP BY customer_id
HAVING COUNT(DISTINCT item_id) > 1;

“If order and item are stored in separate tables, I would join order_items first and then group by customer.”

101. Java coding task: total salary by employee in descending order.

“If there can be multiple salary records per employee, I would group by employee name, sum salary, and then sort by total salary in descending order.”

LinkedHashMap<String, BigDecimal> result = records.stream()
        .collect(Collectors.groupingBy(
                SalaryRecord::employeeName,
                Collectors.reducing(
                        BigDecimal.ZERO,
                        SalaryRecord::salary,
                        BigDecimal::add
                )
        ))
        .entrySet()
        .stream()
        .sorted(Map.Entry.<String, BigDecimal>comparingByValue().reversed())
        .collect(Collectors.toMap(
                Map.Entry::getKey,
                Map.Entry::getValue,
                (a, b) -> a,
                LinkedHashMap::new
        ));

“I use LinkedHashMap so the sorted order is preserved.”
