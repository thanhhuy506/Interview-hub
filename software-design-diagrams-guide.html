Software Design Diagrams

A practical guide to the diagrams that software teams use to explain structure, behavior, data, deployment, security, and user experience.

How to read this page

The English is kept around IELTS 5.5–6.5 level. Important technical words include a short Vietnamese meaning.

StructureWhat parts exist?
BehaviorWhat happens next?
DataHow is information stored or moved?
DeploymentWhere does the system run?
One key idea

A diagram is not “better” because it looks more complex. A good diagram answers one clear question for one clear audience.

Architecture = structure. Flow = process. Sequence = who talks to whom, and in what order.

The examples below use one e-commerce system, so you can see how different diagrams explain different views of the same product.

Architecture Diagram

Architecture (kiến trúc) shows the major building blocks.

Very common

Use it when: you need to explain the system structure before going into detailed logic.

Example: “Our checkout request goes from the Web App to the API Gateway, then to Order, Payment, and Inventory services.”

C4 Model

C4 Model (mô hình 4 cấp kiến trúc) gives several levels of detail.

Best practice

Use it when: one architecture picture is either too simple or too detailed. C4 lets you zoom in step by step.

Sequence Diagram

Sequence (trình tự tương tác) shows messages in time order.

Very common

Use it when: debugging API calls, designing a new feature, or checking the order of service calls.

Flowchart / Activity Diagram

Flow (luồng xử lý) shows steps, decisions, and branches.

Very common

Flowchart: simple process or logic. Activity Diagram: better when the workflow has parallel work, joins, or more formal UML rules.

State Diagram

State (trạng thái) shows how one object changes over time.

Great for rules

Use it when: an object has strict lifecycle rules. Good examples are Order, Payment, Ticket, Document, or Account.

ERD — Entity Relationship Diagram

Entity (thực thể) and relationship (quan hệ) explain database structure.

Backend staple

Use it when: designing or discussing relational data. ERD focuses on entities, keys, and relationships.

Deployment Diagram

Deployment (triển khai) shows where software runs.

DevOps

Use it when: discussing servers, containers, clusters, cloud services, environments, and runtime connections.

Event Flow Diagram

Event-driven (hướng sự kiện) systems often need a clear event map.

Microservices

Use it when: services communicate through events, queues, topics, or a message broker.

User Flow

User flow (luồng người dùng) shows the path a user follows in the product.

Product / UX

Use it when: discussing screens, user tasks, navigation, onboarding, checkout, or product experience.

3. Full practical catalog

These are common names you may meet in software, product, data, security, or DevOps work.

System Context Diagram

Shows the system, its users, and external systems. Sơ đồ bối cảnh hệ thống.

System Architecture Diagram

Shows the major parts of a software system. Sơ đồ kiến trúc hệ thống.

Solution Architecture

Shows a full solution across applications, platforms, and external services. Kiến trúc giải pháp.

C4 Context / Container / Component

Shows architecture from high level to detailed level. Các cấp độ kiến trúc C4.

Component Diagram

Shows modules or components and their dependencies. Sơ đồ thành phần.

Package / Module Diagram

Shows how the codebase is divided into packages or modules. Sơ đồ package / module.

Dependency Graph

Shows what depends on what. Đồ thị phụ thuộc.

Sequence Diagram

Shows messages between actors or services in time order. Sơ đồ tuần tự.

Activity Diagram

Shows a workflow with branches, joins, and parallel actions. Sơ đồ hoạt động.

Flowchart

Shows steps and decisions in a simple process. Lưu đồ.

Swimlane Diagram

Shows a process and who is responsible for each step. Sơ đồ làn trách nhiệm.

BPMN

A formal notation for business processes. Ký pháp mô hình hóa quy trình nghiệp vụ.

State Machine Diagram

Shows object states and allowed transitions. Sơ đồ máy trạng thái.

Timing Diagram

Shows how states or signals change over exact time. Sơ đồ thời gian.

Communication Diagram

Shows object communication with focus on relationships. Sơ đồ giao tiếp.

Use Case Diagram

Shows what actions each actor can perform. Sơ đồ ca sử dụng.

ERD

Shows entities, keys, and database relationships. Sơ đồ quan hệ thực thể.

Database Schema

Shows real tables, columns, types, keys, and constraints. Lược đồ cơ sở dữ liệu.

Conceptual Data Model

High-level business view of data entities. Mô hình dữ liệu khái niệm.

Logical Data Model

Detailed data structure without physical database details. Mô hình dữ liệu logic.

Physical Data Model

Implementation-level data model with real database details. Mô hình dữ liệu vật lý.

Data Flow Diagram (DFD)

Shows where data comes from, how it is processed, and where it goes. Sơ đồ luồng dữ liệu.

Data Lineage Diagram

Shows the origin and movement of data across systems. Sơ đồ nguồn gốc và hành trình dữ liệu.

ETL / Data Pipeline Diagram

Shows the steps used to collect, transform, and store data. Sơ đồ pipeline dữ liệu.

API Interaction Diagram

Shows how one application calls another through APIs. Sơ đồ tương tác API.

Integration Diagram

Shows connections between systems, vendors, and platforms. Sơ đồ tích hợp.

Event Flow Diagram

Shows which events are published and consumed. Sơ đồ luồng sự kiện.

Message Flow Diagram

Shows messages moving through queues, topics, or services. Sơ đồ luồng thông điệp.

Deployment Diagram

Shows where software components run. Sơ đồ triển khai.

Infrastructure Diagram

Shows servers, cloud resources, storage, and networking. Sơ đồ hạ tầng.

Cloud Architecture Diagram

Shows cloud services such as AWS, Azure, or GCP resources. Sơ đồ kiến trúc cloud.

Network Diagram

Shows networks, subnets, firewalls, routes, and connections. Sơ đồ mạng.

Authentication Flow

Shows how the system proves a user’s identity. Luồng xác thực danh tính.

Authorization Flow

Shows how the system checks what a user is allowed to do. Luồng phân quyền.

Trust Boundary Diagram

Shows trusted and untrusted areas of a system. Sơ đồ ranh giới tin cậy.

Threat Model Diagram

Shows possible attack paths and security risks. Sơ đồ mô hình mối đe dọa.

Class Diagram

Shows classes, properties, methods, and relationships. Sơ đồ lớp.

Object Diagram

Shows example object instances at one point in time. Sơ đồ đối tượng.

User Flow

Shows the path a user takes through a product. Luồng người dùng.

Wireflow / Screen Flow

Combines screen ideas with navigation flow. Luồng màn hình.

Sitemap

Shows the page or information hierarchy of a website or product. Sơ đồ cấu trúc trang.

User Journey Map

Shows user goals, actions, pain points, and experience over time. Bản đồ hành trình người dùng.

CI/CD Pipeline Diagram

Shows build, test, scan, and deployment steps. Sơ đồ pipeline CI/CD.

Git / Branching Flow

Shows branch and merge strategy. Luồng nhánh Git.

Observability Architecture

Shows logs, metrics, traces, alerts, and monitoring tools. Kiến trúc quan sát hệ thống.

Incident Response Flow

Shows what the team does after an alert or production issue. Luồng xử lý sự cố.

Decision Tree

Shows decisions and possible results as branches. Cây quyết định.

4. How to choose the right diagram

Start with the question you want to answer. Do not start with the drawing tool.

“What parts does the system have?”
→ Architecture / C4

Use for system structure and boundaries.

“Who talks to whom, and when?”
→ Sequence Diagram

Use for API calls and service interactions.

“What happens next?”
→ Flowchart / Activity

Use for logic and process steps.

“How does the status change?”
→ State Diagram

Use for lifecycle rules.

“How is data structured?”
→ ERD / Schema

Use for database and entity relationships.

“Where does data move?”
→ DFD / Data Lineage

Use for data processing and data movement.

“Where does the software run?”
→ Deployment / Infrastructure

Use for runtime, servers, cloud, and networks.

“Which events move between services?”
→ Event Flow

Use for queues, topics, and event-driven systems.

“How does the user move through the product?”
→ User Flow

Use for UX, screens, and product tasks.

Important: architecture style (phong cách kiến trúc) is not the same as a diagram type. Microservices, Clean Architecture, Hexagonal Architecture, Layered Architecture, and Event-Driven Architecture are design approaches. You can use several diagram types to explain them.

5. Technical vocabulary

Useful words that appear often in software design discussions.

Architecture — overall system structure. Kiến trúc.
Component — a main part of a system. Thành phần.
Module — a separated part of code or functionality. Mô-đun.
Dependency — when one part needs another part. Sự phụ thuộc.
Interaction — communication between parts. Sự tương tác.
Sequence — order of actions or messages. Trình tự.
Workflow — a series of work steps. Quy trình công việc.
Branch — one possible path after a decision. Nhánh xử lý.
State — current condition or status of an object. Trạng thái.
Transition — movement from one state to another. Chuyển trạng thái.
Entity — a main data object, such as User or Order. Thực thể.
Relationship — connection between data entities. Mối quan hệ.
Schema — formal structure of a database. Lược đồ.
Data lineage — history of where data comes from and where it goes. Dòng nguồn gốc dữ liệu.
Deployment — putting software into an environment where it can run. Triển khai.
Infrastructure — servers, networks, cloud resources, and related technology. Hạ tầng.
Runtime — the environment while software is running. Môi trường chạy.
Event — a fact that something happened, such as OrderCreated. Sự kiện.
Publish / Consume — send an event / receive and process an event. Phát / nhận sự kiện.
Message broker — software that moves messages between services. Bộ trung gian thông điệp.
Authentication — proving who a user is. Xác thực.
Authorization — checking what a user can do. Phân quyền.
Trust boundary — a line between areas with different security trust levels. Ranh giới tin cậy.
Threat model — a model of possible security risks and attacks. Mô hình mối đe dọa.

Recommended learning order

If you are a software engineer, learn these first:

1 Architecture → 2 C4 → 3 Sequence → 4 Flowchart / Activity → 5 State → 6 ERD → 7 Deployment → 8 Event Flow → 9 Class Diagram.

If you understand these nine well, you can explain most software designs clearly in technical discussions, code reviews, design reviews, and interviews.
