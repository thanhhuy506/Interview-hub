A bilingual EN/VN learning website for senior backend interviews and real project implementation. Focus: internal architecture, request flow, JWT validation, stateless APIs, method security, CSRF/CORS, token lifecycle, and advanced pitfalls.

1. Big Picture

Spring Security is a security framework for authentication, authorization, and protection against common attacks. In Spring Boot applications, it is usually configured through one or more SecurityFilterChain beans.

Authentication

Answers: who are you? Example: username/password, session login, JWT bearer token, OAuth2 login, API key.

Authorization

Answers: what are you allowed to do? Example: role, authority, scope, ownership, policy rule.

Exploit Protection

Protects against common web attacks such as CSRF, clickjacking, insecure headers, and session fixation.

HTTP Request ↓ Servlet Container ↓ DelegatingFilterProxy ↓ FilterChainProxy ↓ Matched SecurityFilterChain ↓ Security Filters ↓ Authentication + Authorization ↓ Controller / REST API
Senior mental model: Spring Security is not only an annotation library. It is mainly a servlet filter-based security pipeline that authenticates the request, stores the result in a security context, then performs authorization checks before the request reaches business code.

Authentication vs Authorization

Concept Question Spring Security Object / Feature
Authentication Who is the user/client? Authentication, AuthenticationManager, AuthenticationProvider, SecurityContext
Authorization Is this authenticated user allowed? AuthorizationFilter, AuthorizationManager, @PreAuthorize, roles/scopes/authorities

2. Spring Security Architecture

Core Servlet Components

Component Role Senior Notes
DelegatingFilterProxy Servlet container filter that delegates to a Spring bean. Bridge between servlet container and Spring-managed security filters.
FilterChainProxy Main Spring Security filter that delegates to a list of security filters through SecurityFilterChain. Good starting point for debugging Spring Security request flow.
SecurityFilterChain Defines which security filters apply to a request. Multiple chains can exist; first matching chain wins.
SecurityContextHolder Stores the current SecurityContext. Usually ThreadLocal-based in servlet apps.
SecurityContext Contains the current Authentication. If Authentication exists and is authenticated, user is considered authenticated.
Authentication Represents current principal, credentials, and authorities. Before authentication it can hold credentials; after authentication it represents the authenticated principal.

Basic SecurityFilterChain Configuration

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())
            .cors(Customizer.withDefaults())
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/products/**").hasAuthority("SCOPE_product:read")
                .requestMatchers(HttpMethod.POST, "/api/products/**").hasAuthority("SCOPE_product:write")
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth2 ->
                oauth2.jwt(Customizer.withDefaults())
            )
            .build();
    }
}

Multiple SecurityFilterChain

In advanced systems, different URL groups may need different authentication mechanisms. For example, API endpoints use JWT while admin pages use form login. 

@Bean
@Order(1)
SecurityFilterChain apiSecurity(HttpSecurity http) throws Exception {
    return http
        .securityMatcher("/api/**")
        .csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()))
        .build();
}

@Bean
@Order(2)
SecurityFilterChain adminSecurity(HttpSecurity http) throws Exception {
    return http
        .securityMatcher("/admin/**")
        .authorizeHttpRequests(auth -> auth.anyRequest().hasRole("ADMIN"))
        .formLogin(Customizer.withDefaults())
        .build();
}
Important: If multiple chains match, only the first matching SecurityFilterChain is used. Order and matchers are extremely important.

3. Authentication Flow

High-Level Flow

Unauthenticated Request ↓ Authentication Filter extracts credentials/token ↓ Creates Authentication object ↓ AuthenticationManager.authenticate(authentication) ↓ ProviderManager chooses AuthenticationProvider ↓ AuthenticationProvider verifies credentials/token ↓ Returns authenticated Authentication ↓ SecurityContextHolder stores Authentication ↓ Authorization checks run ↓ Controller executes

AuthenticationManager, ProviderManager, AuthenticationProvider

Component Meaning Example
AuthenticationManager Strategy interface for authentication. Usually implemented by ProviderManager.
ProviderManager Delegates authentication to a list of AuthenticationProvider. Can try DAO provider, JWT provider, LDAP provider, custom provider.
AuthenticationProvider Performs a specific authentication type. DaoAuthenticationProvider, JwtAuthenticationProvider, custom API key provider.

Username/Password Authentication Flow

POST /login username/password ↓ UsernamePasswordAuthenticationFilter ↓ UsernamePasswordAuthenticationToken ↓ AuthenticationManager / ProviderManager ↓ DaoAuthenticationProvider ↓ UserDetailsService.loadUserByUsername() ↓ PasswordEncoder.matches(rawPassword, encodedPassword) ↓ Authenticated principal + authorities ↓ SecurityContext stored in session by default

Important Objects

Object Purpose
UserDetailsService Loads user data from database, LDAP, external system, etc.
UserDetails Represents username, password, enabled/locked/expired status, and authorities.
PasswordEncoder Verifies raw password against stored hash.
GrantedAuthority Represents permission, role, or scope. Example: ROLE_ADMIN, SCOPE_order:read.

4. Authentication Mechanisms

Mechanism How it works Best For Production Notes
Form Login + Session User logs in with username/password; server stores authentication in HTTP session. Server-rendered web apps, admin portals. Keep CSRF enabled. Use secure session cookie settings.
HTTP Basic Client sends username/password in Authorization: Basic header. Internal tools, simple machine-to-machine only over TLS. Avoid for public user-facing apps. No logout concept.
JWT Bearer Token Client sends Authorization: Bearer <token>; API validates token signature and claims. Stateless REST APIs, microservices. Validate issuer, audience, expiration, signature, algorithm, and map scopes/roles carefully.
OAuth2 Login User logs in via external identity provider such as Google, Okta, Keycloak. Web apps needing federated login. Usually uses Authorization Code flow. For OIDC, ID token identifies the user.
OAuth2 Resource Server API validates access tokens issued by an Authorization Server. Modern REST APIs. The API is not the login server; it validates bearer tokens.
API Key Client sends a static or rotating key in header. Service integrations, webhooks. Use limited permissions, rotation, rate limits, hashing at rest.
MFA / TOTP Second factor after password, often time-based OTP. Admin users, sensitive systems. Store backup codes safely, bind MFA to risk-based policies.
Interview answer: For modern microservices, the application is often a Resource Server. It should not usually implement its own login/password/token issuing flow unless it is intentionally acting as an Authorization Server.

5. JWT Deep Dive

What is JWT?

JWT — JSON Web Token — is a compact token format commonly used as a bearer access token. It contains claims and is cryptographically signed.

JWT = Base64Url(Header) + "." + Base64Url(Payload) + "." + Signature Header: { "alg": "RS256", "typ": "JWT", "kid": "key-id-1" } Payload / Claims: { "iss": "https://auth.example.com", "sub": "user-123", "aud": "order-api", "exp": 1710000000, "iat": 1709996400, "scope": "order:read order:write", "roles": ["ADMIN"] }

Important JWT Claims

Claim Meaning Validation Note
iss Issuer Must match trusted Authorization Server.
sub Subject / user id Do not assume it is email unless issuer defines it that way.
aud Audience Should match your API/service identifier.
exp Expiration time Reject expired token.
nbf Not before Reject token used too early.
iat Issued at Useful for age and debugging.
jti JWT ID Useful for revocation/blacklist or audit.
scope / scp OAuth2 permissions Usually mapped to Spring authorities like SCOPE_order:read.

JWT Validation Steps

  1. Extract bearer token from Authorization header.
  2. Decode JWT header and find algorithm/key id.
  3. Load public key from JWKS or configured key.
  4. Verify signature.
  5. Validate issuer.
  6. Validate audience.
  7. Validate expiration and not-before time.
  8. Map claims/scopes/roles to GrantedAuthority.
  9. Create authenticated Authentication object.
  10. Store it in SecurityContextHolder for the current request.

Symmetric vs Asymmetric Signing

Type Example How it works Best Practice
Symmetric HS256 Same secret signs and verifies token. Harder to share safely across many services. Avoid weak secrets.
Asymmetric RS256, ES256 Authorization Server signs with private key; Resource Server verifies with public key. Preferred for distributed systems. Supports JWKS and key rotation.
Never trust JWT just because it can be decoded. Base64Url decoding is not validation. A valid JWT must have a trusted signature and valid claims.

JWT Access Token vs ID Token vs Refresh Token

Token Used By Purpose Should API accept it?
Access Token Resource Server / API Authorize API access. Yes.
ID Token Client application Proves user authentication in OIDC. Usually no. API should not treat ID token as access token.
Refresh Token Client + Authorization Server Obtain new access token. No. Resource Server should not accept refresh token for API access.

6. OAuth2 Resource Server with JWT

A Resource Server is an API that accepts bearer tokens issued by an Authorization Server. Its job is to validate the token and enforce authorization rules.

Client ↓ Authorization: Bearer access_token Resource Server API ↓ BearerTokenAuthenticationFilter ↓ BearerTokenAuthenticationToken ↓ ProviderManager ↓ JwtAuthenticationProvider ↓ JwtDecoder verifies signature + validates claims ↓ JwtAuthenticationConverter maps claims to authorities ↓ JwtAuthenticationToken stored in SecurityContext ↓ Authorization rules ↓ Controller

Spring Boot Configuration

spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://auth.example.com/realms/demo
          # or jwk-set-uri: https://auth.example.com/realms/demo/protocol/openid-connect/certs

SecurityFilterChain for Stateless JWT API

@Bean
SecurityFilterChain apiSecurity(HttpSecurity http) throws Exception {
    return http
        .csrf(csrf -> csrf.disable())
        .cors(Customizer.withDefaults())
        .sessionManagement(session ->
            session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
        )
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/actuator/health").permitAll()
            .requestMatchers(HttpMethod.GET, "/api/orders/**").hasAuthority("SCOPE_order:read")
            .requestMatchers(HttpMethod.POST, "/api/orders/**").hasAuthority("SCOPE_order:write")
            .anyRequest().authenticated()
        )
        .oauth2ResourceServer(oauth2 -> oauth2
            .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtAuthenticationConverter()))
        )
        .build();
}

Custom Role Mapping from JWT Claims

@Bean
JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtGrantedAuthoritiesConverter scopes = new JwtGrantedAuthoritiesConverter();
    scopes.setAuthorityPrefix("SCOPE_");
    scopes.setAuthoritiesClaimName("scope");

    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(jwt -> {
        Collection<GrantedAuthority> authorities = new ArrayList<>(scopes.convert(jwt));

        List<String> roles = jwt.getClaimAsStringList("roles");
        if (roles != null) {
            roles.stream()
                .map(role -> "ROLE_" + role)
                .map(SimpleGrantedAuthority::new)
                .forEach(authorities::add);
        }

        return authorities;
    });

    return converter;
}

Custom Audience Validation

@Bean
JwtDecoder jwtDecoder() {
    NimbusJwtDecoder decoder = JwtDecoders.fromIssuerLocation("https://auth.example.com");

    OAuth2TokenValidator<Jwt> withIssuer =
        JwtValidators.createDefaultWithIssuer("https://auth.example.com");

    OAuth2TokenValidator<Jwt> audienceValidator = jwt -> {
        if (jwt.getAudience().contains("order-api")) {
            return OAuth2TokenValidatorResult.success();
        }

        OAuth2Error error = new OAuth2Error(
            "invalid_token",
            "The required audience is missing",
            null
        );
        return OAuth2TokenValidatorResult.failure(error);
    };

    decoder.setJwtValidator(new DelegatingOAuth2TokenValidator<>(
        withIssuer,
        audienceValidator
    ));

    return decoder;
}
Senior note: Scope and role mapping must match the identity provider contract. Do not randomly mix ROLE_ADMIN, ADMIN, SCOPE_admin, and realm_access.roles without a clear mapping strategy.

7. Refresh Token, Revocation, and Logout

Access Token and Refresh Token Flow

User logs in at Authorization Server ↓ Authorization Server returns: - short-lived access token - longer-lived refresh token ↓ Client calls API with access token ↓ Access token expires ↓ Client sends refresh token to Authorization Server ↓ Authorization Server validates refresh token ↓ New access token issued

Important Rule

Refresh tokens should be sent only to the Authorization Server token endpoint. Resource Servers should not accept refresh tokens for API access.

JWT Revocation Problem

A signed JWT is usually self-contained. After it is issued, the API can validate it without calling the Authorization Server. This is good for performance, but immediate revocation becomes harder.

Strategy How it works Trade-off
Short access token TTL Access tokens expire quickly. Simple and common. Revocation delay is limited by TTL.
Refresh token rotation Each refresh returns new refresh token and invalidates old one. Good security, more state in authorization server.
Blacklist by jti Store revoked token IDs in Redis until expiration. Resource Server becomes stateful for revocation checks.
Introspection / opaque token API calls Authorization Server to validate token. Immediate revocation possible, but adds network latency/dependency.
User token version Token contains version; server rejects tokens older than current version. Useful for password reset/logout all devices, but requires lookup.

Where to Store Tokens?

Storage Pros Risks
HttpOnly Secure SameSite cookie Protected from JavaScript access. Needs CSRF strategy if cookie is automatically sent.
In-memory JS variable Reduced persistence if page is closed. Lost on refresh; still vulnerable to active XSS during page lifetime.
localStorage Simple persistence. High XSS impact. Avoid storing high-value tokens if possible.

8. Authorization: Roles, Authorities, Scopes, Method Security

Role vs Authority vs Scope

Term Meaning Spring Convention
Authority Generic permission string. order:read, SCOPE_order:read, ROLE_ADMIN
Role A type of authority representing a user group/role. hasRole("ADMIN") checks for ROLE_ADMIN.
Scope OAuth2 permission granted to a client/user. Usually mapped to SCOPE_xxx.

URL-Level Authorization

.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/public/**").permitAll()
    .requestMatchers(HttpMethod.GET, "/api/orders/**").hasAuthority("SCOPE_order:read")
    .requestMatchers(HttpMethod.POST, "/api/orders/**").hasAuthority("SCOPE_order:write")
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
    .anyRequest().authenticated()
)

Method-Level Authorization

@Service
public class OrderService {

    @PreAuthorize("hasAuthority('SCOPE_order:read')")
    public OrderDto getOrder(Long id) {
        return orderRepository.findDtoById(id).orElseThrow();
    }

    @PreAuthorize("hasRole('ADMIN') or #userId == authentication.name")
    public List<OrderDto> getOrdersForUser(String userId) {
        return orderRepository.findByUserId(userId);
    }
}
Request-level vs method-level: Request-level authorization is good for coarse-grained endpoint protection. Method-level authorization is better for fine-grained business rules near service methods.

RBAC vs ABAC

Model Meaning Example
RBAC Role-Based Access Control Only ADMIN can access user management.
ABAC Attribute-Based Access Control User can view order only if order.ownerId == currentUser.id and order.tenantId == currentTenant. 
@PreAuthorize("@orderPermission.canRead(authentication, #orderId)")
public OrderDto getOrder(Long orderId) {
    return orderRepository.findDtoById(orderId).orElseThrow();
}

@Component
public class OrderPermission {
    public boolean canRead(Authentication authentication, Long orderId) {
        String currentUserId = authentication.getName();
        return orderRepository.existsByIdAndOwnerId(orderId, currentUserId);
    }
}

9. CSRF and CORS

CORS

CORS is a browser mechanism that controls whether JavaScript from one origin can call resources on another origin. In Spring Security, CORS must be processed before security authentication because preflight requests usually do not contain cookies. 

@Bean
CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("https://app.example.com"));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
    config.setAllowedHeaders(List.of("Authorization", "Content-Type", "X-XSRF-TOKEN"));
    config.setAllowCredentials(true);

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return source;
}

CSRF

CSRF protects applications where authentication is automatically attached by the browser, usually cookies.

Application Type CSRF Recommendation Reason
Session-based web app / form login Keep CSRF enabled. Browser automatically sends session cookie.
SPA using cookies for authentication Keep CSRF enabled and expose CSRF token safely. Cookie is automatically sent cross-site depending on settings.
Stateless REST API using Authorization Bearer header Often disable CSRF. Bearer token is manually attached by client, not automatically by browser cookie. 
// Stateless Bearer-token API
http
    .csrf(csrf -> csrf.disable())
    .sessionManagement(session ->
        session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
    )
    .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));
Do not say “CSRF is always disabled for REST”. The real question is how authentication is stored and sent. If browser cookies authenticate the request, CSRF still matters.

10. Password Security

PasswordEncoder

Passwords should not be stored in plain text. Spring Security uses password encoders to hash and verify passwords. 

@Bean
PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();
}

DelegatingPasswordEncoder

DelegatingPasswordEncoder stores an algorithm id prefix in the encoded password, which allows algorithm migration. 

{bcrypt}$2a$10$J7B...
{argon2}$argon2id$v=19$m=...

BCrypt Example

@Bean
PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12);
}

Senior Rules for Passwords

  • Never store plain text passwords.
  • Never use NoOpPasswordEncoder in production.
  • Use adaptive hashing such as BCrypt, Argon2, SCrypt, or PBKDF2.
  • Use secure password reset flow with short-lived one-time token.
  • Consider compromised password checking for sensitive systems.
  • Throttle login attempts and protect against credential stuffing.

11. Advanced Production Topics

Custom Authentication Filter

Use a custom filter when credentials are not handled by built-in filters, for example API key authentication. 

public class ApiKeyAuthenticationFilter extends OncePerRequestFilter {

    private final AuthenticationManager authenticationManager;

    public ApiKeyAuthenticationFilter(AuthenticationManager authenticationManager) {
        this.authenticationManager = authenticationManager;
    }

    @Override
    protected void doFilterInternal(
        HttpServletRequest request,
        HttpServletResponse response,
        FilterChain filterChain
    ) throws ServletException, IOException {

        String apiKey = request.getHeader("X-API-KEY");

        if (apiKey != null) {
            Authentication authRequest = new ApiKeyAuthenticationToken(apiKey);
            Authentication authResult = authenticationManager.authenticate(authRequest);

            SecurityContext context = SecurityContextHolder.createEmptyContext();
            context.setAuthentication(authResult);
            SecurityContextHolder.setContext(context);
        }

        filterChain.doFilter(request, response);
    }
}

Custom AuthenticationProvider

@Component
public class ApiKeyAuthenticationProvider implements AuthenticationProvider {

    @Override
    public Authentication authenticate(Authentication authentication) {
        String apiKey = (String) authentication.getCredentials();

        ApiClient client = apiClientService.findByApiKeyHash(hash(apiKey))
                .orElseThrow(() -> new BadCredentialsException("Invalid API key"));

        return new ApiKeyAuthenticationToken(
            client.getClientId(),
            null,
            List.of(new SimpleGrantedAuthority("ROLE_API_CLIENT"))
        );
    }

    @Override
    public boolean supports(Class<?> authentication) {
        return ApiKeyAuthenticationToken.class.isAssignableFrom(authentication);
    }
}

AuthenticationEntryPoint vs AccessDeniedHandler

Component When used HTTP Status
AuthenticationEntryPoint User is not authenticated and tries to access protected resource. 401 Unauthorized
AccessDeniedHandler User is authenticated but lacks permission. 403 Forbidden 
.exceptionHandling(ex -> ex
    .authenticationEntryPoint((request, response, authException) -> {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType("application/json");
        response.getWriter().write("{\"error\":\"unauthorized\"}");
    })
    .accessDeniedHandler((request, response, accessDeniedException) -> {
        response.setStatus(HttpServletResponse.SC_FORBIDDEN);
        response.setContentType("application/json");
        response.getWriter().write("{\"error\":\"forbidden\"}");
    })
)

Production Checklist

  • Use TLS everywhere.
  • Use stateless JWT only when it fits the system; do not force JWT everywhere.
  • Validate JWT signature, issuer, audience, expiration, and algorithm.
  • Use short-lived access tokens.
  • Protect refresh tokens strongly.
  • Keep CSRF enabled for cookie/session-based apps.
  • Configure CORS with specific origins, not wildcard in credentialed flows.
  • Separate public endpoints, API endpoints, admin endpoints, and actuator endpoints carefully.
  • Do not expose stack traces or security exception details.
  • Log authentication failures carefully without leaking secrets.
  • Use method security for business-level authorization.
  • Test security with integration tests and negative cases.

Common Anti-Patterns

  • Disabling CSRF without understanding cookie-based authentication.
  • Using permitAll() too broadly.
  • Trusting JWT without validating issuer/audience/signature.
  • Using ID token as API access token.
  • Putting secrets or sensitive PII inside JWT claims.
  • Storing access/refresh tokens in insecure browser storage.
  • Mixing roles/scopes without a clear mapping convention.
  • Writing custom security when Spring already provides a standard mechanism.

12. Senior Interview Answer — English

Spring Security is a framework that provides authentication, authorization, and protection against common attacks. Internally, in servlet applications, it is mainly implemented as a filter chain. The servlet container delegates to DelegatingFilterProxy, which delegates to Spring Security’s FilterChainProxy. FilterChainProxy selects the first matching SecurityFilterChain, and the filters inside that chain handle authentication, session/security context management, CSRF, CORS, and authorization.

Authentication is the process of identifying who the user or client is. Spring Security represents this with the Authentication object. Authentication filters extract credentials or tokens and pass an authentication request to AuthenticationManager. The common implementation is ProviderManager, which delegates to one or more AuthenticationProvider implementations, such as DaoAuthenticationProvider for username/password or JwtAuthenticationProvider for JWT bearer tokens. Once authentication succeeds, the authenticated principal and authorities are stored in the SecurityContextHolder.

For modern stateless REST APIs, I usually configure the application as an OAuth2 Resource Server. The API receives a bearer access token, validates the JWT signature and claims using a JwtDecoder, maps scopes or roles to Spring authorities with a JwtAuthenticationConverter, and then enforces URL-level or method-level authorization rules. I always validate issuer, audience, expiration, signature algorithm, and key rotation strategy through JWKS.

For authorization, I separate coarse-grained endpoint rules in HttpSecurity from fine-grained business rules using method security like @PreAuthorize. For CSRF, I do not simply disable it everywhere. If authentication is cookie/session-based, CSRF protection is important. For stateless bearer-token APIs where the token is sent explicitly in the Authorization header, CSRF is commonly disabled. For CORS, I configure explicit trusted origins and ensure preflight requests are handled before authentication.

13. Tổng quan Spring Security

Spring Security là framework dùng để xử lý authentication, authorization và bảo vệ ứng dụng khỏi các attack phổ biến. Trong Spring Boot, mình thường cấu hình bằng một hoặc nhiều bean SecurityFilterChain.

Authentication

Trả lời câu hỏi: user/client là ai? Ví dụ: username/password, session login, JWT bearer token, OAuth2 login, API key.

Authorization

Trả lời câu hỏi: user/client được phép làm gì? Ví dụ: role, authority, scope, ownership, policy rule.

Exploit Protection

Bảo vệ khỏi các web attack như CSRF, clickjacking, insecure headers, session fixation.

HTTP Request ↓ Servlet Container ↓ DelegatingFilterProxy ↓ FilterChainProxy ↓ Matched SecurityFilterChain ↓ Security Filters ↓ Authentication + Authorization ↓ Controller / REST API
Mindset Senior: Spring Security không chỉ là vài annotation. Nó là một security pipeline dựa trên servlet filters: authenticate request, lưu kết quả vào SecurityContext, sau đó kiểm tra authorization trước khi request vào controller/business code.

Authentication vs Authorization

Khái niệm Câu hỏi Object / Feature trong Spring Security
Authentication Người dùng/client là ai? Authentication, AuthenticationManager, AuthenticationProvider, SecurityContext
Authorization Người dùng này có được phép làm action này không? AuthorizationFilter, AuthorizationManager, @PreAuthorize, roles/scopes/authorities

14. Kiến trúc Spring Security

Các component chính

Component Vai trò Ghi nhớ khi phỏng vấn
DelegatingFilterProxy Servlet filter delegate request tới Spring bean. Là cầu nối giữa servlet container và Spring-managed security filters.
FilterChainProxy Main filter của Spring Security, delegate tới nhiều security filter thông qua SecurityFilterChain. Nơi tốt để debug flow Spring Security.
SecurityFilterChain Định nghĩa security filters nào áp dụng cho request. Có thể có nhiều chain; chain match đầu tiên sẽ được dùng.
SecurityContextHolder Lưu current SecurityContext. Trong servlet app thường dựa trên ThreadLocal.
SecurityContext Chứa current Authentication. Nếu Authentication tồn tại và authenticated, user được xem là đã login/authenticated.
Authentication Đại diện cho principal, credentials và authorities. Trước auth có thể chứa credentials; sau auth đại diện cho authenticated principal.

Nhiều SecurityFilterChain

Trong hệ thống nâng cao, các nhóm URL khác nhau có thể cần cơ chế authentication khác nhau. Ví dụ: API dùng JWT, admin page dùng form login. 

@Bean
@Order(1)
SecurityFilterChain apiSecurity(HttpSecurity http) throws Exception {
    return http
        .securityMatcher("/api/**")
        .csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()))
        .build();
}

@Bean
@Order(2)
SecurityFilterChain adminSecurity(HttpSecurity http) throws Exception {
    return http
        .securityMatcher("/admin/**")
        .authorizeHttpRequests(auth -> auth.anyRequest().hasRole("ADMIN"))
        .formLogin(Customizer.withDefaults())
        .build();
}
Quan trọng: Nếu nhiều chain cùng match, chỉ chain đầu tiên match được sử dụng. Vì vậy order và matcher rất quan trọng.

15. Authentication Flow

Flow tổng quát

Unauthenticated Request ↓ Authentication Filter extract credentials/token ↓ Tạo Authentication object ↓ AuthenticationManager.authenticate(authentication) ↓ ProviderManager chọn AuthenticationProvider phù hợp ↓ AuthenticationProvider verify credentials/token ↓ Trả về authenticated Authentication ↓ SecurityContextHolder lưu Authentication ↓ Authorization checks ↓ Controller chạy

AuthenticationManager, ProviderManager, AuthenticationProvider

Component Ý nghĩa Ví dụ
AuthenticationManager Interface định nghĩa cách authenticate. Thường được implement bởi ProviderManager.
ProviderManager Delegate authentication cho danh sách AuthenticationProvider. Có thể thử DAO provider, JWT provider, LDAP provider, custom provider.
AuthenticationProvider Thực hiện một kiểu authentication cụ thể. DaoAuthenticationProvider, JwtAuthenticationProvider, custom API key provider.

Username/Password Authentication Flow

POST /login username/password ↓ UsernamePasswordAuthenticationFilter ↓ UsernamePasswordAuthenticationToken ↓ AuthenticationManager / ProviderManager ↓ DaoAuthenticationProvider ↓ UserDetailsService.loadUserByUsername() ↓ PasswordEncoder.matches(rawPassword, encodedPassword) ↓ Authenticated principal + authorities ↓ SecurityContext được lưu trong session mặc định

Các object quan trọng

Object Mục đích
UserDetailsService Load user data từ database, LDAP, external system...
UserDetails Đại diện username, password, trạng thái enabled/locked/expired và authorities.
PasswordEncoder Verify raw password với stored hash.
GrantedAuthority Đại diện permission, role hoặc scope. Ví dụ: ROLE_ADMIN, SCOPE_order:read.

16. Các cơ chế authentication

Cơ chế Cách hoạt động Phù hợp cho Lưu ý production
Form Login + Session User login username/password; server lưu authentication trong HTTP session. Server-rendered web app, admin portal. Giữ CSRF enabled. Cấu hình cookie secure.
HTTP Basic Client gửi username/password trong Authorization: Basic. Internal tools, machine-to-machine đơn giản qua TLS. Không nên dùng cho public app. Không có logout concept rõ ràng.
JWT Bearer Token Client gửi Authorization: Bearer <token>; API validate signature và claims. Stateless REST APIs, microservices. Validate issuer, audience, expiration, signature, algorithm và map scopes/roles cẩn thận.
OAuth2 Login User login qua external identity provider như Google, Okta, Keycloak. Web app cần federated login. Thường dùng Authorization Code flow. Với OIDC, ID token định danh user.
OAuth2 Resource Server API validate access token do Authorization Server cấp. Modern REST APIs. API không phải login server; API chỉ validate bearer token.
API Key Client gửi static/rotating key trong header. Service integration, webhook. Dùng limited permissions, rotation, rate limit, hash key khi lưu DB.
MFA / TOTP Yêu cầu factor thứ hai sau password, thường là time-based OTP. Admin user, hệ thống nhạy cảm. Backup code phải lưu an toàn, có thể kết hợp risk-based policy.
Câu nói phỏng vấn: Với microservices hiện đại, application thường đóng vai trò Resource Server. Nó không nên tự implement login/password/token issuing trừ khi mình chủ đích xây Authorization Server.

17. JWT chuyên sâu

JWT là gì?

JWT — JSON Web Token — là token format compact, thường dùng làm bearer access token. Nó chứa claims và được ký bằng cryptographic signature.

JWT = Base64Url(Header) + "." + Base64Url(Payload) + "." + Signature Header: { "alg": "RS256", "typ": "JWT", "kid": "key-id-1" } Payload / Claims: { "iss": "https://auth.example.com", "sub": "user-123", "aud": "order-api", "exp": 1710000000, "iat": 1709996400, "scope": "order:read order:write", "roles": ["ADMIN"] }

Các claims quan trọng

Claim Ý nghĩa Lưu ý validate
iss Issuer Phải match trusted Authorization Server.
sub Subject / user id Không tự assume là email nếu issuer không định nghĩa vậy.
aud Audience Nên match API/service identifier.
exp Expiration time Reject expired token.
nbf Not before Reject token nếu dùng quá sớm.
iat Issued at Hữu ích để debug và kiểm tra token age.
jti JWT ID Hữu ích cho revocation/blacklist hoặc audit.
scope / scp OAuth2 permissions Thường map sang Spring authorities như SCOPE_order:read.

Các bước validate JWT

  1. Lấy bearer token từ header Authorization.
  2. Decode JWT header để biết algorithm/key id.
  3. Load public key từ JWKS hoặc configured key.
  4. Verify signature.
  5. Validate issuer.
  6. Validate audience.
  7. Validate expiration và not-before time.
  8. Map claims/scopes/roles sang GrantedAuthority.
  9. Tạo authenticated Authentication.
  10. Lưu vào SecurityContextHolder cho request hiện tại.

Symmetric vs Asymmetric Signing

Loại Ví dụ Cách hoạt động Best Practice
Symmetric HS256 Cùng secret dùng để sign và verify token. Khó share an toàn trong nhiều services. Tránh weak secret.
Asymmetric RS256, ES256 Authorization Server sign bằng private key; Resource Server verify bằng public key. Phù hợp distributed systems. Hỗ trợ JWKS và key rotation.
Không bao giờ trust JWT chỉ vì decode được. Base64Url decoding không phải validation. JWT hợp lệ phải có trusted signature và valid claims.

Access Token vs ID Token vs Refresh Token

Token Dùng bởi Mục đích API có nên accept?
Access Token Resource Server / API Authorize API access. Có.
ID Token Client application Chứng minh user authentication trong OIDC. Thường không. API không nên dùng ID token như access token.
Refresh Token Client + Authorization Server Lấy access token mới. Không. Resource Server không accept refresh token cho API access.

18. OAuth2 Resource Server với JWT

Resource Server là API nhận bearer token do Authorization Server cấp. Nhiệm vụ của nó là validate token và enforce authorization rules.

Client ↓ Authorization: Bearer access_token Resource Server API ↓ BearerTokenAuthenticationFilter ↓ BearerTokenAuthenticationToken ↓ ProviderManager ↓ JwtAuthenticationProvider ↓ JwtDecoder verify signature + validate claims ↓ JwtAuthenticationConverter map claims sang authorities ↓ JwtAuthenticationToken lưu vào SecurityContext ↓ Authorization rules ↓ Controller

Spring Boot configuration

spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://auth.example.com/realms/demo
          # hoặc jwk-set-uri: https://auth.example.com/realms/demo/protocol/openid-connect/certs

SecurityFilterChain cho stateless JWT API

@Bean
SecurityFilterChain apiSecurity(HttpSecurity http) throws Exception {
    return http
        .csrf(csrf -> csrf.disable())
        .cors(Customizer.withDefaults())
        .sessionManagement(session ->
            session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
        )
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/actuator/health").permitAll()
            .requestMatchers(HttpMethod.GET, "/api/orders/**").hasAuthority("SCOPE_order:read")
            .requestMatchers(HttpMethod.POST, "/api/orders/**").hasAuthority("SCOPE_order:write")
            .anyRequest().authenticated()
        )
        .oauth2ResourceServer(oauth2 -> oauth2
            .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtAuthenticationConverter()))
        )
        .build();
}

Custom role mapping từ JWT claims

@Bean
JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtGrantedAuthoritiesConverter scopes = new JwtGrantedAuthoritiesConverter();
    scopes.setAuthorityPrefix("SCOPE_");
    scopes.setAuthoritiesClaimName("scope");

    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(jwt -> {
        Collection<GrantedAuthority> authorities = new ArrayList<>(scopes.convert(jwt));

        List<String> roles = jwt.getClaimAsStringList("roles");
        if (roles != null) {
            roles.stream()
                .map(role -> "ROLE_" + role)
                .map(SimpleGrantedAuthority::new)
                .forEach(authorities::add);
        }

        return authorities;
    });

    return converter;
}

Custom audience validation

@Bean
JwtDecoder jwtDecoder() {
    NimbusJwtDecoder decoder = JwtDecoders.fromIssuerLocation("https://auth.example.com");

    OAuth2TokenValidator<Jwt> withIssuer =
        JwtValidators.createDefaultWithIssuer("https://auth.example.com");

    OAuth2TokenValidator<Jwt> audienceValidator = jwt -> {
        if (jwt.getAudience().contains("order-api")) {
            return OAuth2TokenValidatorResult.success();
        }

        OAuth2Error error = new OAuth2Error(
            "invalid_token",
            "The required audience is missing",
            null
        );
        return OAuth2TokenValidatorResult.failure(error);
    };

    decoder.setJwtValidator(new DelegatingOAuth2TokenValidator<>(
        withIssuer,
        audienceValidator
    ));

    return decoder;
}
Senior note: Scope và role mapping phải khớp với contract của identity provider. Không nên mix bừa ROLE_ADMIN, ADMIN, SCOPE_admin, realm_access.roles nếu chưa có strategy rõ ràng.

19. Refresh Token, Revocation và Logout

Access Token và Refresh Token Flow

User login tại Authorization Server ↓ Authorization Server trả về: - access token ngắn hạn - refresh token dài hạn hơn ↓ Client gọi API bằng access token ↓ Access token hết hạn ↓ Client gửi refresh token tới Authorization Server ↓ Authorization Server validate refresh token ↓ Cấp access token mới

Rule quan trọng

Refresh token chỉ nên gửi tới token endpoint của Authorization Server. Resource Server không nên accept refresh token cho API access.

Vấn đề revocation của JWT

JWT thường là self-contained token. Sau khi được cấp, API có thể validate token mà không gọi Authorization Server. Điều này tốt cho performance, nhưng làm immediate revocation khó hơn.

Strategy Cách hoạt động Trade-off
Short access token TTL Access token hết hạn nhanh. Đơn giản và phổ biến. Revocation delay giới hạn bởi TTL.
Refresh token rotation Mỗi lần refresh trả token mới và invalidate token cũ. Bảo mật tốt hơn, nhưng Authorization Server cần state.
Blacklist theo jti Lưu revoked token IDs trong Redis đến khi token hết hạn. Resource Server trở nên stateful cho revocation checks.
Introspection / opaque token API gọi Authorization Server để validate token. Revocation nhanh hơn nhưng thêm network latency/dependency.
User token version Token chứa version; server reject token cũ hơn current version. Hữu ích cho password reset/logout all devices, nhưng cần lookup.

Nên lưu token ở đâu?

Storage Ưu điểm Rủi ro
HttpOnly Secure SameSite cookie JavaScript không đọc được token. Cần CSRF strategy nếu cookie tự động được gửi.
In-memory JS variable Không persist lâu sau khi close page. Mất khi refresh; vẫn bị active XSS trong page lifetime.
localStorage Dễ persist. Impact XSS cao. Tránh lưu high-value token nếu có thể.

20. Authorization: Roles, Authorities, Scopes, Method Security

Role vs Authority vs Scope

Khái niệm Ý nghĩa Convention trong Spring
Authority Permission string tổng quát. order:read, SCOPE_order:read, ROLE_ADMIN
Role Một loại authority đại diện cho role/group. hasRole("ADMIN") check ROLE_ADMIN.
Scope OAuth2 permission được cấp cho client/user. Thường map sang SCOPE_xxx.

URL-Level Authorization

.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/public/**").permitAll()
    .requestMatchers(HttpMethod.GET, "/api/orders/**").hasAuthority("SCOPE_order:read")
    .requestMatchers(HttpMethod.POST, "/api/orders/**").hasAuthority("SCOPE_order:write")
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
    .anyRequest().authenticated()
)

Method-Level Authorization

@Service
public class OrderService {

    @PreAuthorize("hasAuthority('SCOPE_order:read')")
    public OrderDto getOrder(Long id) {
        return orderRepository.findDtoById(id).orElseThrow();
    }

    @PreAuthorize("hasRole('ADMIN') or #userId == authentication.name")
    public List<OrderDto> getOrdersForUser(String userId) {
        return orderRepository.findByUserId(userId);
    }
}
Request-level vs method-level: Request-level tốt cho coarse-grained endpoint protection. Method-level tốt cho fine-grained business rules gần service methods.

RBAC vs ABAC

Model Ý nghĩa Ví dụ
RBAC Role-Based Access Control Chỉ ADMIN được vào user management.
ABAC Attribute-Based Access Control User chỉ xem order nếu order.ownerId == currentUser.id và order.tenantId == currentTenant. 
@PreAuthorize("@orderPermission.canRead(authentication, #orderId)")
public OrderDto getOrder(Long orderId) {
    return orderRepository.findDtoById(orderId).orElseThrow();
}

@Component
public class OrderPermission {
    public boolean canRead(Authentication authentication, Long orderId) {
        String currentUserId = authentication.getName();
        return orderRepository.existsByIdAndOwnerId(orderId, currentUserId);
    }
}

21. CSRF và CORS

CORS

CORS là cơ chế của browser để kiểm soát JavaScript từ origin này có được gọi resource ở origin khác không. Trong Spring Security, CORS cần được xử lý trước authentication vì preflight request thường không có cookies. 

@Bean
CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("https://app.example.com"));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
    config.setAllowedHeaders(List.of("Authorization", "Content-Type", "X-XSRF-TOKEN"));
    config.setAllowCredentials(true);

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return source;
}

CSRF

CSRF bảo vệ application khi authentication tự động được browser attach, thường là cookies.

Loại application Khuyến nghị CSRF Lý do
Session-based web app / form login Giữ CSRF enabled. Browser tự động gửi session cookie.
SPA dùng cookies để authenticate Giữ CSRF enabled và expose CSRF token an toàn. Cookie có thể tự động được gửi cross-site tùy settings.
Stateless REST API dùng Authorization Bearer header Thường disable CSRF. Bearer token được client attach thủ công, không tự động bởi browser cookie. 
// Stateless Bearer-token API
http
    .csrf(csrf -> csrf.disable())
    .sessionManagement(session ->
        session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
    )
    .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));
Không nên nói “REST thì luôn disable CSRF”. Câu hỏi đúng là authentication được lưu và gửi bằng cách nào. Nếu dùng browser cookies để authenticate, CSRF vẫn quan trọng.

22. Password Security

PasswordEncoder

Password không được lưu plain text. Spring Security dùng password encoder để hash và verify password. 

@Bean
PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();
}

DelegatingPasswordEncoder

DelegatingPasswordEncoder lưu algorithm id prefix trong encoded password, giúp migrate thuật toán hash dễ hơn. 

{bcrypt}$2a$10$J7B...
{argon2}$argon2id$v=19$m=...

BCrypt Example

@Bean
PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12);
}

Rule Senior cho password

  • Không bao giờ lưu plain text password.
  • Không dùng NoOpPasswordEncoder trong production.
  • Dùng adaptive hashing như BCrypt, Argon2, SCrypt hoặc PBKDF2.
  • Password reset flow phải dùng short-lived one-time token.
  • Cân nhắc compromised password checking cho hệ thống nhạy cảm.
  • Throttle login attempts và chống credential stuffing.

23. Các chủ đề nâng cao trong production

Custom Authentication Filter

Dùng custom filter khi credentials không được xử lý bởi built-in filters, ví dụ API key authentication. 

public class ApiKeyAuthenticationFilter extends OncePerRequestFilter {

    private final AuthenticationManager authenticationManager;

    public ApiKeyAuthenticationFilter(AuthenticationManager authenticationManager) {
        this.authenticationManager = authenticationManager;
    }

    @Override
    protected void doFilterInternal(
        HttpServletRequest request,
        HttpServletResponse response,
        FilterChain filterChain
    ) throws ServletException, IOException {

        String apiKey = request.getHeader("X-API-KEY");

        if (apiKey != null) {
            Authentication authRequest = new ApiKeyAuthenticationToken(apiKey);
            Authentication authResult = authenticationManager.authenticate(authRequest);

            SecurityContext context = SecurityContextHolder.createEmptyContext();
            context.setAuthentication(authResult);
            SecurityContextHolder.setContext(context);
        }

        filterChain.doFilter(request, response);
    }
}

Custom AuthenticationProvider

@Component
public class ApiKeyAuthenticationProvider implements AuthenticationProvider {

    @Override
    public Authentication authenticate(Authentication authentication) {
        String apiKey = (String) authentication.getCredentials();

        ApiClient client = apiClientService.findByApiKeyHash(hash(apiKey))
                .orElseThrow(() -> new BadCredentialsException("Invalid API key"));

        return new ApiKeyAuthenticationToken(
            client.getClientId(),
            null,
            List.of(new SimpleGrantedAuthority("ROLE_API_CLIENT"))
        );
    }

    @Override
    public boolean supports(Class<?> authentication) {
        return ApiKeyAuthenticationToken.class.isAssignableFrom(authentication);
    }
}

AuthenticationEntryPoint vs AccessDeniedHandler

Component Khi nào dùng HTTP Status
AuthenticationEntryPoint User chưa authenticated nhưng access protected resource. 401 Unauthorized
AccessDeniedHandler User đã authenticated nhưng không đủ quyền. 403 Forbidden 
.exceptionHandling(ex -> ex
    .authenticationEntryPoint((request, response, authException) -> {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType("application/json");
        response.getWriter().write("{\"error\":\"unauthorized\"}");
    })
    .accessDeniedHandler((request, response, accessDeniedException) -> {
        response.setStatus(HttpServletResponse.SC_FORBIDDEN);
        response.setContentType("application/json");
        response.getWriter().write("{\"error\":\"forbidden\"}");
    })
)

Production Checklist

  • Dùng TLS ở mọi nơi.
  • Dùng stateless JWT khi phù hợp; không ép JWT cho mọi hệ thống.
  • Validate JWT signature, issuer, audience, expiration và algorithm.
  • Dùng short-lived access token.
  • Bảo vệ refresh token thật kỹ.
  • Giữ CSRF enabled cho cookie/session-based apps.
  • Cấu hình CORS bằng origin cụ thể, không wildcard trong credentialed flows.
  • Tách public endpoints, API endpoints, admin endpoints, actuator endpoints rõ ràng.
  • Không expose stack trace hoặc security exception detail.
  • Log authentication failures cẩn thận, không leak secrets.
  • Dùng method security cho business-level authorization.
  • Test security bằng integration tests và negative cases.

Common Anti-Patterns

  • Disable CSRF mà không hiểu cookie-based authentication.
  • Dùng permitAll() quá rộng.
  • Trust JWT mà không validate issuer/audience/signature.
  • Dùng ID token như API access token.
  • Đưa secrets hoặc sensitive PII vào JWT claims.
  • Lưu access/refresh token trong browser storage không an toàn.
  • Mix roles/scopes không có convention rõ ràng.
  • Tự viết custom security trong khi Spring đã có standard mechanism.

24. Câu trả lời phỏng vấn — Vietnamese

Spring Security là framework cung cấp authentication, authorization và protection against common attacks. Trong servlet application, Spring Security chủ yếu hoạt động dựa trên filter chain. Servlet container gọi DelegatingFilterProxy, filter này delegate tới Spring Security FilterChainProxy. Sau đó FilterChainProxy chọn SecurityFilterChain đầu tiên match với request, và các filter trong chain sẽ xử lý authentication, session/security context, CSRF, CORS và authorization.

Authentication là quá trình xác định user hoặc client là ai. Spring Security biểu diễn thông tin này bằng object Authentication. Authentication filter extract credentials hoặc token rồi gửi authentication request tới AuthenticationManager. Implementation phổ biến là ProviderManager, nó delegate tới các AuthenticationProvider như DaoAuthenticationProvider cho username/password hoặc JwtAuthenticationProvider cho JWT bearer token. Khi authentication thành công, principal và authorities được lưu vào SecurityContextHolder.

Với REST API stateless hiện đại, em thường cấu hình application như một OAuth2 Resource Server. API nhận bearer access token, validate JWT signature và claims bằng JwtDecoder, map scopes hoặc roles sang Spring authorities bằng JwtAuthenticationConverter, sau đó enforce authorization rule ở URL-level hoặc method-level. Em luôn kiểm tra issuer, audience, expiration, signature algorithm và key rotation strategy thông qua JWKS.

Về authorization, em tách coarse-grained endpoint rules trong HttpSecurity và fine-grained business rules bằng method security như @PreAuthorize. Với CSRF, em không disable một cách máy móc. Nếu authentication dựa trên cookie/session, CSRF protection rất quan trọng. Với stateless bearer-token API gửi token rõ ràng trong Authorization header thì thường disable CSRF. Với CORS, em cấu hình trusted origins cụ thể và đảm bảo preflight request được xử lý trước authentication.
