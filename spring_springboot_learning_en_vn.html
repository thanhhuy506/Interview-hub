Spring is mainly about object creation, dependency wiring, lifecycle management, and infrastructure support so that business code can stay clean.

Recommended order

  2. Learn IoC and Dependency Injection.
  3. Learn what a Bean is.
  4. Learn ApplicationContext and BeanFactory.
  5. Learn component scanning and annotations.
  6. Learn bean lifecycle and bean scopes.
  7. Learn how Spring resolves multiple beans.
  8. Learn Spring Boot and starters.
  9. Learn auto-configuration.
  10. Learn properties and profiles.
  11. Learn REST API structure.
  12. Learn validation, exception handling, transaction, AOP, and testing.

Core mental model

Your code declares dependencies ↓ Spring scans configuration metadata ↓ Spring creates beans ↓ Spring injects dependencies ↓ Spring manages lifecycle ↓ Your application uses ready-to-use objects

2. What is Spring?

Spring is a Java application framework that helps build enterprise applications by providing infrastructure for dependency injection, transaction management, web applications, data access, messaging, security integration, testing, and more.

Simple definition: Spring is a framework and IoC container that creates objects, wires dependencies, and manages their lifecycle.

Without Spring

public class OrderService {
    private final PaymentService paymentService = new PaymentService();
    private final EmailService emailService = new EmailService();

    public void createOrder() {
        paymentService.pay();
        emailService.sendEmail();
    }
}

Problems:

  • OrderService directly creates its dependencies.
  • Hard to replace PaymentService with another implementation.
  • Hard to unit test because dependencies are hard-coded.
  • Object creation and business logic are mixed together.

With Spring

@Service
public class OrderService {
    private final PaymentService paymentService;
    private final EmailService emailService;

    public OrderService(PaymentService paymentService, EmailService emailService) {
        this.paymentService = paymentService;
        this.emailService = emailService;
    }

    public void createOrder() {
        paymentService.pay();
        emailService.sendEmail();
    }
}
Now OrderService only declares what it needs. Spring creates and injects the dependencies.

3. IoC and Dependency Injection

3.1. What is IoC?

IoC means Inversion of Control. The control of object creation and dependency wiring is moved from application code to the Spring container.

Traditional code: Your class creates dependencies using new IoC: Spring container creates dependencies and gives them to your class

3.2. What is DI?

Dependency Injection is one implementation of IoC. It means an object receives its dependencies from outside instead of creating them itself.

public class OrderService {
    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

Here, OrderService does not create PaymentService. It receives it through constructor injection.

3.3. IoC vs DI

Concept Meaning Simple Explanation
IoC Inversion of Control The framework controls object creation and wiring.
DI Dependency Injection The framework injects required dependencies into objects.
Interview line: IoC is the principle. DI is the technique Spring uses to implement that principle.

4. Spring IoC Container

The IoC container is responsible for creating, configuring, assembling, and managing Spring beans.

Two important container interfaces

Interface Meaning Use
BeanFactory Basic IoC container. Provides basic bean creation and dependency injection.
ApplicationContext Advanced container built on top of BeanFactory features. Most commonly used. Adds events, i18n, resource loading, environment, annotation support, etc.

Typical Spring Boot container

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        ApplicationContext context =
                SpringApplication.run(DemoApplication.class, args);
    }
}

What happens at startup?

SpringApplication.run() ↓ Create ApplicationContext ↓ Read configuration metadata ↓ Scan components ↓ Register BeanDefinitions ↓ Create beans ↓ Inject dependencies ↓ Run lifecycle callbacks ↓ Application is ready

5. What is a Bean?

A Spring Bean is an object created, configured, and managed by the Spring IoC container.

Normal Java object = object you create and manage yourself.
Spring Bean = object Spring creates and manages for you.

Example bean using @Component

@Component
public class EmailService {
    public void sendEmail(String message) {
        System.out.println("Sending email: " + message);
    }
}

Example bean using @Bean

@Configuration
public class AppConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}

BeanDefinition vs Bean instance

Concept Meaning
BeanDefinition Metadata that tells Spring how to create a bean.
Bean instance The actual object created from BeanDefinition.

6. How Beans Are Created

6.1. Component scanning

Spring scans classes annotated with stereotype annotations and registers them as beans.

@Component @Service @Repository @Controller @RestController 
@Service
public class PaymentService {
    public void pay() {
        System.out.println("Payment completed");
    }
}

6.2. Java configuration with @Bean

Use @Bean when you need to create a bean manually, especially for third-party classes.

@Configuration
public class HttpClientConfig {

    @Bean
    public WebClient webClient() {
        return WebClient.builder()
                .baseUrl("https://api.example.com")
                .build();
    }
}

@Component vs @Bean

Point @Component @Bean
Where used On class On method inside @Configuration class
Best for Your own classes Third-party classes or custom construction logic
Creation style Automatic by component scanning Manual method return value becomes bean

7. Types of Dependency Injection

7.1. Constructor Injection - Recommended

@Service
public class OrderService {
    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
Constructor injection is recommended because it makes dependencies explicit, supports immutability with final, and improves testability.

7.2. Setter Injection

@Service
public class OrderService {
    private PaymentService paymentService;

    @Autowired
    public void setPaymentService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

Useful for optional dependencies, but less strict than constructor injection.

7.3. Field Injection - Usually Avoid

@Service
public class OrderService {

    @Autowired
    private PaymentService paymentService;
}
Field injection is easy to write but harder to test and hides required dependencies. Prefer constructor injection in production code.

Comparison

Injection type Pros Cons Recommendation
Constructor Explicit, immutable, easy to test Can be verbose with many dependencies Best default
Setter Good for optional dependency Object may be partially initialized Use when dependency is optional
Field Short code Harder to test, hides dependency Avoid in business code

9. Bean Lifecycle

Bean lifecycle means the steps Spring follows from bean creation to bean destruction.

1. Instantiate bean 2. Populate properties / inject dependencies 3. Aware callbacks 4. BeanPostProcessor before initialization 5. @PostConstruct 6. InitializingBean.afterPropertiesSet() 7. Custom init method 8. Bean is ready to use 9. @PreDestroy 10. DisposableBean.destroy() 11. Custom destroy method

Example with @PostConstruct and @PreDestroy

@Service
public class CacheService {

    @PostConstruct
    public void init() {
        System.out.println("Initialize cache");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("Cleanup cache");
    }
}

BeanPostProcessor

BeanPostProcessor allows custom logic before and after bean initialization. Many Spring features are implemented using post-processors.

@Component
public class CustomBeanPostProcessor implements BeanPostProcessor {

    @Override
    public Object postProcessBeforeInitialization(Object bean, String beanName) {
        System.out.println("Before init: " + beanName);
        return bean;
    }

    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        System.out.println("After init: " + beanName);
        return bean;
    }
}
Senior note: AOP proxies are often created during bean post-processing. That is why the actual bean used at runtime may be a proxy, not the raw object.

10. Bean Scopes

Bean scope controls how many instances Spring creates and how long they live.

Scope Meaning Use case
singleton One bean instance per Spring container. Default. Stateless services.
prototype New instance every time requested. Stateful or short-lived objects.
request One instance per HTTP request. Web request data.
session One instance per HTTP session. User session state.
application One instance per ServletContext. Application-level web state.

Singleton scope example

@Service
public class OrderService {
}

By default, this is singleton.

Prototype scope example

@Component
@Scope("prototype")
public class ReportBuilder {
}
Important: Since singleton beans are shared across threads, do not store request-specific mutable data in fields.

Bad singleton example

@Service
public class PaymentService {
    private String currentUserId; // dangerous in singleton bean

    public void pay(String userId) {
        this.currentUserId = userId;
    }
}

Good singleton example

@Service
public class PaymentService {

    public void pay(String userId) {
        String currentUserId = userId; // local variable
    }
}

11. Multiple Beans: @Primary and @Qualifier

If multiple beans implement the same interface, Spring may not know which one to inject.

Interface

public interface NotificationService {
    void send(String message);
}

Two implementations

@Service
public class EmailNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}

@Service
public class SmsNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("SMS: " + message);
    }
}

Use @Qualifier

@Service
public class OrderService {
    private final NotificationService notificationService;

    public OrderService(
            @Qualifier("emailNotificationService")
            NotificationService notificationService
    ) {
        this.notificationService = notificationService;
    }
}

Use @Primary

@Service
@Primary
public class EmailNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}
Annotation Meaning
@Primary Default bean when multiple candidates exist.
@Qualifier Explicitly select a bean by name or qualifier.

12. What is Spring Boot?

Spring Boot is built on top of Spring. It makes it easier to create production-ready Spring applications with less configuration.

What Spring Boot gives us

  • Auto-configuration.
  • Starter dependencies.
  • Embedded servers such as Tomcat, Jetty, or Undertow.
  • Externalized configuration through properties or YAML.
  • Actuator for monitoring and management.
  • Easy testing support.
  • Production-friendly defaults.

Minimal Spring Boot application

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@SpringBootApplication internally

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan
public @interface SpringBootApplication {
}

Spring vs Spring Boot

Spring Spring Boot
Core framework. Opinionated way to build Spring applications quickly.
Manual configuration is often needed. Auto-configuration reduces manual setup.
Server setup can be external. Embedded server is included by default for web apps.
More flexible but more verbose. Faster setup with sensible defaults.

13. Spring Boot Auto-configuration

Auto-configuration means Spring Boot tries to automatically configure your application based on the dependencies on the classpath and existing beans in the context.

You add dependency ↓ Spring Boot sees classpath ↓ Auto-configuration classes are evaluated ↓ Conditions are checked ↓ Missing beans are created automatically ↓ You can override them by defining your own bean

Example: Web MVC auto-configuration

If you add:

spring-boot-starter-web

Spring Boot can auto-configure:

  • Embedded Tomcat.
  • Spring MVC.
  • Jackson JSON converter.
  • Default error handling.
  • DispatcherServlet.

Example: DataSource auto-configuration

If JDBC/JPA dependencies and database driver are on the classpath, Spring Boot can configure a DataSource if you provide properties.

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/demo
    username: demo
    password: secret

Common condition annotations

Annotation Meaning
@ConditionalOnClass Apply configuration only if a class exists on the classpath.
@ConditionalOnMissingBean Create bean only if user has not already defined one.
@ConditionalOnProperty Apply configuration based on a property value.
@ConditionalOnWebApplication Apply only in a web application.

Override auto-configuration

@Configuration
public class CustomJacksonConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper()
                .findAndRegisterModules();
    }
}

If auto-configuration uses @ConditionalOnMissingBean(ObjectMapper.class), your custom bean wins.

Disable specific auto-configuration

@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
public class DemoApplication {
}
Interview line: Auto-configuration does not mean magic. It is conditional configuration. Spring Boot checks classpath, properties, and existing beans, then creates default beans only when appropriate.

15. REST API Layer in Spring Boot

Typical layers

Controller → Service → Repository → Database

Entity

@Entity
@Table(name = "employees")
public class Employee {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private BigDecimal salary;
}

Repository

public interface EmployeeRepository extends JpaRepository<Employee, Long> {
}

Service

@Service
public class EmployeeService {
    private final EmployeeRepository employeeRepository;

    public EmployeeService(EmployeeRepository employeeRepository) {
        this.employeeRepository = employeeRepository;
    }

    public Employee getById(Long id) {
        return employeeRepository.findById(id)
                .orElseThrow(() -> new EmployeeNotFoundException(id));
    }
}

Controller

@RestController
@RequestMapping("/api/employees")
public class EmployeeController {
    private final EmployeeService employeeService;

    public EmployeeController(EmployeeService employeeService) {
        this.employeeService = employeeService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<Employee> getById(@PathVariable Long id) {
        return ResponseEntity.ok(employeeService.getById(id));
    }
}

Validation

public class CreateEmployeeRequest {

    @NotBlank
    private String name;

    @Positive
    private BigDecimal salary;
}
@PostMapping
public ResponseEntity<EmployeeResponse> create(
        @Valid @RequestBody CreateEmployeeRequest request
) {
    return ResponseEntity.ok(employeeService.create(request));
}

Global exception handler

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(EmployeeNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(EmployeeNotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(new ErrorResponse("EMPLOYEE_NOT_FOUND", ex.getMessage()));
    }
}

16. AOP - Aspect Oriented Programming

AOP helps separate cross-cutting concerns from business logic.

Common cross-cutting concerns

  • Logging.
  • Security.
  • Transaction management.
  • Metrics.
  • Auditing.
  • Retry.

Example custom annotation

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface LogExecutionTime {
}

Aspect

@Aspect
@Component
public class LogExecutionTimeAspect {

    @Around("@annotation(LogExecutionTime)")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();

        Object result = joinPoint.proceed();

        long end = System.currentTimeMillis();
        System.out.println("Execution time: " + (end - start) + "ms");

        return result;
    }
}

Use annotation

@Service
public class ReportService {

    @LogExecutionTime
    public void generateReport() {
        // business logic
    }
}
Senior note: Spring AOP usually works through proxies. A common limitation is self-invocation: when one method inside the same class calls another proxied method, the proxy may be bypassed.

17. Transaction Management

@Transactional tells Spring to run a method inside a database transaction.

@Service
public class OrderService {

    @Transactional
    public void createOrder(CreateOrderRequest request) {
        orderRepository.save(order);
        paymentRepository.save(payment);
    }
}

What happens?

Method starts ↓ Spring opens transaction ↓ Business logic runs ↓ If success → commit If runtime exception → rollback

Important rules

  • By default, rollback happens for unchecked exceptions.
  • Checked exceptions do not trigger rollback by default unless configured.
  • @Transactional usually works through proxy-based AOP.
  • Self-invocation may bypass transaction proxy.
  • Use transaction boundary at service layer, not controller layer.

Rollback for checked exception

@Transactional(rollbackFor = Exception.class)
public void process() throws Exception {
    // business logic
}

Read-only transaction

@Transactional(readOnly = true)
public List<Order> getOrders() {
    return orderRepository.findAll();
}

18. Testing Spring Boot Applications

Unit test service with Mockito

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {

    @Mock
    private OrderRepository orderRepository;

    @InjectMocks

19. Production Best Practices

Use constructor injection

Clear dependencies, easier tests, immutable fields.

Keep services stateless

Singleton beans are shared by multiple threads.

Separate layers

Controller, service, repository, DTO, mapper.

Use DTOs

Do not expose entities directly in public APIs.

Centralize exceptions

Use @RestControllerAdvice.

Use configuration properties

Prefer typed configuration over many scattered @Value.

Use profiles carefully

Separate dev, staging, production config.

Monitor with Actuator

Expose health, metrics, readiness/liveness carefully.

Common mistakes

  • Putting business logic in controller.
  • Using field injection everywhere.
  • Using entities as API response directly.
  • Storing request-specific data in singleton services.
  • Misunderstanding @Transactional self-invocation.
  • Creating too many beans without clear responsibility.
  • Overusing profiles to hide design problems.

20. Interview Summary

What is Spring?

Spring is a Java framework and IoC container that helps build enterprise applications. It manages object creation, dependency injection, lifecycle, transactions, web layer, data access, and many infrastructure concerns so developers can focus on business logic.

What is a Bean?

A bean is an object that is created, configured, and managed by the Spring IoC container. Instead of manually creating objects using new, we let Spring create and wire them.

What is IoC?

IoC means Inversion of Control. The responsibility of creating and wiring objects is moved from application code to the Spring container.

What is DI?

Dependency Injection is a way to implement IoC. A class receives its dependencies from outside, usually through constructor injection, instead of creating them itself.

What is Spring Boot auto-configuration?

Auto-configuration is conditional configuration. Spring Boot checks classpath dependencies, properties, and existing beans, then creates default beans automatically when appropriate. Developers can override it by defining their own beans or excluding specific auto-configuration classes.

Best short interview answer

Spring is mainly about IoC and Dependency Injection. 
Instead of creating dependencies manually, we declare what a class needs, 
and the Spring container creates beans, injects dependencies, and manages their lifecycle.

Spring Boot builds on top of Spring and reduces configuration through starters and auto-configuration. 
Auto-configuration checks the classpath, properties, and existing beans, then creates sensible default beans. 
It is not magic; it is conditional configuration that can be overridden.

2. Spring là gì?

Spring là Java application framework giúp xây dựng enterprise applications bằng cách cung cấp nền tảng cho dependency injection, transaction management, web application, data access, messaging, security integration, testing và nhiều phần infrastructure khác.

Định nghĩa dễ nhớ: Spring là framework và IoC container giúp tạo object, nối dependency và quản lý lifecycle của chúng.

Nếu không dùng Spring

public class OrderService {
    private final PaymentService paymentService = new PaymentService();
    private final EmailService emailService = new EmailService();

    public void createOrder() {
        paymentService.pay();
        emailService.sendEmail();
    }
}

Vấn đề:

  • OrderService tự tạo dependency.
  • Khó thay PaymentService bằng implementation khác.
  • Khó unit test vì dependency bị hard-code.
  • Object creation bị trộn với business logic.

Khi dùng Spring

@Service
public class OrderService {
    private final PaymentService paymentService;
    private final EmailService emailService;

    public OrderService(PaymentService paymentService, EmailService emailService) {
        this.paymentService = paymentService;
        this.emailService = emailService;
    }

    public void createOrder() {
        paymentService.pay();
        emailService.sendEmail();
    }
}
Lúc này OrderService chỉ khai báo nó cần gì. Spring sẽ tạo và inject dependencies.

3. IoC và Dependency Injection

3.1. IoC là gì?

IoC là Inversion of Control. Nghĩa là quyền kiểm soát việc tạo object và wiring dependency được chuyển từ code của mình sang Spring container.

Code truyền thống: Class tự tạo dependency bằng new IoC: Spring container tạo dependency và đưa dependency đó cho class

3.2. DI là gì?

Dependency Injection là một cách implement IoC. Object nhận dependency từ bên ngoài thay vì tự tạo dependency bên trong.

public class OrderService {
    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

Ở đây OrderService không tự tạo PaymentService. Nó nhận dependency qua constructor.

3.3. IoC vs DI

Khái niệm Ý nghĩa Giải thích dễ hiểu
IoC Inversion of Control Framework kiểm soát việc tạo object và wiring.
DI Dependency Injection Framework inject dependency vào object.
Câu phỏng vấn: IoC là nguyên lý. DI là kỹ thuật Spring dùng để implement nguyên lý đó.

4. Spring IoC Container

IoC container chịu trách nhiệm tạo, cấu hình, assemble và quản lý Spring beans.

Hai interface quan trọng

Interface Ý nghĩa Cách dùng
BeanFactory IoC container cơ bản. Cung cấp bean creation và dependency injection cơ bản.
ApplicationContext Container nâng cao, mở rộng từ các feature của BeanFactory. Dùng phổ biến nhất. Có event, i18n, resource loading, environment, annotation support, v.v.

Container trong Spring Boot

7. Các kiểu Dependency Injection

7.1. Constructor Injection - Khuyến nghị dùng

@Service
public class OrderService {
    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
Constructor injection được khuyến nghị vì dependency rõ ràng, hỗ trợ immutability với final, và dễ test hơn.

7.2. Setter Injection

@Service
public class OrderService {
    private PaymentService paymentService;

    @Autowired
    public void setPaymentService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

Hữu ích cho optional dependencies, nhưng không strict bằng constructor injection.

7.3. Field Injection - Thường nên tránh

@Service
public class OrderService {

    @Autowired
    private PaymentService paymentService;
}
Field injection viết nhanh nhưng khó test hơn và che giấu required dependencies. Trong production code nên ưu tiên constructor injection.

So sánh

Kiểu injection Ưu điểm Nhược điểm Khuyến nghị
Constructor Rõ ràng, immutable, dễ test Có thể dài nếu quá nhiều dependency Nên dùng mặc định
Setter Tốt cho optional dependency Object có thể bị partially initialized Dùng khi dependency optional
Field Code ngắn Khó test, giấu dependency Nên tránh trong business code

9. Bean Lifecycle

Bean lifecycle là các bước Spring thực hiện từ lúc tạo bean đến lúc destroy bean.

1. Instantiate bean 2. Populate properties / inject dependencies 3. Aware callbacks 4. BeanPostProcessor before initialization 5. @PostConstruct 6. InitializingBean.afterPropertiesSet() 7. Custom init method 8. Bean sẵn sàng sử dụng 9. @PreDestroy 10. DisposableBean.destroy() 11. Custom destroy method

Ví dụ @PostConstruct và @PreDestroy

@Service
public class CacheService {

    @PostConstruct
    public void init() {
        System.out.println("Initialize cache");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("Cleanup cache");
    }
}

BeanPostProcessor

BeanPostProcessor cho phép chạy custom logic trước và sau bean initialization. Rất nhiều feature của Spring được implement thông qua post-processors.

@Component
public class CustomBeanPostProcessor implements BeanPostProcessor {

    @Override
    public Object postProcessBeforeInitialization(Object bean, String beanName) {
        System.out.println("Before init: " + beanName);
        return bean;
    }

    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        System.out.println("After init: " + beanName);
        return bean;
    }
}
Senior note: AOP proxies thường được tạo trong giai đoạn bean post-processing. Vì vậy object runtime đôi khi là proxy, không phải raw object ban đầu.

10. Bean Scopes

Bean scope quyết định Spring tạo bao nhiêu instance và vòng đời của instance đó.

Scope Ý nghĩa Use case
singleton Một bean instance cho mỗi Spring container. Mặc định. Stateless services.
prototype Mỗi lần request bean sẽ tạo instance mới. Stateful hoặc short-lived objects.
request Một instance cho mỗi HTTP request. Web request data.
session Một instance cho mỗi HTTP session. User session state.
application Một instance cho mỗi ServletContext. Application-level web state.

Singleton scope

@Service
public class OrderService {
}

Mặc định bean này là singleton.

Prototype scope

@Component
@Scope("prototype")
public class ReportBuilder {
}
Quan trọng: Vì singleton bean được share giữa nhiều threads, không nên lưu request-specific mutable data trong field.

Ví dụ sai với singleton

@Service
public class PaymentService {
    private String currentUserId; // nguy hiểm trong singleton bean

    public void pay(String userId) {
        this.currentUserId = userId;
    }
}

Ví dụ đúng

@Service
public class PaymentService {

    public void pay(String userId) {
        String currentUserId = userId; // local variable
    }
}

11. Nhiều Bean: @Primary và @Qualifier

Nếu nhiều bean cùng implement một interface, Spring có thể không biết nên inject bean nào.

Interface

public interface NotificationService {
    void send(String message);
}

Hai implementation

@Service
public class EmailNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}

@Service
public class SmsNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("SMS: " + message);
    }
}

Dùng @Qualifier

@Service
public class OrderService {
    private final NotificationService notificationService;

    public OrderService(
            @Qualifier("emailNotificationService")
            NotificationService notificationService
    ) {
        this.notificationService = notificationService;
    }
}

Dùng @Primary

@Service
@Primary
public class EmailNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}
Annotation Ý nghĩa
@Primary Bean mặc định khi có nhiều candidates.
@Qualifier Chọn bean cụ thể theo name hoặc qualifier.

Ví dụ: DataSource auto-configuration

Các condition annotations phổ biến

Annotation Ý nghĩa

public class CustomJacksonConfig {

    @Bean

                .findAndRegisterModules();

Nếu auto-configuration dùng @ConditionalOnMissingBean(ObjectMapper.class), bean custom của mình sẽ được ưu tiên.

15. REST API Layer trong Spring Boot

Các layer phổ biến

Controller → Service → Repository → Database

Entity

@Entity
@Table(name = "employees")
public class Employee {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private BigDecimal salary;
}

Repository

public interface EmployeeRepository extends JpaRepository<Employee, Long> {
}

Service

@Service
public class EmployeeService {
    private final EmployeeRepository employeeRepository;

    public EmployeeService(EmployeeRepository employeeRepository) {
        this.employeeRepository = employeeRepository;
    }

    public Employee getById(Long id) {
        return employeeRepository.findById(id)
                .orElseThrow(() -> new EmployeeNotFoundException(id));
    }
}

Controller

@RestController
@RequestMapping("/api/employees")
public class EmployeeController {
    private final EmployeeService employeeService;

    public EmployeeController(EmployeeService employeeService) {
        this.employeeService = employeeService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<Employee> getById(@PathVariable Long id) {
        return ResponseEntity.ok(employeeService.getById(id));
    }
}

public class CreateEmployeeRequest {

    @NotBlank
    private String name;

    @Positive
    private BigDecimal salary;
}
@PostMapping
public ResponseEntity<EmployeeResponse> create(
        @Valid @RequestBody CreateEmployeeRequest request
) {
    return ResponseEntity.ok(employeeService.create(request));
}

public class GlobalExceptionHandler {

16. AOP - Aspect Oriented Programming

AOP giúp tách các cross-cutting concerns ra khỏi business logic.

Các cross-cutting concerns phổ biến

  • Logging.
  • Security.
  • Transaction management.
  • Metrics.
  • Auditing.
  • Retry.

Ví dụ custom annotation

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface LogExecutionTime {
}

Aspect

@Aspect
@Component
public class LogExecutionTimeAspect {

    @Around("@annotation(LogExecutionTime)")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();

        Object result = joinPoint.proceed();

        long end = System.currentTimeMillis();
        System.out.println("Execution time: " + (end - start) + "ms");

        return result;
    }
}

Sử dụng annotation

@Service
public class ReportService {

    @LogExecutionTime
    public void generateReport() {
        // business logic
    }
}
Senior note: Spring AOP thường hoạt động thông qua proxy. Một limitation phổ biến là self-invocation: method trong cùng class gọi method khác cũng trong class đó thì proxy có thể bị bypass.

17. Transaction Management

@Transactional nói với Spring rằng method cần chạy trong database transaction.

@Service
public class OrderService {

    @Transactional
    public void createOrder(CreateOrderRequest request) {
        orderRepository.save(order);
        paymentRepository.save(payment);
    }
}

Điều gì xảy ra?

Method bắt đầu ↓ Spring mở transaction ↓ Business logic chạy ↓ Nếu success → commit Nếu runtime exception → rollback

Quy tắc quan trọng

  • Mặc định rollback cho unchecked exceptions.
  • Checked exceptions không rollback mặc định nếu không config.
  • @Transactional thường hoạt động qua proxy-based AOP.
  • Self-invocation có thể bypass transaction proxy.
  • Nên đặt transaction boundary ở service layer, không phải controller layer.

Rollback cho checked exception

@Transactional(rollbackFor = Exception.class)
public void process() throws Exception {
    // business logic
}

Read-only transaction

@Transactional(readOnly = true)
public List<Order> getOrders() {
    return orderRepository.findAll();
}

19. Production Best Practices

Dùng constructor injection

Dependency rõ ràng, dễ test, hỗ trợ immutable fields.

Giữ service stateless

Singleton beans được share bởi nhiều threads.

Tách layer rõ ràng

Controller, service, repository, DTO, mapper.

Dùng DTOs

Không expose entity trực tiếp ra public APIs.

Centralize exceptions

Dùng @RestControllerAdvice.

Dùng configuration properties

Ưu tiên typed configuration thay vì nhiều @Value rải rác.

Dùng profiles cẩn thận

Tách config dev, staging, production rõ ràng.

Monitor bằng Actuator

Expose health, metrics, readiness/liveness một cách an toàn.

Lỗi phổ biến

  • Đưa business logic vào controller.
  • Dùng field injection khắp nơi.
  • Dùng entity làm API response trực tiếp.
  • Lưu request-specific data trong singleton services.
  • Không hiểu self-invocation của @Transactional.
  • Tạo quá nhiều beans mà responsibility không rõ.
  • Lạm dụng profiles để che design problem.

20. Tóm tắt phỏng vấn

Spring là gì?

Spring là Java framework và IoC container giúp xây dựng enterprise applications. Nó quản lý object creation, dependency injection, lifecycle, transaction, web layer, data access và nhiều infrastructure concerns để developer tập trung vào business logic.

Bean là gì?

Bean là object được Spring IoC container tạo, cấu hình và quản lý. Thay vì tự tạo object bằng new, mình để Spring tạo và wire object đó.

IoC là gì?

IoC là Inversion of Control. Trách nhiệm tạo object và wiring dependency được chuyển từ application code sang Spring container.

DI là gì?

Dependency Injection là cách implement IoC. Một class nhận dependency từ bên ngoài, thường qua constructor injection, thay vì tự tạo dependency bên trong.

Spring Boot auto-configuration là gì?

Auto-configuration là conditional configuration. Spring Boot kiểm tra classpath dependencies, properties và existing beans, sau đó tự tạo default beans khi phù hợp. Developer có thể override bằng cách tự define bean hoặc exclude auto-configuration class cụ thể.

Câu trả lời phỏng vấn ngắn gọn

Spring chủ yếu xoay quanh IoC và Dependency Injection. 
Thay vì tự tạo dependencies thủ công, mình khai báo class cần gì, 
Spring container sẽ tạo beans, inject dependencies và quản lý lifecycle của chúng.

Spring Boot xây dựng trên Spring và giảm configuration thông qua starters và auto-configuration. 
Auto-configuration kiểm tra classpath, properties và existing beans, sau đó tạo các default beans phù hợp. 
Nó không phải magic; nó là conditional configuration và mình có thể override.
